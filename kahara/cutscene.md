# ボス戦前のイベント: 範囲・主人公の動き・話者

> 対象: 電波人間のRPG2 (`kahara`) v1.1.0。分類: ゲーム既存仕様。
> 根拠: 2026-10-31 にユーザーの PC の ROM で code.bin を読んだ解析 (Panana の逆アセンブラ・実行器)。エミュレーター・実機では未確認。
> アドレスは特記なき限り実行時/Ghidra アドレス (code.bin の位置 = アドレス − `0x100000`)。RPG3 には適用しない。

区画 8 の範囲と種類 0x24 のスクリプトで作られている、ボス戦の前の演出 (主人公が歩く・ボスが話す・カメラが切り替わる) の作りです。
仕組みの全体は [events.md](events.md) §8、Panana で同じ部品を使って演出を作る MOD は [イベント拡張 MOD §9](../integrations/panana/event-mods.md)。

確度: **確定** = コードを読んで確認、**推定** = 使われ方からの推測。

## 1. 立ち入り範囲

### 1.1 作られ方 (確定)
`FUN_001c92f8` が区画 8 のレコードごとに次を行う:
- 出現条件 (EventObject +0x4B / +0x4C、`FUN_0030b8a4`) が成り立たなければ範囲を作らない。
- 中心 = (x×100+50, 0, y×100+50)。**y (高さ) は常に 0**。
- 大きさ = +0x0A: 0→200、1→400、2→600、3→800、4→1000、5 以上→0。
- `FUN_002ef4f4` で 0x1C バイトの範囲を作り、マネージャ (`*(*0x56A1DC + 0x18)`) の +0x1A0 の配列に積む (数は +0x1F0)。範囲: +0 中心、+0xC 大きさ、+0x10 行、+0x14 = EventObject +0x48 (u16)、+0x16 = レコード +0x0B、+0x17 = レコード +0x0C の下位バイト、+0x18 = 有効 (1)。
- ハンドラ `FUN_001f4658` (vtable 0x4FC634) を `FUN_0030cab8` で登録。
- レコード **+0x08 / +0x09 はこの経路では読まれない** (+0x08 は常に 9。+0x09 は 1/2/3 があるが、読む場所は見つけられていない。推定: 使われていない)。

### 1.2 判定 `FUN_0028fdec(マネージャ, 位置, モード)` (確定)
- 形: +0x0C = 0 → **球** (中心からの 3D 距離² < (大きさ/2)²。y も含む)。+0x0C ≠ 0 → **正方形** (|dx| ≤ 大きさ/2 かつ |dz| ≤ 大きさ/2、高さは見ない)。境界は、球が「未満」、正方形が「以下」。
- +0x0B (範囲 +0x16) が呼び出しのモードと一致する範囲だけを調べる。向きの条件はない。
- イベントが実行待ち・実行中 (マネージャ +4 ≠ 0、または +8 の 5 枠のどれかが埋まっている) のあいだは、どの範囲も調べない。
- `FUN_00317f68(行, 0)` (= `FUN_00208e8c`) で範囲の「有効」を 0 にできる (マップを読み直すまで)。バニラの一度きりのイベントは、終わりと読み込み時 (0x91 が立っていれば) にこれで自分を消す。
- 入っていれば、ハンドラの vt[3] (`FUN_0023d82c`: 行の状態で +0x4D/+0x4E/+0x4F の動作を選ぶ) を呼び、返った動作をマネージャ +8 の 5 枠に積む。1 を返す。
- 特例: 行 0x35 は、マップのハッシュが 0x706AA9AB のとき `FUN_00270148` / `FUN_002700f4` で追加の判定 (D05 の熱い道)。

### 1.3 モード (+0x0B) と発火のしかた
呼び出し元はどちらもフィールドの主人公の更新 `FUN_003fef98`。
- **+0x0B = 1**: 毎フレーム、**主人公の今の位置**で判定する (確定)。入った瞬間に発火する。まだ全段階を終えていない行 (状態 < 段階数) なら `FUN_0040132c` も呼ぶ (推定: 主人公の移動を止める)。EventObject +0x48 ≠ 0 なら別の経路 (`FUN_002de244` / `FUN_002e8b44` に +0x48 × 10⁹ を渡す。推定: その秒数だけ留まると発火。worldmap.md と同じ。バニラの区画 8 では +0x48 は全部 0)。
- **+0x0B = 0**: `FUN_003ff7ec` の中、区画 3/5 の「調べる」対象が見つからなかったあとで、**主人公の位置 + 向き × 80** の点で判定する (確定)。推定 (強): A ボタンで調べたときに発火する (店のカウンター越しの会話など)。
- 中にいる間に何度も発火するのを防ぐのは、スクリプト側 (0x91 や行の状態を見て何もしない、終わりに `FUN_00317f68` で範囲を消す) の役目。範囲そのものは「出た/入った」の区別をしない。

## 2. バニラのスクリプトの中身 (命令の並び)

共通の形 (確定): 動作のクラスの vtable = `{0, [1] 後始末, [2] 本体 (コルーチン), [3], [4] 完了, 0x43C2CC}`。
- [3] は「主人公のハンドルを入れ、頭上のマークを消す」(D01 36 / D02 20 / D05 22) か何もしない (0x1B0FC8)。推定: 範囲に入って [2] の前に呼ばれる準備 ([2] がそのハンドルを使うため)。呼んでいる場所は未確認。
- [4] = `FUN_0031713c` (状態を進める) + 「0x91[n] が 0 なら 1 にする」(`FUN_0031d710(n, 1)`)。
- 台詞の行は [2] の先頭で 0x91[n] ≠ 0 (D01 37 は == 2) なら何もしない。
