# 電波人間のRPG2 (kahara): 回復の泉・ワープ記録・テレポーター

対象: 日本版 Title ID `00040000000A7900`、TitleVersion 1040 (1.1.0)。アドレスは展開済み code.bin の仮想アドレス (base `0x100000`)。[解析案内](analysis.md) / [ROM の識別・展開](../roms/kahara.md)。

## 回復の泉と確認ダイアログ
- 泉の処理は `FUN_001f0dd8`。
  - オブジェクト +0x254 が使用済みフラグで、立っていれば 0x1BE1「回復の効果が失われている…」を出す。
  - 立っていなければ `FUN_0030873c(0x1BE0)`「回復しますか？」→ はいで全回復 (`FUN_003008dc`) し、+0x254 = 1、0x1BE2 を出す。
- はい/いいえ ダイアログ: `FUN_0030873c` → `FUN_00303f7c(種別)` → `FUN_002e42e4` (クラス vtable 0x4FBE78、種別 +0x364)。
  - ボタンはレイアウトのペインを種別ごとの表 (0x5E5ADC 左 / 0x5E5ABC 右) から選ぶ: Yes/No, Ok, oku。
  - **最大 2 ボタン**なので、3 択はレイアウトから作る必要がある。

Panana の水汲み MOD が追加する `0x1F0E8C` → cave `spring` の処理・所持上限判定は [実装記録](../integrations/panana/analysis.md) を参照。

## ワープホールの記録とテレポーター

### ワープ記録 (セーブ変数、ダンジョン枠 13)
記録枠は `FUN_002f8de0(dungeon)` で決まる。
- D01〜D10 → 0〜9
- K01〜K03 → 10〜12
- それ以外 (K04、S 系など) は -1 で、記録できない。

| 変数 | 型 | 内容 |
|---|---|---|
| 0x5F | 1bit × 13 | 記録あり |
| 0x61 | u32 × 13 | マップ (ハッシュ) |
| 0x62 | 3 × u32 × 13 | 位置 xyz (float) |
| 0x63 | s8 × 13 | 階 (−2 = 地下2階) |

関数 (`save` = `*(0x564638)+0x404`):
- 書き込み: `FUN_00430ec4(save, dungeon, map, &pos, floor)`
- 消去: `FUN_00430f54(save, dungeon)`
- 有無: `FUN_002f2794(save, dungeon)`
- 階: `FUN_0044d584(save, dungeon)`

現在地:
- ダンジョン = var 0x4F (`FUN_0030b788`)
- マップ = var 0x50 (`FUN_00319170`)
- プレイヤー位置 = var 0x5A (xyz)、向き = 0x5B、方向 = 0x52

### ワープホールを通ったとき (`FUN_001c3ecc`、イベント種別 0x13。ギミックの +0x18 オブジェクト、+0x1C 階)
1. 0x1BF9「ダンジョンの外へ出ますか？」を聞く。
2. ダウンした仲間がいれば確認する (`FUN_001defd8`)。
3. D02 と D03 は記録を 1 つ共有する。逆側の記録を消す。
4. ワープホールのオブジェクトの `+0x10 → +0x14` の位置で記録を書く。
5. テレポーターと同じ脱出処理に進む。

### 入口 (`FUN_001dbd34`)
1. 記録があれば 0x21 (地下) / 0x22 で「ワープホールの記録があります…から始めますか？」と聞く。
2. はいなら `FUN_00430f90(..., 1)` を呼ぶ。var 0x50 = 記録のマップ、`save+0x406 |= 4` になる。
3. マップを読み込むとき、このビットが立っていれば var 0x62 → 0x5A にコピーする。つまり記録した座標に出現する。
4. D02 と D03 の入口は、どちらの記録でも使う。

### マップ→ダンジョン表 0x4C3AFC
56 行 × 0x10 = {ダンジョン, 名前, マップ数, マップ配列}。マップ行は 0x1C バイトで、+0 がハッシュ、+4 が階、+0x18 が名前 (例 "D02B02002")。
`FUN_002f1f48(map)` で行が得られる (見つからなければ 0x5204F4 の既定行)。

### テレポーター (アイテム 28、アクション行は使わない)
`FUN_002c65f8` (メニューからのアイテム使用) が ID 0x1C を直接処理する。
1. 使えるかを判定する。フィールドマネージャーがあり、かつダンジョン表の bit1 が立っていること。
   - 使えなければ 0x17DC「しかし何も起きなかった」を出す。消費しない。
2. ダウンした仲間がいれば 0x1BFA で確認する。
3. `FUN_0030b7ac(field, 0x1300000)` で脱出イベント (`FUN_00353480`) を起動する。
4. `FUN_0031140c(inv, r5, -1)` で消費する。

呼び出し元のうち、フィールドのメニュー 0x25DE4C と `FUN_00266938` の 0x266B14 も、ID 0x1C なら使用後にメニューを閉じる。

水汲み・テレポーター+ の追加パッチは [Panana 実装記録](../integrations/panana/analysis.md)。

- セーブ上の配置: 変数はビット単位で詰めて格納される (32bit 境界にそろえない)。v1.1.0 の実セーブでは、var 0x61 の枠 7 (D08) が 0x2FA1 の bit 6 から始まり、0x62 がその直後に続く (マップハッシュをビット単位で検索して確認)。
- D02 と D03 は、バニラと同じく逆側の記録を消す。
