# 電波人間のRPG2 (kahara): メッセージと制御コード

対象: 日本版 Title ID `00040000000A7900`、TitleVersion 1040 (1.1.0)。アドレスは展開済み code.bin の仮想アドレス (base `0x100000`)。[解析案内](analysis.md) / [ROM の識別・展開](../roms/kahara.md)。

## GMSG (.gsmb) メッセージ
ヘッダー・オフセット表は [共通 GMSG 形式](../common/formats.md#gmsg-メッセージ)。以下は kahara 固有の ID・処理・制御コード。

- ヘッダー +0x04 は実際のファイルサイズで、4 の倍数には揃えない。+0x18 のオフセット表は 0x20、+0x1C の文字列ベースは `0x20 + 4 × 件数`。
- ID は全ファイル通しのグローバル番号。+0x14 の ID 間隔は既存データでは常に 1。検索では `(ID − first)` がこの間隔で割り切れない場合に失敗する。
- +0x10 は 0 = 本文、1 = `*_IN` (音声用の読みと推定)。本文と読みは同じ ID でも別の種別として引かれる。

- オフセットは ID 順に狭義単調増加。メッセージの間と末尾にパディングはなく、各メッセージは「種別コード 1 文字 + 本文 + 0x0000 ちょうど 1 つ」。
- 読み込み (`FUN_001e78f0`) は +0x18 / +0x1C を足すだけで、マジック・サイズ・末尾を検証しない。文字列の長さを変えて作り直してよい (既存の MOD で確認)。
- 検索 (`FUN_00310438` / `FUN_0043ccac`) は登録順に「+0x10 が一致し first <= ID <= last」の最初のファイルを使い、種別コードを飛ばした位置を返す。
- 本文の ID 範囲は重ならない: SystemCommon 0–0x17DA、Battle 0x17DB–0x1BDE、Field 0x1BDF–0x21AF、Nagomi (6F896E38) 0x21B0–0x26F2、Antenna (56860091) 0x26F3–0x2944、Command 0x2945–0x2B18、Staffroll (FBADD94C) 0x2B19–0x2B85、CodeFilter (108B9147) 0x2B86–0x2B92。MessageEvent_JP / _IN は空 (last = 0xFFFFFFFF)。
- 56562135 の type 6: 21 SystemCommon (49607C00)、22 SystemCommon_IN (124D7400)、23 Battle (D5D06400)、24 Field (5CEDC400)、25 Field_IN (DDF30800)。
- MessageCommand は 4 つのアーカイブ (1D37838B / 49A43B63 / 91B0619D / BACF5819) に同じ内容で入っている。書き換えるなら 4 つとも揃える。
- *_IN は 1 バイト文字列 (半角カナと ' / などの記号) で、`$page$`、`$message:ID$`、`$hero$` などを含む。メッセージ窓が音声用に引くだけで表示には使わず、ID がなければ音声なしで進む。本文を書き換えたら、_IN の同じ ID を 0 埋めにするのが無難 (panana はそうしている)。

### 本文の制御コード
本文に見える Latin 拡張の文字 (č ď Ď ā Ć Ē …) は字形ではなく、`0x0001` の直後のタグ番号を文字のまま出したもの。ゲームの画面には文字として出ない。

| 並び | 意味 |
|---|---|
| 先頭の 1 文字 (0x00〜0x13) | 種別コード。表示されない (名前 0x0001、説明 0x000C / 0x000D など) |
| 0x0000 | 終端 |
| 0x000A | 改行 |
| 0x0001 X | タグ (2 u16。X = 0x24 / 0x2A だけ引数 2 つで 4 u16、データでは未使用) |
| 0x0002 0x0026 ID 0x0000 | 別のメッセージ (地名など) の差し込み |

タグ X (展開は `FUN_0018ff64`):

| X | 意味 |
|---|---|
| 0x27 ' / 0x28 ( / 0x29 ) | ルビ: `[0001]' 親字 [0001]( よみ [0001])` |
| 0x10 | ページ送り。データでは必ず直後に 0x0A があり、それも一緒に消費する (改行として出ない) |
| 0x02〜0x16 (0x10 以外) | 数値などの書式の差し込み (値は表示関数の引数)。**0x0A は数値で、改行ではない** |
| 0x100 Ā | 数値 (3 桁ごとにカンマ) |
| 0x101 ā / 0x102 Ă | 電波人間の名前 |
| 0x103 ă / 0x104 Ą | モンスターの名前 (Ą は MonsterParameter の行 → MonsterDesign の名前) |
| 0x105 ą | 同じモンスターが複数いるときの A〜Z ((引数 − 1) mod 26) |
| 0x106 Ć | アイテム名 |
| 0x107 ć | ワザの名前 (actionData +0x04) |
| 0x10A / 0x10B / 0x10C | 決まった名前: メッセージ 0x176A「あかり」(ヒロイン) / 0x176B「テル」(子供1) / 0x176C「ルナ」(子供2)。_IN の $heroine$ / $child01$ / $child02$ と同じ ID (code.bin 0x27E150〜0x27E158) |
| 0x110 / 0x111 | 決まった名前: メッセージ 0x1772「ライラ」/ 0x1773「リラ」 |
| 0x10D č / 0x10E Ď / 0x10F ď | **声** (文字送りの効果音 0x44 / 0x43 / 0x42、`FUN_00190660`)。何も表示しない。行頭に置く。データでは Ď = 地底人の片言、ď = です調、č = それ以外の口調 |
| 0x112 Ē | 色つきの ● (U+25CF) 1 文字 (`FUN_00310280`)。前後に色の指定 (0x113〜0x11E のどれか) と色を戻す指定が付く。色は直前の Ć (アイテム名) の展開で、アイテムごとの値 (`FUN_001cd048`) が 0x51A460 に保存されて決まる。「〜のたね」の後ろの花の色 (推定) |
| 0x113〜0x11E / 0x11F | 文字色 (色表 0x20〜0x2B) / 色を戻す (日本語のデータでは未使用) |
| 0x120 Ġ | 表示幅を取るための「の」× 10 (推定) |
| 0x121 | 入力された文字列 (0x5E5D78 + 引数 × 0x100) |
| 0x122 Ģ / 0x123 ģ / 0x124 Ĥ | **感情** (音声の表情を 0x65 / 0x66 / 0x67 に、既定は 100。`FUN_0018fed4`)。表示しない。例: Ģ「あなた！！」(驚き)、Ĥ「ぐすん」(泣き) |

私用領域 (0xE000〜0xF8FF) の文字や、ほかの改行・ページ送りのコードはない。
エディタの表現・プレビューの実装は [Panana 実装記録](../integrations/panana/analysis.md)。

SystemCommon 内の未使用スロット: 0x17D9 (フォントテスト), 0x17DA (隠し「モンスター」), 0x0038, 0x0E1A, 0x1732。

## メッセージ ID の追加
- 検索 `FUN_00310438`: 登録済み GMSG を順に走査し first<=id<=last の最初のファイルを使う (返すのは種別コード 1 文字を飛ばした位置)
- アーカイブ内エントリは type 別ハンドラ (`FUN_003377c4`/`FUN_0033ba90`) で処理され、type 6 が GMSG
- Panana の MOD では、新規 GMSG (ID 0x2C00〜) を 56562135 に type 6 エントリとして追加して利用 (MessageMod_JP.gsmb, hash 0x4D4F4400)
