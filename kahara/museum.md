# モンスターのミュージアム: 項目・倒した記録・「そうぐうしたばしょ」

> 対象: 電波人間のRPG2 (`kahara`) v1.1.0。分類: ゲーム既存仕様。
> 根拠: 本文に記す関数 (code.bin を base `0x100000` で逆アセンブル) と、master (56562135) の monsterParameter.bin / mapGroup.bin / areaInfoData.bin / flagData.bin の実データ (2026-11-09)。
> アドレスは実行時アドレス (code.bin の位置 = アドレス − `0x100000`)。

ミュージアム (モンスター) の項目の作り方と、倒したときに残す記録。モデルの表示は [モーション §2](monster-motion.md#2-ミュージアム)。Panana の対応は [連携メモ](../integrations/panana/kahara-battle.md#図鑑の番号と新しいダンジョンの場所)。

## 1. 要点

- **項目は種族 (MonsterParameter w0 bit0-7) ごと。** 記録は**図鑑の番号 (+0x4A bit4-11)** ごと。どちらも 0xD2 (210) 未満。
- 倒した記録は、倒した行の図鑑の番号に書く。同じ番号の行は、どれを倒しても同じ項目に載る。
- 「そうぐうしたばしょ」は、倒したときに「いる場所」の番号 (0〜0x4D) を残したもの。名前は **areaInfoData の行 +0x00 のメッセージ**。
- ダンジョンの「いる場所」は **mapGroup +0x28**。ダンジョンに入ると入る。

## 2. 項目 (種族 → 行)

- 起動時の `FUN_003fd304` が MonsterParameter を走査し、種族ごとに最初の行をランタイム +0xA48 のバイトの配列 (210 個) に入れる (0x3FD51C)。種族ごとの図鑑の番号の配列も作る。
- `FUN_002be36c(ctx, 種族)`: 種族 < 0xD2 → 行 = +0xA48[種族] (0 なら無し。行 < 0xB9 も確かめる) → 行の +0x4A から図鑑の番号 → セーブ 0x6D / 0x6E の場所 → 場所の名前。呼び出しは 0x34DC98・0x34EE14 (ミュージアムの画面) と 0x44B4A4。
- 一覧 `FUN_002be9bc` は MonsterParameter の行 1〜を走査し、条件 (仮想関数 +8、登録済みかどうかと推定) を満たす行を**種族で重複を除いて** 最大 200 件 (0xC8) 集める。1 件 = {種族, デザイン +0x4C, …}。
- 種族と図鑑の番号はほとんどの行で同じ。種族 115〜126 の行は図鑑の番号が 1 小さい (114〜125)、種族 114 の行は 191。
- 使われていない番号 (v1.1.0): 種族・図鑑の番号のどちらでも使われていないのは 72〜76、127〜169、200〜209 (計 58)。0 は「なし」。

## 3. 倒したときの記録 (`FUN_003fc2cc`)

戦闘の終わり (`FUN_00411160` の 0x411668) から、倒した敵 1 体ごとに `FUN_003fc2cc(セーブ, 行, …)` を呼ぶ。行の図鑑の番号を `n`、いる場所 (ランタイム +0xA47) を `p` とする。

| セーブ変数 | 要素 | 書くもの |
|---|---|---|
| 0x6B | 210 × 1 bit | `[n] = 1` (倒した) |
| 0x6C | 210 × 3 × 10 bit (最大 750) | 手に入れたドロップ (`FUN_00305a54` で 3 つ読む) |
| 0x6D | 210 × 8 bit (最大 150) | 最初の場所。0 なら `p` |
| 0x6E | 210 × 8 bit (最大 150) | 最後の場所。0x6D が 0 でなければ `p` を入れる。そのとき 0x6D も 0x6E も `p` でなく 0x6E が 0 でもなければ、先に 0x6F を立てる |
| 0x6F | 210 × 1 bit | 場所が 3 つ以上ある (「ほか」の表示と推定) |

- 図鑑の数の集計 (`FUN_0034e1d0` 付近、0x34E890) は、種族で重複を除いた一覧の行の 0x6B を数える。
- `FUN_002d4440` 付近は種族 0〜0xD1 の 0x6B を回してハッシュのような値 (+0x3F4) を作る (用途は未確認)。

## 4. いる場所

- 値はランタイム +0xA47 の u8。入れるのは `FUN_002e59bc(ctx, 値)` だけで、**0x4E 以上は 0 にする** (`cmp r1, #0x4E; movhs r1, #0`)。起動時は 0 (`FUN_003fd304`)。
- 呼び出し元:
  - `FUN_00401568` (ダンジョンに入る): 今のダンジョン (`FUN_0030b788`) の mapGroup の行 +0x28。
  - `FUN_001e4924` / `FUN_003ffc40` (ワールドマップ): `FUN_002e5b30` が返す範囲の +0x10 (0 なら変えない)。
- アイテムを手に入れたときも同じ値を使う (`FUN_003fb94c`: 0x70 / 0x71 / 0x72、各 750 個。0x71 / 0x72 は 8 bit で最大 150)。

### 4.1 areaInfoData (master、78 行 × 8 B、ハッシュの索引あり)

| 位置 | 型 | 内容 |
|---|---|---|
| +0x00 | u32 | 場所の名前のメッセージ ID |
| +0x04 | u16 | ワールドマップの範囲 (行 1〜18) と D01〜K04 の行 (41〜54) にある値。`FUN_0021ee50` 付近・`FUN_002d6440` 付近がワールドマップの位置から引いた行で読む (意味は未確認) |

- 行 1〜18 はワールドマップの範囲、19〜77 はダンジョン (mapGroup +0x28 の値)。ダンジョンの名前 (mapGroup +0x14) と同じメッセージのことが多いが、塔の階 (mapGroup 12〜14 → 55〜57) などは別のメッセージ。
- 読む側 (`FUN_002be36c`、`FUN_003fbab0` 付近) は表の行数 (master +0x288 の先頭) と比べてから引く。行を足せば、番号 0x4E 以上もそのまま読める。上限は `FUN_002e59bc` の比較と、セーブの最大 150。
- mapGroup の行 11 (空き、"E00") の +0x28 は 0。

## 5. 新しいモンスター・ダンジョンへの影響

- 行を写して新しいモンスターを作ると、種族と図鑑の番号も写る。そのままでは**元の項目に載り、元を倒したことになる**。空いている番号 (§2) を種族と図鑑の番号の両方に入れれば、別の項目になる。ボスの別の形態のように 1 体として載せたいなら、種族と図鑑の番号をその行と同じにする。
- mapGroup の行を写して新しいダンジョンを作ると +0x28 も写り、**「そうぐうしたばしょ」に元のダンジョンの名前が出る**。areaInfoData に行を足し (+0x00 = 新しいダンジョンの名前のメッセージ)、+0x28 をその行にし、`FUN_002e59bc` の比較 (0x2E59BC) を広げる (セーブの最大から 0x97 まで)。
