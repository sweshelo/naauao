# 出現する敵と BGM

> 対象: 電波人間のRPG2 (`kahara`) v1.1.0。分類: ゲーム既存仕様。
> 根拠: [再編前の解析記録](https://github.com/sweshelo/naauao/blob/27cc7ec6682589c764906ada88e78f5d04d57cc2/encounters.md) と本文に記す関数・実データ。従来の「確定」は元の解析で確認した範囲を指し、今回の再編で ROM 全体を再検証した意味ではない。
> アドレスは特記なき限り実行時/Ghidra アドレス (code.bin の位置 = アドレス − `0x100000`)。RPG3 には適用しない。

マップに出る敵 (エンカウントの群れ) と、マップの BGM・効果音の仕組み。
モンスター 1 体ごとの能力は [battle.md](battle.md) の §2〜§4、一覧は [reference/monsters.md](reference/monsters.md)。

## 1. 流れ

1. マップを読み込むと、`FUN_001ca5a0` が区画 6 を読む (§2)。
   - ヘッダーのハッシュを `FUN_002ef15c(*DAT + 0x54, ハッシュ)` に渡す。これがマップの群れになる。
     - 0 のときは既定の値 (`*(DAT_001ca7e4 + 0x338)`) を渡す。
   - セルごとのハッシュを、セル (0x24 バイト) の +0x10 に書く。0 は −1 にして書く。一覧にないセルは 0 のまま。
2. マップにシンボルの敵を出すとき (`FUN_0021d190`)、セル +0x10 で出せるかを決める (§2)。
   - `FUN_0021dcdc`: プレイヤーの周り (±3 セル) から乱数でセルを選び、+0x10 が 0 でも −1 でもない (= 区画 6 で群れを指定した) セルなら、その群れのシンボルを出す。
   - `FUN_0021dbf4` → `FUN_002d60e8`: マップの群れ (`FUN_002d625c(…, 0)`) のシンボルを出す。置く位置のセルの +0x10 が 0 のときだけ出す。
3. 戦闘の直前に `FUN_00190b6c` (エンカウントの構造体 = `*DAT + 0x54`) が、出る敵の一覧 (+0x38A に u16 × 最大 8、数は +0x3A2) を作る。
   - エンカウントの枠 (0x1C バイト × 32、今の枠は +0x384): +0 先頭の候補の番号、+1 敵の数、+2 monsterFixGroup の行、+4 群れのハッシュ。
   - 群れは `FUN_0030f984(ハッシュ)` で monsterGroup の行を引く (マスター +0x984、ハッシュの索引 `FUN_0031a83c`)。ハッシュが 0 なら `*(DAT_0030fa14 + 0x3D4)` を使う。
   - +1 (敵の数) が 0 のときは、+2 の monsterFixGroup (マスター +0x968) の決まった組み合わせを使う。
4. 戦闘では `FUN_0040f3b4` が一覧の各行を `FUN_00289524` → `FUN_00234cb0` → `FUN_00199c00` で作る ([battle.md](battle.md))。

## 2. 区画 6 (マップの群れとセル)

| 位置 | 型 | 内容 |
|---|---|---|
| +0 | u32 | マップの群れ (monsterGroup のハッシュ、0 = なし) |
| +4 | u32 | −1 |
| +8 + 8n | u32 | セルの群れ (0 = **敵が出ない**) |
| +12 + 8n | s16 × 2 | セルの x, y |

- マップ 139 個に群れがある。セルの群れは、ほかのダンジョンの群れと同じ表 (monsterGroup) のハッシュ。
- セルの一覧は「マップの群れを出さないセル」の一覧 (§1 の 2)。
  - 値 0 のセル (+0x10 = −1): **敵が出ない**。どちらの処理も −1 のセルには出さない。
  - 値が群れのハッシュのセル: その群れのシンボルだけが出る (`FUN_0021dcdc`)。マップの群れはそこに出ない。
  - 一覧にないセル (+0x10 = 0): マップの群れが出る。
- 実データ (編集できるマップ): 値 0 のセル 1227 個 (26 マップ)、群れを指定したセル 72 個 (D05F02001・F04OUT000・K01B02001・K02B02001 の 4 マップ)。
- セルの一覧が空で群れだけがあるマップも多い (D03 など)。そのマップでは、どこにでもマップの群れが出る。

## 3. monsterGroup (56562135 entry 57、144 行 × 0x2E、ハッシュの索引つき)

| 位置 | 型 | 内容 |
|---|---|---|
| +0x00 | {u16 モンスター, u8 重み, u8 数のコード} × 5 | 先頭 (マップで見える敵) と 3 体目の候補 |
| +0x14 | 同じ × 5 | 2 体目と 4 体目の候補 |
| +0x28〜+0x2D | u8 × 6 | 未解析 (+0x28〜+0x2B は敵の数の重み? +0x2D は敵のいない行で 2 / 3) |

- モンスター = MonsterParameter の行。重みは候補の中での比 (`FUN_00190b6c` で重みの合計に乱数を掛けて選ぶ)。
- 数のコード (`FUN_0030f4c0`): 0〜3 = 1〜4 体、4 = 8 体、5 = 1〜2 体、6 = 1〜3 体、7 = 1〜4 体 (5 以上は乱数)。
- 先頭の候補は、エンカウントの枠の +0 で決まる (マップに出したシンボルの敵)。2 体目以降は、候補から重みで選ぶ。
- 同じモンスターが重なったら、数をまとめる。全体で 8 体まで。

## 4. BGM と効果音

- mapData (56562135、91 行 × 7 バイト) の基本行 = mapGroup +0x26 (ダンジョンごと)。屋内は +0x27、さらに designedMap / マップ固有キーの上書きがある ([map.md](map.md) §3「タイルの見た目」)。
  - [0] タイルセット、[1] mapResource の行、[4] **フィールドの BGM**、[5] **戦闘の BGM**、[6] **足音**。いずれも soundData の行。
  - 例: 山のどうくつ (mapData 行 1) = 18 BGM_CAVE / 27 BGM_BATTLE_1 / 77 SE_FLD_STEPS1。
- soundData (418 行 × 0xC): +0 = サウンドアーカイブのアイテム ID (0x01nnnnnn = 音 nnnnnn)、+4 = 0x340、+8 = 音量 (100)。
  - 行 1〜34 が BGM (1 BGM_TITLE … 27 BGM_BATTLE_1 … 34 BGM_ENDING2)。
- 音の名前は RomFS の `sound/sound.bcsar` にある。
  - STRG ブロック (0x2000) の文字列表と、INFO ブロック (0x2001) の音の一覧 (参照 0x2100)。
  - 音の情報の +0x14 のフラグの bit0 があれば、+0x18 が文字列の番号。
  - 音 430 個。0 BGM_TITLE、1 BGM_WORLDMAP …。曲の本体は `sound/stream/BGM_*.bcstm`。
- 町・屋内で mapGroup +0x26 だけでは決まらない場合も、上記の行選択をたどる。音の個別の再生条件は別途確認が必要。

### 4.1 サウンドアーカイブとストリームの並び (実測、2026-10-25)

kahara v1.1.0 の RomFS を読んだ値。他作品は比較のため併記する ([oahu/sound.md](../oahu/sound.md) §1)。

- `sound.bcsar` (CSAR 0x02020000、3,274,432 B): STRG 0x40 (0x7FA0 B)、INFO 0x7FE0 (0xBC00 B)、FILE 0x13BE0。
  - STRG: 文字列表 (484 個、要素 {0x1F01, 表からの位置, 長さ}) の直後に文字列、その後ろ (+0x3400) に名前の検索木。
  - INFO の表は 2100 音 (430) → 2104 → 2101 → 2103 → 2105 → 2102 → 2106 ファイル (60) → 220B の順に並び、各表は「数 + 参照の配列」の直後に要素が続く (参照は表の先頭から)。
  - 音 0〜50 がストリーム (BGM 34 曲・ME)。要素は 68 B: +0x00 ファイル、+0x04 プレイヤー 0x04000000、+0x08 音量、+0x0C 詳細 {0x2201, 0x3C}、+0x14 フラグ 0x80000107、+0x18 名前の文字列番号、+0x3C 詳細 (u16 1 = track、u16 2 = チャンネル数、4 B 0)。
  - ストリームのファイルは外部ファイルの要素 {0x220D, 0x0C} + 4 B 0 + パス (`stream/BGM_TITLE.bcstm`)。
  - soundData から指されない音が 20 個ある (43 `ME_BANNER` のほかは効果音のシーケンス)。soundData の重複は 121 / 122 (`SE_IVT_DIG`) と 375〜380。
- ストリーム (`sound/stream/*.bcstm`) は CSTM 0x02010000。INFO の参照 +0x08 が track の表 (+0x50、1 本) で、channel の表 (+0x5C) の直後に track が続く。32728 Hz、ステレオ、DSP-ADPCM。

| 作品 | CSAR | CSTM | track |
|---|---|---|---|
| 初代 | 0x02000000 | 0x02000000 | あり (kahara と同じ並び) |
| RPG2 | 0x02020000 | 0x02010000 | あり |
| RPG3 / FREE! | 0x02030000 | 0x02020000 | 参照が null。stream info の後ろに 12 B (u16 0x100 と null の参照) |

- マップ・戦闘・ボス戦の BGM は soundData の行を 1 バイトで持ち、行 1〜255 はすべてゲームの音 (1〜34 BGM、35〜50 ME、51〜 効果音)。行を足しても (418〜) これらの欄からは指せない。他作品の BGM を足すときの扱いは [Panana の連携資料](../integrations/panana/bgm-port.md) を参照。

## 5. 決まった敵との戦闘 (monsterFixGroup、確定)

- **`FUN_002fc790(行, BGM)`** が決まった敵との戦闘を始める (ボス戦。呼び出しは 31 か所。`events.md` §8)。
  - 行 < 表の行数なら、その行の +0 のフラグで戦闘の設定 (グローバル +0x3F8〜+0x3FA) をする: bit0 → +0x3F9 = 1、+0x3F8 = 0、+0x3FA = 1。bit1 がなければ +0x3FA = 1。
  - `FUN_00190ae8(エンカウント, 行)` が空いたエンカウントの枠に {+0 = 0, +1 = 0 (敵の数), +2 = 行} を書く (§1 の 3)。
  - BGM (soundData の行) を `FUN_0030378c` で鳴らし、`FUN_003014f0(5, 0)` で戦闘の場面に移る。
- monsterFixGroup (56562135、65 行 × 0x18、索引なし):

| 位置 | 型 | 内容 |
|---|---|---|
| +0x00 | u32 | フラグ。ボスは 0x341、ほかに 0x342 / 0x340。bit0 / bit1 は上のとおり、ほかは未解析 |
| +0x04 + 4k | u16 | モンスター (MonsterParameter の行、k = 0〜4)。0 で終わり |
| +0x06 + 4k | u8 | 数のコード (§3 と同じ。0 = 1 体) |
| +0x07 + 4k | u8 | 0xD0 (使われない) |

- 行 0 は使われない (`FUN_00190b6c` は行 0 を「なし」とみなす)。戦闘の枠は行を 1 バイトで持つので、255 行まで。
- 例: 行 9 = ポーン (77)、行 27 = しんじつのポーン (88)、行 19 = 0x9E / 0xA1 / 0x9E の 3 体。
