# ワールドマップのデータ構造

> 対象: 電波人間のRPG2 (`kahara`) v1.1.0。分類: ゲーム既存仕様。
> 根拠: [再編前の解析記録](https://github.com/sweshelo/naauao/blob/27cc7ec6682589c764906ada88e78f5d04d57cc2/worldmap.md) と本文に記す関数・実データ。従来の「確定」は元の解析で確認した範囲を指し、今回の再編で ROM 全体を再検証した意味ではない。
> アドレスは特記なき限り実行時/Ghidra アドレス (code.bin の位置 = アドレス − `0x100000`)。RPG3 には適用しない。

電波人間のRPG2 v1.1.0 を解析した結果です。アドレスは Ghidra 上のもの。ダンジョンのマップ ([map.md](map.md)) とは別の仕組みで読み込まれる。ワールドマップ固有の構造を記録する。

確度の表記は [map.md](map.md) と同じ (**確定** / **推定**)。

## 1. ワールドマップの一覧 (確定)

`FUN_002d9ac4` がマップ ID をワールドマップの番号 0〜3 に変える (それ以外は ワールドマップではない)。

| 番号 | マップ ID | mapGroup | マップ DB の区画 0 のサイズ |
|---|---|---|---|
| 0 | A8654391 | 0x34 (52) W01 | 183,096 B |
| 1 | 09A1DA1B | 0x35 (53) W02 | 4,476 B |
| 2 | E1E102F7 | 推定: 0x36 (54) W98 | 6,180 B |
| 3 | A7835BBD | 推定: 0x37 (55) W99 | 0 B |

- DebugMapJump の行 13 = A8654391 (mapGroup 0x34)、行 184 = 09A1DA1B (0x35)。
- 4 枚とも code.bin 0x4C1A74 ([map.md](map.md) §2) と 0x4C3AFC のマップ表には載っていない。そのため W01〜W99 のマップ数は 0 ([reference/dungeons.md](reference/dungeons.md))。
- [monster-motion.md](monster-motion.md) の拡大率の分岐 (+0x2C) も、今のマップが A8654391 / 09A1DA1B のとき。

## 2. 区画表 (確定)

- code.bin **0x4C3A7C** に 4 行 × 32 バイト (u32 × 8、区画 0〜7)。各区画はマップ DB (A90C8038/A2C14C00) のハッシュ。
- 取り出し: 区画 0 = `FUN_0020e580`、1 = `FUN_0020e4a8`、2 = `FUN_002f67e8`、3 = `FUN_0020e7b4`、4 = `FUN_0020e714`、5 = `FUN_0020e61c`、6 = `FUN_0020e920`、7 = `FUN_0020e880`。
- シーンの初期化 `FUN_001e1fc4` → `FUN_002e6624` (地形)、`FUN_001e2ac4` (入口)、`FUN_001e2598` / `FUN_001e2400` (エンカウント)、`FUN_001e2840` (イベント)、`FUN_001e3168` (置物)、`FUN_00234360` (環境)。

## 3. 座標 (確定)

- 1 セル = **100** 単位 (ダンジョンは 500)。ワールド = 50 + 値 × 100。
- グリッドは 300 × 300。`FUN_002e609c` が 300 で折り返すので、上下左右がつながっている。

## 4. 地形 (確定)

- **W01 / W02 はマップ DB の区画 0 を使わない**。`FUN_002e6624` → `FUN_002cf2dc` が、マスター 56562135 の **W01_ground.bin (エントリ 280、2BC1D000) / W02_ground.bin (281、52D98000)** を読む。
  - W98 / W99 だけが DB の区画 0 を `FUN_0023463c` で読む。
  - DB の区画 0 と ground.bin は 15,258 セル中 6,548 セルしか一致しない。推定: DB 側は古い元データ。
- ground.bin (W01 は 180,664 B):
  ```
  u32 1, u32 0x10, u32 0x2BF30, u32 0x2C074        ヘッダー
  +0x10     300 × 300 × { u8 worldmapParts の行, u8 向き (下位 2bit) }   y × 300 + x の順。0 = 空 (海)
  +0x2BF30  u32 × 81   23 × 15 セルの表示窓に入る部品ごとの最大数 (インスタンスのプール長、FUN_00204160)
  +0x2C074  u32 × 81   モード +0x15E8 = 1 用。意味は未解明
  ```
  - +0x2BF30 の表は全 81 種で再計算と一致した。地形を変えたら作り直す必要がある (足りないとプールがあふれる)。
  - 再計算の決まり (2026-10 に W01・W02 とも 81 個すべてで再確認): 部品の**起点のセル**を、**横 23 × 縦 15** の窓をずらして数えた最大数 (端の折り返しの有無で結果は変わらない)。縦横を入れ替えると W01 で 31 個違う。
  - +0x2C074 はこの数え方とは W01 で 45 個、W02 で 10 個違う。Panana は地形を変えたとき、+0x2BF30 が増えた分だけ +0x2C074 も増やす (無編集なら元のまま)。
- DB の区画 0 の形式は [map.md](map.md) §3 と同じ 12 B `{u32 種類, s16 x, s16 y, u8 向き}`。ただし種類は mapParts ではなく worldmapParts の行。

### worldmapParts (確定)

- マスター 56562135 の #52、81 行 × 12 B: `{u32 モデル (アーカイブ D98F0E82 の bcres), u8 フラグ (+4), u8 (+5), u8 mapObject の行 (+8), u8 (+9)}`。
- フラグ: 0x10 = 2 × 2 マスを占める、0x20 = 2 マスを占める (向きで方向が決まる)、0x08 → セルの bit7、0x04 = 入口から出たときの出現位置に使える、bit0-1 = 地形の種類 (エンカウントの判定)。
- 読み込み後、`FUN_002344a4` が 2 × 2 の同じ種類を大きいタイル (2 / 0x13 / 0x1B / 0xC / 0x26 / 0x27) にまとめる。
- モデル (`wld_flat_00` など) はテクスチャを持たず、同じアーカイブのエントリ **`CC4E7000`** (テクスチャだけの bcres、`bg_sea`・`mnmp_*` の 93 枚。RPG3 の `tex_worldmap.bch` に当たる) を名前で使う。町・塔などの建物のモデル (`wld_house07` など、mapObject の行) は自分のテクスチャを持つ。
- 1 セル = 100 単位で、部品のモデルは 1 セル (2 × 2 の部品はブロック) の中心が原点。RPG3 も同じ ([oahu/worldmap.md](../oahu/worldmap.md))。

## 5. 区画 1: 環境のゾーン

- 形式 (確定): 2 bit × 300 × 300 (22,500 B)。`FUN_002e64d0` で引く。
- 推定: 雪・色調などの環境。北と南の極地に値 3 が集まっている。`FUN_002e609c` で 0〜100 にフェードする。

## 6. 区画 2: 町・ダンジョンの入口 (確定)

36 B × 54 件 (W01)。`FUN_001e2ac4`。

| 位置 | 内容 |
|---|---|
| +0x00 | worldmapParts の行 (74〜79 = モデルなしの入口の種類) |
| +0x04 | この入口の ID (ハッシュ) |
| +0x08 | 行き先のマップ |
| +0x0C | 行き先の地点 ID |
| +0x10 | W01_EventObject の行 (出現条件、0 = 常に出る) |
| +0x14 | 区画 3 の地点 ID |
| +0x18 | 表示モデル (mapObject の行 0xEE〜0x106)。0 なら worldmapParts +8 |
| +0x1C / +0x1E | s16 x / y (セル) |
| +0x20 | u8 向き 0〜3 |

- 戻る位置: セーブ変数 0x51 (`FUN_002ff4b4`) がこの入口の ID なら、入口の隣に出る (フラグ 0x04 のタイルを探す)。
- 表示距離: マスター +0x690 の **MapAppearWorldmap** (8 行 `{u32, u16 mapObject の行, u16 距離}`)。
- ダンジョンの区画 3 の出口 → (A8654391, 入口の ID) と、入口 → (マップ, 地点) が互いを指す。W01 へ出る出口 64 件のうち 46 件で両方向が一致する。

### 6.1 入口の出現条件 (確定、2026-10 に ROM で確認)

- `FUN_001e2ac4` は +0x10 が 0 でなければ、W01_EventObject の行 (+0x10) の **+0x4C / +0x04 (成り立つと消える) と +0x4B / +0x00 (成り立つと出る)** を `FUN_0030b8a4` で調べ、通らなければその入口を置かない。判定はダンジョンの区画と同じ ([event-list.md](event-list.md) §4)。「今のダンジョン」を読む種類 (0x37 など) は W01 では mapGroup 0x34 を読む。
- 置いた入口は `FUN_001c0390(行, 入口)` でハンドラ (vtable 0x4FB870) を作り、`FUN_0030cab8` に登録する。[2] `FUN_0023d72c` は登録の直前に 1 回だけ呼ばれ、行の動作を作る。[4] `FUN_001c0270` はダンジョン 0x34 のとき `FUN_0017ef94` を呼ぶ。
- 入口に触れると行の動作がキューに積まれる。**動作がない行では入れない**。行の種類 (+0x4D) ごとの違い:

| 種類 | 入口の動き |
|---|---|
| 0x11 | ふつうの入口 (`FUN_00319184` / `FUN_002daac0`)。条件つきの入口を新しく作るときはこれ |
| 0x24 | 行番号で決まるスクリプト。W01 は行 0x12〜0x1C だけを扱う。それ以外の行では入れない |
| 0x21 | 触れるとメッセージ (+0x08) が出るだけ |
| 0x00 | 入れない |

- W01 で +0x10 を持つ入口 (v1.1.0):

| 入口 | 行 | 条件 | 中身 |
|---|---|---|---|
| 12 | 18 | なし | 0x4FE104 (ふつうの入口) |
| 19 | 27 | なし | 0x4FE128: セーブ 0x92 のフラグ (`FUN_0031c3d8(0x34, 2)`) が立つと行き先を B7947C06 / 998E8C1E に差し替える |
| 49 / 50 / 43 / 41 / 48 | 23 / 28 / 24 / 25 / 26 | +0x4B = 0xAE〜0xB2、値 1 (0x91[1] = 0〜4) | 行き先はどれも 0F4E6026。0x91[1] の値で 5 か所のどれか 1 つだけが出る (動く島) |

- 動く島の入口は、同じ場所にある**区画 6 の範囲の行 (トリガー)** と組になっている: トリガー 19→入口の行 23、20→24、21→25、22→26、14→28。
  - 入口の行は読み込み時 (`FUN_0017ef94`) にトリガーの行の状態 `FUN_0031bff4(0x34, 行)` を見る。0 なら入口を見えなくし、当たり判定を消して 1000 ずらす。入る処理の [2] (`FUN_0022cf08` など) も、トリガーの状態が 0 でないときだけ `FUN_002daac0` を呼ぶ。
  - トリガーの範囲: 判定は `FUN_0028fdec` (毎フレーム、呼び出し元 `FUN_003fef98`)。発動するのはレコード +0xB = 1 の範囲。大きさは +0xA の 0〜4 → 200 / 400 / 600 / 800 / 1000 の半分、+0xC = 0 なら球、それ以外は正方形。W01 のトリガーは半径 200 (2 マス)。推定: 行 +0x48 (W01 は 5) が 0 でなければ、その秒数だけ範囲に留まると発動する。
  - トリガーの動作 [2] (`FUN_00262ccc` など) は「自分の状態が 0 なら `FUN_002c4d98(入口の行, 座標)`」だけ。状態は [4] `FUN_0031713c` が 0→1 にする。
  - `FUN_002c4d98` の演出: `FUN_00310798(0x1FBC)`「うわっ、何か来ますよう！」→ カメラとエフェクト → 入口を座標に出して当たり判定を有効に → `FUN_00310798(0x1FBD)`「これが[地名]！」→ カメラを戻す。

- 黄泉の門 (入口 19、(115, 146)、モデル 0x106、行 27): 区画 2 の入れ替えではない。行 27 の動作 0x4FE128 は、0x92 のフラグ (`FUN_0031c3d8(0x34, 2)`) が立つまで生成時に vt[3](0) を呼んで +0xC の bit7 を消し (推定: 隠して入れない)、立つと行き先を「黄泉の門 屋外 (0)」3574000A から「(1)」B7947C06 に差し替える。フラグは `FUN_001c0630` の中で `FUN_003192f0(2, 1)` (= `FUN_003047f8(今のダンジョン, 2, 1)`) が立てる。モデルは変わらない。近くに釣り場の入口はない (釣り場は入口 3 / 17 / 38)。
- 入口の配列 (fp+0x11B4、数は +0x2C0) は**最大 176 件で範囲の検査がない** (超えると後ろの欄を壊す)。W01 は 54 件。fp+0x14BC の配列 (最大 32) は行き先が特定の 4 つのハッシュのときだけ。ほかにイベントのハンドラは最大 100、範囲は最大 20。
- 表示距離 (MapAppearWorldmap、8 行: ED 150、F5 150、102 130、F0 140、106 140、F3 140、FD 100、FF 100): 載っていない mapObject の行の入口も置かれる。距離の既定は 100 (mapObject の半径 × 0.5 > 40 なら max(100, 半径 + 60))。値は `FUN_002ee784` に渡る (表示距離か接近の判定かは未確認)。
- 入口 +0x18 のモデル (W01): 0 (worldmapParts +8) 11 件、F6 8、F5 6、103 5 (水の神殿の候補地)、F8・F9・FE 各 3、FA・FB・100・FF 各 2、106・FD・FC・102・F4・EE・104 各 1。
- 表示中の入口のオブジェクトの位置は「セルの中心 + (0, −100, 0)」。`FUN_0031c970(行)` で入口のオブジェクト (+0x5E = 入口 +0x10 の行) が取れる。

### 6.2 マップに入ったときの動作 (確定)

- フィールドのシーンのコンストラクタ `FUN_00402358` (シーンのファクトリ `FUN_00174cb8(3)` → `FUN_0017f534` → `FUN_0019ae74` から) が `FUN_00198450` を呼び、疑似行 **0x1000000** (マップに入ったときの動作) を条件なしでキューに積む (`FUN_0030b7ac`)。マップを移るたび・セーブを読み込んだあとに動く。推定: 戦闘から戻るときもシーンを作り直すなら、そのたびに動く。
- `FUN_0030b840` が `FUN_0019aa88(ハンドラ, シーンのモード)` を呼び、戻り値の動作をハンドラ +0xC に置く。0 なら何も積まれない。
- `FUN_0019aa88` はダンジョンごとに分かれる。W01 は 0x19AB9C `pop {r4, lr}`、0x19ABA0 `b 0x17e08c` で `FUN_0017e08c` を末尾呼び出しする (r0 = ハンドラ、r1 = 4)。`FUN_0017e08c` は進行に合わせた演出の動作か 0 を返す。
  - 0x4FB8A8 ([2] `FUN_001c0488`): メッセージ 0x1DF1「デンパ島」。
  - 0x4FB8C8 ([2] `FUN_001c0630`): 黄泉の門が出る演出。下の「黄泉の門が出るとき」。
  - どちらも確保 0x10、`FUN_0031b170(obj, 0x1000000)`、vtable `{0, 0x1C0884 (後始末), [2], 0x1B0FC8, 0x31713C, 0x43C2CC, 0, 0}`。[4] `FUN_0031713c` は疑似行 (≥ 0xFFFFFF) の状態を書かない。
- `FUN_0030cc48` は地の文の窓 (`FUN_00311384(1)`)、`FUN_00310798` は会話の窓 (`FUN_00311384(0)`) と推定。どちらも閉じるまで待つので続けて呼べる。
- カメラ: スタックに 0xF0 B の構造体を作る (グローバルではない)。`FUN_0031b1b4(cam, 0, 1)` → `FUN_003179b8(cam)` → `FUN_00301f80(cam)` (今の視点・注視点を覚える) → `FUN_00317210(cam, &視点, &注視点, 3)` (s0 = 秒) → `FUN_00301d9c(cam)` で待つ → `FUN_00301a44(cam, 3, 0)` (s0 = 秒) で戻す → `FUN_00301d9c` → `FUN_00301888` → `FUN_00301764`。ベクトルの和は `FUN_00338450(a, b, out)`。[event-mods](../integrations/panana/event-mods.md) §7 の門の演出と同じ。推定 (強): カメラ関数はシーンのモード 4 で分岐し、W01 もモード 4 なので、ワールドマップでも同じ呼び方で動く。通常のカメラの距離 (`FUN_00301e08` の s0 = 1300) も近い。
- バニラの演出はカメラを遠くへ向けない (向けるとその場所の地形が読み込まれない)。離れた場所は、フェードの間にプレイヤーをそこへ移すかワープして見せる。
- 黄泉の門が出るとき (確定、2026-10-31):
  - 妖精の里の動作 `FUN_00226064` (vtable 0x4FDD04): 門のアニメ 0x62 → `FUN_003192f0(2, 1)` (妖精の里のフラグ) → 効果音 0xC4 → 白のフェードアウト 0.5 秒 → `FUN_00308d44(*0x564638 + 0x404, W01 = A8654391, D3E36EF0)` (D3E36EF0 = 区画 2 の 19 番、黄泉の門の入口) → `FUN_003014f0(4, 0)` → `FUN_00308bac(0, 0, *0x4D07CC)` でシーンを切り替える。W01 は入口の隣から普通に読み込まれる。
  - 読み込みのあと `FUN_0017e08c` → 0x4FB8C8 → `FUN_001c0630`: 白で即フェードアウト (`FUN_003174e8(0xFF, 0xFF, 0xFF, 2)`、`FUN_003174c8(2, 0)`) → パーティを隠す (`FUN_0031c580` / `FUN_0031c4bc` / `FUN_00301500` を 0 で) → `FUN_0030150c` (推定: カメラをプレイヤーに合わせる) → フェードイン 0.5 秒・フェードアウト 1.5 秒 → `FUN_003192f0(2, 1)` (W01 のフラグ。入口 19 の行き先が変わる) → `FUN_0031c970(0x1B)` の門を表示 → フェードイン 1.5 秒 → 1 秒待つ → `FUN_00300854` → 効果音 0x2F → `FUN_0030cc48(0x1BF6, 0, 0, 0)` (s0 = 0.2) → `FUN_003007c0` → `FUN_00308d44` で妖精の里の 2 階へワープ (元の位置へは戻らない)。
  - `FUN_00308d44` はセーブ 0x4F〜0x52 を書く。ワールドマップの地点は入口の ID で、その入口の隣に出る。
- フェード (確定): `FUN_003174e8(r, g, b, 2)` 色、`FUN_003174c8(2, s0)` フェードアウトを始める、`FUN_00300dbc(s0)` フェードアウトして待つ、`FUN_0031745c(2, s0)` フェードインを始める、`FUN_00302464(s0)` フェードインして待つ、`FUN_0031747c()` 今のフェードを待つ、`FUN_003073e8()` フェード中なら 1、`FUN_003086e4(s0)` s0 秒待つ。待ちはどれもコルーチンの中で譲るループ。
- 動く島の演出 `FUN_002c4d98` (確定): 白でフェードアウト 1.0 秒 → 動かす物 = `FUN_002e592c()` (乗り物、乗っていなければ 0) か `FUN_00319a6c()` (パーティの先頭) → 入口のオブジェクト (`FUN_0031c970` → `FUN_0031c958` → `FUN_0031c948`) の位置 + (0, −1100, 300) (−1100 は隠れた入口の +1000 の打ち消し、+300 = 3 マス南) に `FUN_0031b408(p, &vec3)` → `FUN_00331ca8(p, &{0, π, 0})` で北を向かせる → `FUN_002fc19c(cam, s0 = 0)` → `FUN_00301888(cam)` → 1 秒待つ → フェードイン 1.0 秒。元の位置へは戻さない。
  - p +0x10 は変換ノード T。位置 T+0x14 (float 3)、向き T+0x2C (オイラー角、ラジアン)。T+0x10 の bit3 が立つと向きは T+0x38 からの四元数。
  - `FUN_0031c948(handle)` は位置 (float 3) へのポインタを返す。1 マス = 100、x = 50 + セル x × 100、z = 50 + セル y × 100、南は +z。
- 推定: `FUN_003024f8(0/1)` が *(0x56A1D8)+4 の +0x2E (操作の可否) を書く。キューの動作の中では元から止まっている可能性が高い。

### 6.3 状態の枠 (確定)

- `FUN_003048f8(ダンジョン, 行, 値)` / `FUN_0031bff4(ダンジョン, 行)` は、行が mapGroup +0x1C より小さいときだけ効く。W01 は +0x1C = 39、行は 29 なので、**新しい行に使えるのは 29〜38 の 10 行**。
- メッセージの `&` (0x0002 0x0026 ID 0x0000) の ID は本文に固定。地名を引数で渡す仕組みは見つかっていない (推定)。地名は mapGroup +0x14 (u16) のメッセージ ID (例: mapGroup 6 = 0x9F 水の神殿、W01 は 0)。

## 7. そのほかの区画 (確定)

- **区画 3** (8 B × 35): `{u32 ID, s16 x, s16 y}`。`FUN_00234234` が入口 +0x14 の地点へプレイヤーを移す (セーブ +0x406 bit0 またはフラグ 0x34,3 のとき)。推定: 町の前への移動先。
- **区画 4 / 5** (12 B): `{u32 ハッシュ, s16 x, s16 y, u8 幅, u8 高さ}`。どちらも 3 セル単位で、100 × 100 × 2 層のエリアグリッド (+0xA8D4) に areaInfoData の行を書く (`FUN_002d5a84`)。**エンカウントの範囲**。4 = 陸、5 = 海 (船)。ハッシュは areaInfoData と monsterGroup の両方の索引にある。推定 (強): +0x4E2D が船に乗っているフラグ。
- **区画 6** (16 B × 23): [map.md](map.md) の区画 8 と同じ形 (EventObject の行 + 座標、`FUN_002ef4f4`)。
- **区画 7** (12 B × 7): `{u32 mapObject の行 (0xF2), s16 x, s16 y}`。区画 2 (置物) の簡略版。

## 8. 編集するには

- 入口 (位置・向き・行き先・見た目・出現条件)、エンカウントの範囲、イベント・置物、地形のタイルが編集の対象になる。
- 条件つきの入口を足すときは、W01_EventObject に種類 0x11 の行を足し (行 29〜38)、+0x4B / +0x4C に条件を書いて、入口 +0x10 にその行を入れる (§6.1)。
- 出たことを知らせる「〇〇が出現した！」は Panana のパッチ ([world-notice.md](../integrations/panana/world-notice.md))。
- W01 / W02 の地形は 56562135 の W0x_ground.bin を書き換える (DB の区画 0 ではない)。+0x2BF30 の表を作り直す。+0x2C074 は意味が分からないので、減らさずに +0x2BF30 と同じだけ増やしておくのが安全 (§4)。
- 入口を変えたら、行き先のマップの区画 3 (戻り先の入口 ID) も揃える。
- W98 / W99 は DB の区画 0 をそのまま使うので、ダンジョンの形式に近い。
