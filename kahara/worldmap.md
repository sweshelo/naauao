# ワールドマップのデータ構造

> 対象: 電波人間のRPG2 (`kahara`) v1.1.0。分類: ゲーム既存仕様。
> 根拠: [再編前の解析記録](https://github.com/sweshelo/naauao/blob/27cc7ec6682589c764906ada88e78f5d04d57cc2/worldmap.md) と本文に記す関数・実データ。従来の「確定」は元の解析で確認した範囲を指し、今回の再編で ROM 全体を再検証した意味ではない。
> アドレスは特記なき限り実行時/Ghidra アドレス (code.bin の位置 = アドレス − `0x100000`)。RPG3 には適用しない。

電波人間のRPG2 v1.1.0 を解析した結果です。アドレスは Ghidra 上のもの。ダンジョンのマップ ([map.md](map.md)) とは別の仕組みで読み込まれる。ワールドマップ固有の構造を記録する。

確度の表記は [map.md](map.md) と同じ (**確定** / **推定**)。

## 1. ワールドマップの一覧 (確定)

`FUN_002d9ac4` がマップ ID をワールドマップの番号 0〜3 に変える (それ以外は ワールドマップではない)。

| 番号 | マップ ID | mapGroup | マップ DB の区画 0 のサイズ |
|---|---|---|---|
| 0 | A8654391 | 0x34 (52) W01 | 183,096 B |
| 1 | 09A1DA1B | 0x35 (53) W02 | 4,476 B |
| 2 | E1E102F7 | 推定: 0x36 (54) W98 | 6,180 B |
| 3 | A7835BBD | 推定: 0x37 (55) W99 | 0 B |

- DebugMapJump の行 13 = A8654391 (mapGroup 0x34)、行 184 = 09A1DA1B (0x35)。
- 4 枚とも code.bin 0x4C1A74 ([map.md](map.md) §2) と 0x4C3AFC のマップ表には載っていない。そのため W01〜W99 のマップ数は 0 ([reference/dungeons.md](reference/dungeons.md))。
- [monster-motion.md](monster-motion.md) の拡大率の分岐 (+0x2C) も、今のマップが A8654391 / 09A1DA1B のとき。

## 2. 区画表 (確定)

- code.bin **0x4C3A7C** に 4 行 × 32 バイト (u32 × 8、区画 0〜7)。各区画はマップ DB (A90C8038/A2C14C00) のハッシュ。
- 取り出し: 区画 0 = `FUN_0020e580`、1 = `FUN_0020e4a8`、2 = `FUN_002f67e8`、3 = `FUN_0020e7b4`、4 = `FUN_0020e714`、5 = `FUN_0020e61c`、6 = `FUN_0020e920`、7 = `FUN_0020e880`。
- シーンの初期化 `FUN_001e1fc4` → `FUN_002e6624` (地形)、`FUN_001e2ac4` (入口)、`FUN_001e2598` / `FUN_001e2400` (エンカウント)、`FUN_001e2840` (イベント)、`FUN_001e3168` (置物)、`FUN_00234360` (環境)。

## 3. 座標 (確定)

- 1 セル = **100** 単位 (ダンジョンは 500)。ワールド = 50 + 値 × 100。
- グリッドは 300 × 300。`FUN_002e609c` が 300 で折り返すので、上下左右がつながっている。

## 4. 地形 (確定)

- **W01 / W02 はマップ DB の区画 0 を使わない**。`FUN_002e6624` → `FUN_002cf2dc` が、マスター 56562135 の **W01_ground.bin (エントリ 280、2BC1D000) / W02_ground.bin (281、52D98000)** を読む。
  - W98 / W99 だけが DB の区画 0 を `FUN_0023463c` で読む。
  - DB の区画 0 と ground.bin は 15,258 セル中 6,548 セルしか一致しない。推定: DB 側は古い元データ。
- ground.bin (W01 は 180,664 B):
  ```
  u32 1, u32 0x10, u32 0x2BF30, u32 0x2C074        ヘッダー
  +0x10     300 × 300 × { u8 worldmapParts の行, u8 向き (下位 2bit) }   y × 300 + x の順。0 = 空 (海)
  +0x2BF30  u32 × 81   23 × 15 セルの表示窓に入る部品ごとの最大数 (インスタンスのプール長、FUN_00204160)
  +0x2C074  u32 × 81   モード +0x15E8 = 1 用。意味は未解明
  ```
  - +0x2BF30 の表は全 81 種で再計算と一致した。地形を変えたら作り直す必要がある (足りないとプールがあふれる)。
- DB の区画 0 の形式は [map.md](map.md) §3 と同じ 12 B `{u32 種類, s16 x, s16 y, u8 向き}`。ただし種類は mapParts ではなく worldmapParts の行。

### worldmapParts (確定)

- マスター 56562135 の #52、81 行 × 12 B: `{u32 モデル (アーカイブ D98F0E82 の bcres), u8 フラグ (+4), u8 (+5), u8 mapObject の行 (+8), u8 (+9)}`。
- フラグ: 0x10 = 2 × 2 マスを占める、0x20 = 2 マスを占める (向きで方向が決まる)、0x08 → セルの bit7、0x04 = 入口から出たときの出現位置に使える、bit0-1 = 地形の種類 (エンカウントの判定)。
- 読み込み後、`FUN_002344a4` が 2 × 2 の同じ種類を大きいタイル (2 / 0x13 / 0x1B / 0xC / 0x26 / 0x27) にまとめる。

## 5. 区画 1: 環境のゾーン

- 形式 (確定): 2 bit × 300 × 300 (22,500 B)。`FUN_002e64d0` で引く。
- 推定: 雪・色調などの環境。北と南の極地に値 3 が集まっている。`FUN_002e609c` で 0〜100 にフェードする。

## 6. 区画 2: 町・ダンジョンの入口 (確定)

36 B × 54 件 (W01)。`FUN_001e2ac4`。

| 位置 | 内容 |
|---|---|
| +0x00 | worldmapParts の行 (74〜79 = モデルなしの入口の種類) |
| +0x04 | この入口の ID (ハッシュ) |
| +0x08 | 行き先のマップ |
| +0x0C | 行き先の地点 ID |
| +0x10 | W01_EventObject の行 (出現条件、0 = 常に出る) |
| +0x14 | 区画 3 の地点 ID |
| +0x18 | 表示モデル (mapObject の行 0xEE〜0x106)。0 なら worldmapParts +8 |
| +0x1C / +0x1E | s16 x / y (セル) |
| +0x20 | u8 向き 0〜3 |

- 戻る位置: セーブ変数 0x51 (`FUN_002ff4b4`) がこの入口の ID なら、入口の隣に出る (フラグ 0x04 のタイルを探す)。
- 表示距離: マスター +0x690 の **MapAppearWorldmap** (8 行 `{u32, u16 mapObject の行, u16 距離}`)。
- ダンジョンの区画 3 の出口 → (A8654391, 入口の ID) と、入口 → (マップ, 地点) が互いを指す。W01 へ出る出口 64 件のうち 46 件で両方向が一致する。

## 7. そのほかの区画 (確定)

- **区画 3** (8 B × 35): `{u32 ID, s16 x, s16 y}`。`FUN_00234234` が入口 +0x14 の地点へプレイヤーを移す (セーブ +0x406 bit0 またはフラグ 0x34,3 のとき)。推定: 町の前への移動先。
- **区画 4 / 5** (12 B): `{u32 ハッシュ, s16 x, s16 y, u8 幅, u8 高さ}`。どちらも 3 セル単位で、100 × 100 × 2 層のエリアグリッド (+0xA8D4) に areaInfoData の行を書く (`FUN_002d5a84`)。**エンカウントの範囲**。4 = 陸、5 = 海 (船)。ハッシュは areaInfoData と monsterGroup の両方の索引にある。推定 (強): +0x4E2D が船に乗っているフラグ。
- **区画 6** (16 B × 23): [map.md](map.md) の区画 8 と同じ形 (EventObject の行 + 座標、`FUN_002ef4f4`)。
- **区画 7** (12 B × 7): `{u32 mapObject の行 (0xF2), s16 x, s16 y}`。区画 2 (置物) の簡略版。

## 8. 編集するには

- 入口 (位置・向き・行き先・見た目・出現条件)、エンカウントの範囲、イベント・置物、地形のタイルが編集の対象になる。
- W01 / W02 の地形は 56562135 の W0x_ground.bin を書き換える (DB の区画 0 ではない)。+0x2BF30 の表を作り直す。+0x2C074 は意味が分からないので、元の値と再計算した値の大きい方にしておくのが安全。
- 入口を変えたら、行き先のマップの区画 3 (戻り先の入口 ID) も揃える。
- W98 / W99 は DB の区画 0 をそのまま使うので、ダンジョンの形式に近い。

## 9. 未解明

- ground.bin +0x2C074 の表、区画 1 の値の意味、入口 +0x00 の 74〜79 の違い (町・洞窟など)。
