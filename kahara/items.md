# 電波人間のRPG2 (kahara): アイテムと使用アクション

対象: 日本版 Title ID `00040000000A7900`、TitleVersion 1040 (1.1.0)。アドレスは展開済み code.bin の仮想アドレス (base `0x100000`)。[解析案内](analysis.md) / [ROM の識別・展開](../roms/kahara.md)。

## itemData.bin (713 行 × 0x30、アイテムID = 行番号)
| off | 型 | 内容 |
|---|---|---|
| 0x00 | u32 | 買値 |
| 0x04 | u32 | 売値 |
| 0x08 | u32 | フラグ (空行は 0xA0000320) |
| 0x0C | u32 | 名前 メッセージID (MessageSystemCommon) |
| 0x10-0x1C | u32×4 | 説明文 メッセージID ×4 |
| 0x20 | u32 | リソースハッシュ (CGFX/bcres。例 DC3B6800 は 1D37838B 内) |
| 0x24 | u32 | 道具 (大分類 1) ならアクションの行 (`FUN_002f6794`)。装備は s16 × 2 = 効果 1 / 2 の値 ([item-effects.md](item-effects.md))。たねなどはほかの値 |
| 0x28 | u16 | 並びの番号 (下記) |
| 0x2A | u16 | 上限到達時の連鎖先アイテムID |
| 0x2C | u8  | カテゴリ: 下位4bit=大分類 (1 道具 / 2 ゴールド / 3 装備 / 4 つりざお / 5 エサ)、上位4bit=小分類 |
| 0x2D-0x2E | u8 × 2 | 装備: 効果 1 / 2 の状態 (conditionData の ID、`FUN_0030a3d0`、[item-effects.md](item-effects.md))。つりざお・エサ・たね・花などはほかの値 |
| 0x2F | u8  | 最大所持数 (0 → 99) |

装備の小分類: 0x03 首 / 0x13 腕 / 0x23 足 / 0x33 背中 / 0x43 服

### +0x28 (並びの番号)
- 実在のアイテム 568 個に 1〜568 が重複なしで振られている (ゴールドボーナスと空き行は 0)。ID の順に増える。
- `FUN_001cd548` が、ID 1〜0x2C8 (712、行数が固定で書かれている) を順に見て、表[+0x28] = ID を作る (表は u16 × 713)。+0x28 が 0 の行は飛ばす。すでに埋まっている番号は上書きしないので、**同じ番号の行があると ID の小さいほうだけが残る**。
- 呼び出し元は `FUN_003fd304` (画面のオブジェクトの初期化、@0x3FD330)。表を読む側 (どの画面の並びか) は未確認。
- 新しいアイテムには、使われている最大 + 1 (569〜) を振るのが安全。[Panana の追加アイテム MOD](../integrations/panana/analysis.md) の ID 34 / 35 は +0x28 = 34 / 35 で、たね (ID 38 / 39) と重なっている (ID の小さい MOD のアイテムが残り、たねが表から外れる)。

### 使ったときに減るアイテム (アクション +0x14)
- `FUN_002f4c54(?, アクションの行)` は、行が 0xB2〜0xE6 (178〜230、「āはĆを使った」の行) ならアクションの **+0x14 (u16) = アイテム ID** を返し、それ以外は 0 を返す。
- フィールド・ハウスで使う処理 (`FUN_002f5324`) は、その ID を `FUN_0031140c(所持品, ID, -1, 0)` で 1 つ減らす (@0x2F5AD0、@0x410964)。つまり**減るのはアクションの +0x14 のアイテム**で、使ったアイテムそのものではない。
- 戦闘のメッセージ「āはĆを使った」の Ć も +0x14 から引く (`FUN_0024dc80` ほか、範囲の判定なし)。
- 元のデータでは、道具のアクションはすべて 178〜230 にあり、+0x14 はその道具自身 (#179 = 1 キズぐすり … #230 = 33)。行 0〜176 の +0x14 は別の意味 (電波人間のワザの AP など)、231〜671 はすべて 0。
- したがって、道具を写して新しいアイテムにするときは、アクションも写して +0x14 を新しい ID にする必要がある (同じアクションのままだと、元のアイテムが減る)。写したアクションは表の後ろ (672〜) に入るので、`FUN_002f4c54` の範囲を「0xB2 以上」に広げるパッチがいる (@0x2F4C58: `cmp r1, #0xb2` / `movlo r0, #0` / `push {r4, lr}` / `blo 0x2F4CA0`)。231〜671 は +0x14 が 0 なので結果は変わらない。
- 戦闘中に使ったときに減らす経路は、まだ確かめていない。

## itemData 説明文フィールド (確定)
+0x10 メニュー用 ([000D]) / +0x14 片言 Ď / +0x18 片言 ď / +0x1C 自然な口調 ď (「〜するよ。」)

## actionData.bin (672 行 × 0x3C) — アイテム使用効果
item+0x24 がアクション行番号 (消耗品のみ, `FUN_002f6794`)。効果量計算は `FUN_002f41ac` (対象ごと、効果種別で分岐) で、全体/単体は bit11 による対象選択側で決まる → 全体 AP 回復はデータ変更のみで実現可能。アクション番号は 11bit (最大 2047)。旧調査ではこの効果量計算経路に行数の固定値チェックが見当たらず、末尾追加で動作すると想定していた。ただし、戦闘のコマンドスロット設定 `FUN_00288634` の `0x28863C` には **672 以上の行を 0 にする制限**があり、追加アイテムを戦闘で使うには解除が必要 ([後続の MOD 実装記録](../integrations/panana/analysis.md))。
| off | 内容 |
|---|---|
| 0x00 | u32 ビットフィールド: bit1-2 カテゴリ (2=アイテム, 1=スキル), bit3-6 効果 (0 HP / 1 AP / 2 状態回復 / 3 復活), bit11 味方全体。値 (u32) 例: HP単体 0xA0324485 / HP全体 0xA0324C85 / AP単体 0xA032448D / **AP全体 0xA0324C8D** |
| 0x04 | 使用メッセージ (0x17DB「āはĆを使った」) |
| 0x0C / 0x10 | 結果メッセージ (0x1800 HP / 0x1802 HP平均 / 0x1803 AP / 0x1804 AP平均 ※未使用) |
| 0x14 | u16 アイテム ID, u16 1 |
| 0x18 | u16 最小, u16 最大 回復量 |
| 0x1C | u16 エフェクト (0x11 単体回復, 0x12 全体回復, 0x13 AP) |
| 0x20 | SE/演出 (0x44 小, 0x45 中, 0x46 全快) |

## アイテム追加時の制約
1. **予約スロット利用 (RomFS のみ)**: 該当カテゴリ直後の EMPTY 行を埋める
   - itemData.bin の行 + MessageSystemCommon_JP.gsmb に文字列追加 + 既存リソースハッシュ流用
   - 入手経路として [ShopItem](shops.md) / treasureGroup.bin に追加
2. **テーブル拡張 (RomFS + code.ips)**: 713→749 行 + [全アイテム走査ループ 26 箇所](code.md) の cmp を書き換え

### レアリティ
item+0x08 のフラグ bit5〜7 = ☆1〜7。

## 電波人間ハウスで使えるアイテム
ハウスのアイテム一覧 (`FUN_00267af0` case 2) は `FUN_002ddf98`: item+0x2C の下位 4bit が 1 で所持数 > 0 のうち、
場面 (`*(*DAT_002de028+8)`) が 4 なら item flags bit3、5/0x1B なら bit2、それ以外 (ハウス = 7) なら **bit4** が立つもの。
選ぶと `FUN_002c65f8` → `FUN_002f6794` (アイテム→アクション) → `FUN_002f5324` (フィールドと同じ使用処理)。
アクションの使用可否 `FUN_0030f8e0` は場面 4 → bit31、5 → bit29、7 → **bit30**。ペイントざい (186〜) は item bit4 + action bit30。
こていかのくすりは item flags |= 0x10、アクション 0xC03244AD (bit30 追加) でハウスでも使える。

旧メモの追加方針には `vendor.bin (ショップ)` とあったが、[ShopItem の解析](shops.md) と矛盾するため訂正した。`vendor.bin` の用途は未確定。MOD 固有の ID・パッチ・実装履歴は [Panana 実装記録](../integrations/panana/analysis.md)。
