# 電波人間のRPG2 (kahara): セーブ変数と電波人間の由来

対象: 日本版 Title ID `00040000000A7900`、TitleVersion 1040 (1.1.0)。アドレスは展開済み code.bin の仮想アドレス (base `0x100000`)。[解析案内](analysis.md) / [ROM の識別・展開](../roms/kahara.md)。

## セーブ変数 (flagData.bin, 150 行 × 0x10)
`FUN_00304adc(save, key, index, &out)` が行 `key` の定義に従ってビット配列を読む。
行: `+0 最大値, +8 u16 要素数, +0xB >>2 ビット幅, +0xC 要素数/単位`

アイテム関連 (いずれも **750 要素** = ID 0〜749 まで保存可能):
- 0x26 所持数 (7bit, max 99) / 0x27 所持数2 (預かり等)
- 0x15, 0x22, 0x70, 0x73, 0x76: 1bit フラグ (入手済み等)
- 0x71, 0x72, 0x74, 0x75: 8bit 値

flagData を変えるとセーブ配置が変わるため、既存セーブの互換性を維持する際は注意が必要。Panana の MOD は改変しない方針。

## 電波人間の由来 (origin) とさよなら / 呼び戻し
- セーブのユニットレコード (パーティ 8 × 0x78、ハウス × 0x74、`FUN_00311748` mode 0) の **+0x5A bit0-2 = origin**、bit3-7 = 見た目系。ランタイムユニットでは +0x2C にコピー (`FUN_00309f68`)。
  - 1 / 2: シードから生成 (`FUN_0023b844`、+0x0A==0 なら 1)
  - 3: コピー (QR / タウンのパソコン, `FUN_0023b2b0` が 0x6A バイトコピー後 origin=3 に設定)
  - 0: その他 (+0x3E = テーブル番号+1 を持つ)
- さよなら確認 (`FUN_00267af0` case 7): ユニット +0x2C == 3 なら 0x112「QRコードで入手した電波人間は…消滅」、それ以外 0x111。
- さよなら処理 `FUN_00220868`: origin 3 → 保存せず削除 (セーブ変数 0x10=1 のみ)。origin 1/2、または +0x3E≠0 → さよなら記録 (mode 4: 200 件 × 0x42 バイト、セーブブロック +0x5588) に先頭 0x42 バイトを保存。それ以外は削除。
- 精霊のほこら `FUN_00201b00` は mode 4 の記録を `FUN_00215d08` → `FUN_002d5300` で復元 (+0x3E があればテーブルから、無ければ +4 のシードから再生成)。記録には MAC も origin も含まれない。
- MAC アドレス (実セーブの +0x46〜0x4B 付近) が FF のユニットは origin 0 の通常ユニットにも多数あり、呼び戻し可否には使われていない。判定は origin のみ。
- QR 読み込み (`FUN_001be5a0` → `FUN_001bd8d0` → `FUN_00215da0` → `FUN_002db43c`) は QR の 0x04-0x6D をユニットレコード +0x00-0x69 にそのままコピーする (QR オフセット = レコード + 4)。由来は QR 0x5E の下位3bit で、ゲームの QR 書き出し (`FUN_0023b2b0`) は常に 3 にする。入手日の表示 (0x2F7808) も `rec[0x5A]&7 == 3` で「QR」/「入居日」を出し分ける。元解析の補足は外部作業環境の `emp/web/QR_ORIGIN.md` (本リポジトリ未収録、元パス `C:\Users\sweshelo\work\emp\web\QR_ORIGIN.md`)

## セーブのユニットブロック
ヘッダの (offset, 0x8A80) の最初の組がユニットブロック (0xA040)。2 番目 (0x27AB8) は更新されない古い写し。チェックサムなし。
Panana の外部ツール `tools/save_origin.py` の操作方法は [実装記録](../integrations/panana/analysis.md)。
