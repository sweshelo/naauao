# RPG3 (oahu) のショップ (ShopItem・Shop)

店の品揃え (`ShopItem`) と店ごとの設定 (`Shop`) の表。アドレスは Update (v4096) の code.bin。RPG2 (kahara) は `analysis.md`「ShopItem テーブル」「Shop テーブル」。

## 1. 置き場所

| 表 | エントリのハッシュ | 行 | 入っているアーカイブ |
|---|---|---|---|
| ShopItem | `0x67297400` | 782 × 0x10 | `3B630000`・`E3C10000` |
| Shop | `0xD5CEF800` | 44 × 0x38 | `3B630000`・`E3C10000` |

- ハッシュは RPG2 と同じ (同じ名前のファイル)。RPG2 の `49A43B63` に当たるのが `3B630000` (§4.1 の名前の付け方どおり)。
- `3B630000` と `E3C10000` の 2 つに**同じ中身**で入っている (Base・Update とも)。`3B630000` は Update で差し替わる (MessageCommand_JP が入っているため) が、ShopItem・Shop は Base と同じ。書き換えるなら両方を揃える。
- `3B630000` には店の部屋のモデル (`inside_01.bch`〜`inside_12.bch`、`inside_NN_cam.bch` がそのカメラ) も入っている。

## 2. ShopItem (782 行 × 0x10)

RPG2 (8 バイト) に 8 バイト増えた。並び方は同じで、**店 ID が 0 以上の行が店の頭**、続く店 ID −1 の行が品物。

| off | 型 | 頭の行 | 品物の行 |
|---|---|---|---|
| +0x00 | s32 | 店 ID | −1 |
| +0x04 | u32 | 未確認 (店 0・25・27・29・31 は 0、ほかは 1) | アイテム ID (itemData の行) |
| +0x08 | u32 | 0 | **ジュエルなどの値段** (§4。ゴールドの店では 0) |
| +0x0C | u8 | 0 | **1 回だけ買える品物の番号** (0 = 何度でも。1〜17) |
| +0x0D〜+0x0F | | `D0 D0 D0` (詰め物) | 同じ |

- 店 ID は 0〜36 (17・19 はない)。頭の行は 35 個。品物の行は 747 個。一番多い店は 54 品 (店 20)。
- 品物を引くのは `FUN_00233B00` (買う画面のリスト)。`FUN_0023119C(店, ID)` が頭の行を探し、続く行の数を数える。**店 17 と 19 は 16 と 18 の品揃えを使う** (`@0x2311F0` の `cmp r5,#0x11 / cmpne r5,#0x13 / subeq r5,r5,#1`。`@0x4B9764` にも同じ判定がある)。
- **+0x0C (1 回だけ)**: 0 でなければ、セーブのフラグ群 `0xAD` のビット (+0x0C − 1) が立っている品物はリストに出ない (`@0x233B74`、`FUN_004C8E94` → `FUN_004A261C`)。買うとそのビットを立てる (`@0x232D74`、`FUN_004A298C`)。数を選ばずに 1 個だけ買う (`FUN_004C8F0C` が 0 でないか見る、`@0x233E70`)。使われているのは釣りざお (12〜16、1)、ジュエルショップのモト (2〜8、17)、つりばチェッカー (10)、きせきのさお (11)。番号は店をまたいで共通 (店 27 と 28 は同じ番号を使い、どちらで買っても両方から消える)。

## 3. Shop (44 行 × 0x38、行 = Shop ID)

| off | 型 | 内容 | 根拠 |
|---|---|---|---|
| +0x00 | u32 | 店の部屋のモデル (`3B630000` のエントリ。例 `0x0B589C00` = `inside_01.bch`) | エントリ名 |
| +0x04 | u32 | そのカメラ (`inside_01_cam.bch` など) | エントリ名 |
| +0x08 | u32 | 店員のモデル: **+0x35 が 0 のとき mapObject.bin の行** (行の +0x00 / +0x04 = アーカイブ・エントリのハッシュ)。+0x35 が 2 の行 (0・25) は 0x52 | `@0x4B96D0` |
| +0x0C〜+0x30 | u32 × 10 | 店員のメッセージ: +0x0C いらっしゃい、+0x10 / +0x1C 買う / 売るときの「どうする」、+0x14 / +0x20 買う / 売る数、+0x18 / +0x24 買った / 売ったあと、+0x28 もう買えない、+0x2C 売る物がない、+0x30 ここで装備するか | `@0x2318D0`・`@0x231938` (買う / 売るで +0x10 / +0x1C、+0x18 / +0x24 を使い分ける) |
| +0x34 | u8 | 商品の説明の口調 (RPG2 と同じ。0 / 1 / 2) | データ (店員のメッセージの組と対応) |
| +0x35 | u8 | 店員の出し方 (0 = mapObject の行、2 = 特別。ほかの値は使われていない) | `@0x4B96B0` |
| +0x36 | u8 | 店員の高さ (float にして Y 座標に使う。23 か 50) | `@0x4B9720` |
| +0x37 | u8 | **支払いの種類** (§4) | `@0x23376C` → 店のオブジェクト +0x73C |

- 店員のメッセージの組は RPG2 と同じく口調ごと: 0xE3〜 (ちていじん、片言)、0xED〜 (片言)、0x108〜 / 0x111〜 (ふつう / 心の声つき)、0x11A〜、0x123〜、0x12C〜。
- Shop ID は 44 まで (`@0x2337E8`: 0x2C 以上なら 0 にする)。ShopItem に品揃えがあるのは 0〜36。37〜43 は支払いの種類 3 (バザー) で、品物はセーブのバザーの中身から作る (`FUN_002312D0`)。

## 4. 支払いの種類 (Shop +0x37)

| 値 | 通貨 | 値段 | 店 |
|---|---|---|---|
| 0 | ゴールド (セーブ変数 0x29) | itemData の買値 × 数 | 0〜26、34〜36 |
| 1 | **ジュエル** (セーブ変数 0x2A、上限 9999) | ShopItem +0x08 × 数 | 27〜32 (ジュエルショップ) |
| 2 | 別の数 (セーブの +0x288 の下位 24 ビット、上限 9,999,999。コロシアムのポイントと推定) | ShopItem +0x08 × 数 | 33 |
| 3 | ゴールド (1 個ずつ) | | 37〜43 (バザー) |

- 払う処理は `FUN_00232B68` (種類で分岐: 0 `FUN_0022A0C8`、1 `FUN_0022A2E8`、2 `FUN_0022A33C`、3 `FUN_0022A07C`)。持っている数は `FUN_00230DB4` が種類ごとに読む。
- 店 26 (`0x1A`) は釣りの店で、売るときの値段に倍率を掛ける (`@0x233138`)。

## 5. 分からないこと

- ShopItem の頭の行 +0x04 (0 か 1)。店 27・29・31 が 0、そのあとの 28・30・32 (品物が同じか多い) が 1 なので、話の進み具合で切り替える組と推定。
- どのイベントがどの Shop ID を開くか (店の場所)。開くときの ID は `[0x5A1A9C] + 0x0C` から読む (`@0x2337DC`)。
- 店員の +0x35 = 2 のときの 0x52 の意味。
