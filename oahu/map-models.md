# RPG3 (oahu) のマップモデル

対象: 日本版 RPG3 (oahu)、Update TitleVersion 4096 の code.bin。アドレスは実行時仮想アドレス。以下の「確定」は既存のコード解析・実データ照合による記録、「推定」「未確認」はそのまま区別する。Base / Update の資源の選択は [更新データ](../roms/oahu-update.md) を参照。

マップ区画のレコードは [マップ](map.md)、EventObject のオフセットは [イベント](events.md) を参照。


## 1. 宝箱 (区画 4)
- `FUN_003684A4`: EventObject の +0x4E (mapObject の行) が 0 でなければそのモデル。0 ならレコード +0x00 の下位バイト 0 / 1 / 2 で、屋外は mapObject 0x34 / 0x35 / 0x36、屋内 (ランタイム +0x546C) は 0x37 / 0x38 / 0x39 (`gimk_05_trebox_1`〜`06`)。宝箱は回さない。
- 開けたときの動きは EventObject の種類 (+0x55) で決まる。0x10 = 宝箱 (`FUN_001E6804`)、0x12 = 別のクラスの宝箱 (`FUN_0027EED4`)。どちらも +0x10 が treasureGroup の行 ([マップ §10](map.md))。0x2E (スクリプト) で中身を渡す宝箱もある。v4096 では 281 個の宝箱がモデルを持つ。

## 2. キャラ (区画 5 の種類 0〜2) と mapChara
- `FUN_00366F30`: EventObject の +0x4E が **mapChara の行** (マスター 21350000、635 行 × 0x14)、+0x50 がモデルの枠 (0〜2)。
- mapChara: +0x00 の下位 3 ビットが種類。0 = NPC (+0x08 / +0x0A / +0x0C の枠が mapObject の行)、1 = モンスター (枠が monsterDesign の行。402F0000 のモデル)、2 / 3 = 電波人間 (§5)。顔・体・色を mapChara 自体に直接持つわけではない。
- NPC の BCH (アーカイブ 1D1A0000 など) はどれも `001_NPC22_wait` のような "001_" の待機の動きを持つ。

## 3. 向き
- キャラ (区画 5 の種類 0〜2、+0x1C): 0 = 180°、1 = 90°、2 = 0°、3 = 270° (`FUN_00366F30`)。
- 置物 (区画 2 の +0x10) と区画 5 のオブジェクト (種類 4 / 5 / 6 / 0x0B / 0x0D / 0x0E、+0x1C): c = 向き + 1 → 1: 180°、2: 90°、3: 0°、4: −90° (`FUN_00364B80` / `FUN_00366880`)。RPG2 の置物と同じ表。置物の向きが 3 を超えると c = 1 (`FUN_00276078`)。

## 4. mapObject (マスター 21350000、510 行 × 0x38)
| 位置 | 型 | 内容 |
|---|---|---|
| +0x00 / +0x04 | u32 | モデルのアーカイブ / エントリ |
| +0x10 | f32 | 当たりの半径 (円柱)、または箱の幅 |
| +0x18 | f32 | 箱の奥行き |
| +0x1C | u8 | bit0 = 当たりが箱 (幅 +0x10 × 高さ 400 × 奥行き +0x18)。0 なら半径 +0x10 の円柱 |
| +0x20 | f32 | 大きさ (0 = 1。NPC は 1 より大きいものが多い) |
| +0x2C | u16 | オブジェクトの +0x28 に写す |
| +0x2E / +0x30 / +0x32 | s16 | +0x34 のエフェクトを置く位置 (x / y / z。オブジェクトの向きで回す)。宝箱 (`FUN_003684A4`) では当たりの箱のずらし |
| +0x34 | u8 | mapEffect の行 (0 = なし。3 行) |
| +0x35 | s8 | **高さのずらし**。置物 (`FUN_00364B80`) と区画 5 の種類 4 / 5 / 6 / 0x0B / 0x0D / 0x0E (`FUN_00366880`) で y に足す。行 60〜72 が −2 |

- 以前「+0x14 = 高さ」としていたのは誤り (当たりの高さは 400 固定)。
- 区画 8 の種類 100 以上は `FUN_00275F2C` が置物と同じように置く: 100 / 101 / 102 = mapObject 0x1E6 / 0x1E7 / 0x1E8 (`obj_invisible`、見えない壁)、それ以降も 0x1E6。向きは +0x1C (置物の表)。大きさは 240 / 340 / 540 × 140 (幅 × 奥行き)。

## 5. 電波人間 (mapChara 種類 2・3)

Update TitleVersion 4096 の code.bin と Base / Update のマスターで確認 (出典: panana#96)。描画実装・検証の記録は [Panana の連携資料](../integrations/panana/oahu.md)。

**参照先** (`FUN_00367794`〜`00367AE8`, `FUN_00366F30` の続き):

- EventObject +0x50 = 0 / 1 / 2 で mapChara +0x08 / +0x0A / +0x0C の u16 を選ぶ。各枠の +0x0E / +0x0F、+0x10 / +0x11、+0x12 / +0x13 は移動時の値で、顔パーツではない。
- **種類 2**: 選んだ u16 は `denpaCustom.bin` の行。`FUN_002221B8` → `FUN_0038ACFC` で個体を作り、`FUN_00221A94` で描画用モデルを組む。denpaCustom はマスター 21350000 の読み手 +0x284、126 行 × 0x28。
- 種類 2 の行 79 / 82 / 83 は例外。`FUN_00222370` / `FUN_00221820` / `FUN_00221890` がセーブ内の個体を優先し、見つからなければその denpaCustom 行を使う。
- **種類 3**: 選んだ u16 の下位バイトを `FUN_004EF1A4` に渡し、セーブキー **0x49** のその要素の 2 バイト（8bit値2個）から個体参照を作る。定義表の +0x0C = 2 と復元ループを今回のROMで再確認した（[セーブ定義](story.md) §3.1）。`0x4EF1F0` / `0x4EF1F4` で読み、1バイト目の下位5bitと2バイト目を13bit左シフトした値を個体参照に組み込む。denpaCustom の行ではない (例: mapChara #36 の値は 166、#50 は 180)。セーブの個体が見つからないと `FUN_00221A94` は **denpaCustom #92** にフォールバックする。
- 例: mapChara #89 (種類 2) → denpaCustom #115、#36 (種類 3) → セーブ側の参照 166。

**denpaCustom の見た目** (`FUN_0038AE54`〜`0038AEE8`, `FUN_004AEE20`):

| 位置 | 内容 | 描画用の値 |
|---|---|---|
| +0x18 | 体色 | bodyColorData の行 (0 始まり) |
| +0x19 | 頭 | headData / hum_head の番号 − 1 |
| +0x1A | 体型 | bodyData の行 − 1 |
| +0x1B | 顔の形 (Skin) | 顔アトラスの番号 − 1 |
| +0x1C | 髪 (Hair) | 顔アトラスの番号 (減算なし) |
| +0x1D | 肌色 | パレットの番号 − 1 (6 色) |
| +0x1E | 髪色 | パレットの番号 − 1 (12 色) |
| +0x1F / +0x20 / +0x21 | 眉 / 目 / 鼻 | 顔アトラスの番号 − 1 |
| +0x22 / +0x23 / +0x24 | 口 / 頬 / 眼鏡 | 顔アトラスの番号 − 1 |

- #115 は体色 4、頭 0、体型 26、顔 1、髪 17、肌色 2。#92 は体色・頭・体型・各顔パーツすべて 0 の既定個体。
- `FUN_0038ACFC` が初期化する個体の +0x4E〜+0x58 は技 (作成時 0、習得段階の判定で更新)、頭、顔、髪、眉、目、鼻、口、頬、眼鏡、体型。体色は +0x5A、肌色・髪色は +0x5B / +0x5C。`FUN_004CDE2C` は +0x4E へのポインタを返す。

**モデルと体色** (`FUN_00221A94`, `FUN_001EA63C`, `FUN_001EA6EC`, `FUN_001EA4A8`):

- 体: 96EB0000 / **679F6C00**, `hum_body_01` (25 ボーン)。全体型で同じモデル。bodyData は 30 行 × 0x20、+0x00 の f32 は頭の一様倍率、+0x04 は体の縦、+0x08 は体の横・奥行きの倍率 (`FUN_004AEB00` / `FUN_004AEDD4`)。
- 頭: **15920000** の 40 モデル `hum_head_01`〜`hum_head_40`。対応するハッシュの表は code.bin の 0x556580 (`FUN_001EA6EC`)。体の `head` ボーンに接続。
- 顔: 96EB0000 / **1EA28800**, `hum_N_face_01`。8 材質 (Brow / Eye / Nose / Mouth / Cheek / Megane / Hair / Skin)、テクスチャ `parts` と `face_01` を内包。頭の `m_Face` に接続。パーツを個別のモデルから選ぶのではなく、UV 移動でアトラスを選ぶ。
- 体色: bodyColorData は 33 行 × 0x10、+0x00 の u32 がマスター 21350000 内のテクスチャ BCH のハッシュ (`hum_base`)。頭と体で共有。
- アンテナ: **E50D0000** の `antenna_00`〜`antenna_64` と `antenna_empty`。頭の `ante` に接続。共有テクスチャはマスター **75F22000** (`antenna_01`)。denpaCustom +0x04 の u16 が antennaGroup の行で、個体 +0x68 に保存される。+0x11 はレベル (0 はセーブの進行度による)。`FUN_0029B398` がレベルを antennaGroup 各段階の閾値と比較し、段階 − 1 の +0x04 の bits 10〜18 から技を選ぶ。`FUN_001EAD90` → `FUN_001EAECC` が actionData と antennaGroup からモデルの番号を選ぶ (ハッシュ表は 0x5566C0)。個体 +0x4E の 0 をそのままモデルの番号として使わない。
- 待機: **F48B0000 / 6F8F7000**, `001_N_Stay`。体の骨格を動かし、頭・顔・アンテナは接続した骨格に追従する。
- 装備は denpaCustom +0x06〜+0x0E から別途読み込まれる (`FUN_0038AF68`〜`0038AFF0`)。

**名前付きの比較個体** (セーブで変更する前のマスター値):

| 名前 | denpaCustom / 名前のメッセージ | antennaGroup | 頭 / 体型 / 体色 | 顔 / 髪 | 眉 / 目 / 鼻 / 口 / 頬 / 眼鏡 |
|---|---|---|---|---|---|
| あかり | 79 / 8565 | 6 | 0 / 26 / 4 | 1 / 17 | 0 / 24 / 4 / 0 / 1 / 0 |
| みちる | 83 / 8569 | 5 | 25 / 13 / 1 | 1 / 17 | 4 / 30 / 6 / 26 / 0 / 0 |

antennaGroup 5 / 6 の初段は技 14 / 17。両方ともモデルの特別形式 (番号 0 / 1、`antenna_00` / `antenna_01`) と図柄 2 (ハート) を組み合わせる。モデル 1 には輪も付く。技の actionData +0x2A の段階で antennaGroup の `{u32, u32}` を選び、後半の bits 19〜21 が 0 / 1 のときはそのモデル、その他は bits 22〜29 をモデル番号とする (`FUN_001EAECC`)。0 / 1 形式では bits 22〜29 − 1 が図柄番号 (`FUN_001EB044`)。図柄 n の UV 移動は `(floor(n/8)/8, −(n mod 8)/8)` (`FUN_001EADF4` / `001EA958`)。bits 31 が 0 / 1 で共有テクスチャ **75F22000 / 33945C00** を選ぶ (`FUN_001EA54C`)。

アンテナの倍率は技の番号ではなく表示段階から決まる (`FUN_001EAD24` / `001EA3EC`): antennaGroup +0x32 下位 2 bits が 1 なら習得段階 − 1、ほかは 1。表示段階 0 は 0.65、1 は 0.9、2 / 3 は 1.3、その他は 1。頭の倍率を二重に掛けない。


**顔アトラス** (`FUN_001EA958`, `FUN_001EA4F0`):

以下は 0 始まりの値 `n` から得る実行時の UV 移動量 `(U, V)`。モデルの UV に **足す**。

| 材質 | 個数 | (U, V) |
|---|---|---|
| Brow | 20 | n < 16: (4/16, −(n−8)/16)、それ以外: (5/16, −(n−12)/16) |
| Eye | 48 | (floor(n/16)/16, −(n mod 16)/16) |
| Nose | 32 | ((floor(n/16)+3)/16, −(n mod 16)/16) |
| Mouth | 40 | ((2×floor(n/16)+1)/16, −(n mod 16)/16) |
| Cheek | 12 | (1/4, −(n+4)/16)。n ≥ 8 は n−12 を使う |
| Megane | 24 | ((floor(n/16)+4)/16, −(n mod 16)/16) |
| Skin | 12 | n < 8: (−n/8, 0)、それ以外: (−(7−(n mod 8))/8, −1/4) |
| Hair | 40 | n ≥ 32: ((n−32)/8, −3/8)。n < 32 かつ n mod 4 ≠ 0: (floor(n/4)/8, −((n mod 4)−1)/8)。残りは q=floor(n/4) として ((4+(q mod 4))/8, −(floor(q/4)−2)/8) |

- 肌色 RGB の表は 0x5567C8、髪色は 0x556810 (各色 3 個の u32)。`FUN_001EA390` / `FUN_001EA334` が Skin / Hair の定数色を変える。
- 眉は番号 15 のとき髪色、ほかは白。口は番号 25〜27 のとき髪色、ほかは白 (`FUN_001EA2BC` / `FUN_001EA42C`)。

## 6. 出入口・階段・扉 (区画 3、`FUN_00365294`)
`FUN_002CA100` が種類をセルの欄 (+0x0C 階段、+0x0D 向き + 1 = c、+0x0E 鍵、+0x0F ギミック、+0x14 地点 ID) に変え、`FUN_00365294` がそこからモデルと置き方を決める。EventObject の +0x4E が 0 でなければそのモデル。

| 種類 | 階段 / 鍵 / ギミック |
|---|---|
| 0〜0x13 | ギミックは表 `[1,1,5,0xD,2,2,3,4,6,7,8,0,0,0,0,0,0xA,0xB,0xC,0xE]`。4 / 5 は階段 0 (上り) / 1 (下り)、0x0B〜0x0E は鍵 = 種類 − 0x0A |
| 0x14〜0x42 | 町の建物。ギミック = 種類、階段 1 |
| それ以外 | ギミック 1 |

既定のモデル (mapObject の行):
- 町の建物: 種類 0x14〜 の順に 0xBE〜0xCB、0xCD、0xCE、0xD0、0xD2〜0xED、0xCC、0xEE。
- ギミック 5 → 0x5E、0x0A → 0x26、0x0B → 0x27、0x0E → 0xD0 (M10OUT000 / M90OUT000) または 0xD1、9 → 5。
- ギミック 0 で鍵あり → 0x20 + 鍵 (鍵 5 以上は 0x25)。
- 階段 0: ギミック 7 / 4 / 8 → 0x1E4、3 → 0x49、0x0C → 0x1E5、それ以外は鍵ありで 4、なしで 0x20。階段 1 → 1。それ以外はギミック 3 で 0x49、ほかは 2。
- ワープ (種類 8、`FUN_00368784`) は 0x5D。
- 壁の扉 (種類 0x64、`FUN_00274A6C`): セルを {階段 0、c = 置物の c、鍵 0、ギミック 9} として組み、モデルはタイルの mapResource +0x1C (0 なら 5)。高さ −5。

置き方 (c = 向き + 1、1 = 北 / 2 = 東 / 3 = 南 / 4 = 西。角度は c 1: 0°、2: −90°、3: 180°、4: 90°):
- 建物とギミック 5: 回さず、ずらさない。
- 扉 (階段 0 のギミック 0 / 0xA / 0xB): c の角度、c の向きへ 100 ずらす。ギミック 0xC は 250。ギミック 5 / 8 / 3 / 4 はセルの中央。
- 屋内の階段: c の角度 −90° (上り) / +90° (下り)、c の向きへ 50。
- 屋外の階段: 角度は表 (上り `[0, 90°, 0, 270°, 180°]`、下り `[0, 270°, 180°, 90°, 0]` を c で引く)。
- 多くのレコードは +0x0C / +0x10 のずれを持つ (そのまま足す)。

## 7. 区画 5 のオブジェクトの既定モデル
- EventObject の行がなければ置かない。モデルは EventObject の +0x4E、0 なら種類の既定: 3 → 0x33 (`gimk_04_heal_1`)、7 / 8 → 0x62 / 0x63 (`gimk_14_roller_01` / `02`)、9 → 0x67 (`mnmp_obj_02_01`)。
- 種類 3 / 7 / 8 / 0x0C は回さない。9 / 0x0A は置物の表 (§3)。ほかは キャラの表 (§3) と mapObject +0x35。
- 種類 0x0C はエフェクト 1AD40000 / F9061400 の上に EventObject のモデルを置く。種類 6 / 0x0B / 0x0D / 0x0E は下へ光線を飛ばして地面に置く (`FUN_00225BD8`)。
- 種類 9 は D30B01001 (0x97FC787C) でだけモデルを 0E820000 / 39142000 (高さ −45) に替える。
