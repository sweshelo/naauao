# RPG3 (oahu) のワールドマップ (W01)

> 対象: 電波人間のRPG3 日本版 Base v0 + Update v4096。分類: ゲーム既存仕様。
> 根拠: 本文に記す関数の逆アセンブル (capstone) と、v4096 の実データ (マップ DB `B68E0000/A2C14C00`、master `21350000`)。
> アドレスは実行時アドレス (code.bin の位置 = アドレス − `0x100000`)。RPG2 の [worldmap.md](../kahara/worldmap.md) と同じ作りで、違うところは本文に書く。

確度: **確定** = コードで読み方を確認し、実データで裏付けたもの。**推定** = 呼び出し元とデータの形からの推測。

結論を先に書く: **RPG2 と同じ仕組み**。地形は master の `W01_ground.bin`、それ以外はマップ DB の区画で、区画の表は code.bin にある。RPG2 と違うのは、区画の並びと 1 件のサイズ、入口の行き先が **w01_EventObject の行** に移ったこと (ダンジョンの出入口と同じ)、地形の部品ごとのプールの数え方。

## 1. 区画の表 (確定)

- code.bin **0x556D54** に 1 行 × 9 × u32 (マップ DB のハッシュ)。取り出しの関数はどれも「マップ = `A8654391` なら行 0、それ以外は行 −1」で引くので、ワールドマップは W01 の 1 枚だけ。
- マップ表 (`5405E800`) の W01 の行の区画 (スロット 0〜9) は、この表と一部しか一致せず、ゲームは使わない。

| スロット | ハッシュ | サイズ (v4096) | 取り出し | 使い手 | 内容 |
|---|---|---|---|---|---|
| 0 | `A8654391` | 200,088 B | `FUN_002ab9bc` | `FUN_002fbb48` | 地形のタイル `{u32 部品, s16 x, s16 y, u32 向き}` (12 B)。W01 では使わない (§3) |
| 1 | `F54B912E` | 22,500 B | `FUN_002ab900` | `FUN_002fb6f8` (+0x2ECFC) | 2 bit × 300 × 300 のグリッド。値 0〜3 (65,581 / 1,489 / 1,439 / 21,491 セル)。意味は未解明 (RPG2 の区画 1 に当たる) |
| 2 | `85175911` | 4,864 B | `FUN_002ab824` | `FUN_0032d134` ほか 12 か所 | **町・ダンジョンの入口** (32 B × 152、§4) |
| 3 | `085D1B2B` | 3,012 B | `FUN_002abbc4` | `FUN_0032cc9c` | **エンカウントの範囲 (陸)** (12 B × 251、§5) |
| 4 | `6B11FA64` | 7,308 B | `FUN_002ababc` | `FUN_0032cb14` | **エンカウントの範囲 (海)** (12 B × 609、§5) |
| 5 | `AD947450` | 128 B | `FUN_002abe00` | `FUN_0032cf88` | イベントの範囲 (32 B × 4)。ダンジョンの区画 8 と同じ形 (`FUN_00369038` で登録、ハンドラ `FUN_002724e8`) |
| 6 | `59A0B01E` | 40 B | `FUN_002abd50` | `FUN_0032d560` | 置物 (20 B × 2)。ダンジョンの区画 2 と同じ形 `{u32 mapObject の行, s16 x, s16 y, f32 dx, f32 dy}` |
| 7 | `32407956` | 22,500 B | `FUN_002ab73c` | `FUN_002fb4c0` (+0x2ED00) | 2 bit × 300 × 300 のグリッド (DB では全部 0)。§3.3 |
| 8 | `3BF20831` | 80 B | `FUN_002abc74` | `FUN_0032ce24` | **宝箱** (8 B × 10、§6) |

- 区画 3〜6・8 の使い手 (`FUN_0032cb14`〜`FUN_0032d560`) は `FUN_0032d0e8` 付近の 1 つの初期化からまとめて呼ばれる。

## 2. 座標 (確定)

- 1 セル = **100** 単位 (ダンジョンは 500)。セルの中心 = 50 + x × 100 (`FUN_0032ce24` の定数 50 / 100、入口の `FUN_0032d134`)。
- グリッドは 300 × 300。セルは y × 300 + x の順。
- 地形のモデル (`bgpt_wld_*.bch`) は 1 セル = 100 × 100 で、原点はセル (2 × 2 の部品はブロック、2 マスの部品は 2 セル) の中心。

## 3. 地形 (確定)

### 3.1 W01_ground.bin
- master `21350000` の `W01_ground.bin` (エントリ `4FFFAC00`、ZIP、184,628 B)。`FUN_002fa8fc` がマップ = W01 のとき `FUN_002fa9ec` で読む (それ以外のマップは区画 0 を `FUN_002fbb48` で読むが、表の行がないので使われない)。

```
+0x00  u32 1, u32 0x14 (グリッド), u32 0x2BF34 (プール), u32 0x2C0B0 (区画 7 の初期値), u32 0x2DEBC (未使用・ファイルより後ろ)
+0x14  300 × 300 × {u8 worldmapParts の行, u8 向き (下位 2 bit)}   0 = なし (海)
+0x2BF34  u32 × 95   部品ごとのプールの数 (§3.2)
+0x2C0B0  {s16 x, s16 y} × 961、x = 0 で終わり (その後ろは 0 で埋まる)
```

- **部品は起点のセルにだけ入る。** 読み込み時に、worldmapParts +4 のフラグ 0x10 の部品は x+1 / y+1 / x+1・y+1 にも、0x20 の部品は向き 0・2 なら x+1、1・3 なら y+1 にも同じ部品を書く (メモリのセルの byte 1 の bit 2〜3 が「どこの一部か」)。フラグ 0x08 はセルの byte 1 に 0x20 を立てる。RPG2 と同じ。
- フラグ (0x58, 0x18) が立っているときは、x = 115〜149、y = 105〜134 の範囲を読まない (`FUN_002fac48`、話の進みで島が変わると推定)。

### 3.2 プールの数 (確定)
- `FUN_00327138` が部品 2〜0x56 ごとに +0x2BF34 の数だけインスタンスのプールを作る (0x54〜0x56 は別の定数)。
- 値 = **グリッドの 2 × 2 のどのブロック (はみ出しなし、ずらしながら) にも入る、その部品の起点のセルの最大数**。v4096 の 95 個すべてがこの再計算と一致する (RPG2 は 23 × 15 の表示窓だった)。
- 地形を変えたら作り直す。足りないと描けない部品が出ると推定。

### 3.3 区画 7 の初期化 (確定、意味は推定)
- `FUN_002fb4c0` が区画 7 (2 bit) を読み、一度だけ (`0x5A0D28` のフラグ) +0x2C0B0 のリストのセルに値 1 を書く (`FUN_002ab700`)。リストは x 187〜249、y 231〜289 (始まりの島のまわり)。
- 推定: 地図の「開けた」範囲 (最初から見えている場所)。

### 3.4 worldmapParts (master +0x604、95 × 12 B、確定)

| 位置 | 型 | 内容 |
|---|---|---|
| +0x00 | u32 | 地形のモデル = アーカイブ `0E820000` の種別 2 のエントリ (`bgpt_wld_flat_00.bch` など、86 個)。0 = モデルなし |
| +0x04 | u8 | フラグ: 0x10 = 2 × 2 セル、0x20 = 2 セル、0x08 → セルの 0x20、0x04 / 0x01 / 0x02 = 地形の種類 (推定) |
| +0x05 | u8 | 0x34 (全行) |
| +0x08 | u16 | 入口の既定のモデル (mapObject の行)。行 88〜93 だけ (0x16C / 0x16D / 0x16B / 0x170 / 0x16C / 0x16E) |
| +0x0A | u8 | 戦闘の mapData の行 (160〜166。[音 §3.5](sound.md)) |
| +0x0B | u8 | 0xD0 |

- 行 0 = なし、行 1 = 海 (`bgpt_wld_sea_00`、25 × 25 セルの大きな面。グリッドには置かれない)、行 87〜94 = モデルなし (88〜93 は入口の種類)。
- テクスチャは同じアーカイブの `tex_worldmap.bch` (`D47B4000`: `bg_sea`、`mnmp_*`) を共有する。

## 4. 区画 2: 入口 (確定)

32 B × 152。`FUN_0032d134` がモデル (`FUN_00365294`) を置き、`FUN_002fc10c` は位置 (x, y の ±1) で入口を探す。

| 位置 | 型 | 内容 |
|---|---|---|
| +0x00 | u32 | worldmapParts の行 (88〜93 = 入口の種類)。**0 = モデルなし**: 町・ダンジョンから出たときに立つ位置 |
| +0x04 | u32 | モデル (mapObject の行 362〜403。アーカイブ `0E820000` / `F9270000`) |
| +0x08 | u32 | この入口の ID (ハッシュ) |
| +0x0C | u32 | **w01_EventObject の行** (`233D0000` の `w01_EventObject.bin`、112 行)。0 = なし |
| +0x10 / +0x12 | s16 | x / y (セル) |
| +0x14 / +0x18 | f32 | ずれ (セル単位、± 0.5 など)。位置 = 50 + (x + dx) × 100 |
| +0x1C | u8 | 向き (`FUN_00276078`、置物と同じ表) |
| +0x1D | u8 | **mapJumpPoint の行** (87 行。ワープの行き先の一覧)。その行にこの入口の ID と、隣の出る位置の ID が入る (欄の位置は行で違い、未解析) |
| +0x1E | u8 | 2 の行が 2 つ (未解析) |

- **行き先は EventObject に移った**: +0x0C の行の +0x10 / +0x14 が行き先のマップ / 地点 (種類 +0x55 は 0x21 が 81 件、0x2E が 4 件、0x16 が 1 件)。v4096 の 86 件のうち 85 件は実在のマップの出入口 (区画 3 の ID) を指し、1 件 (#56、種類 0x2E) は行き先が 0。RPG2 は入口のレコードの +0x08 / +0x0C だった。
- モデルなしの入口 (66 件) は、ふつう対になる入口の隣のセルにある。ダンジョンの区画 3 の出入口の EventObject (+0x10 = `A8654391`、+0x14 = この ID) がここを指す。
- worldmapPort (master +0x620、26 × u32) は入口の ID の一覧 = 船の止まる入口 (I01〜I24 の島、D30、D60、M10 など)。
- mapAppearWorldmap (2 行 `{u32, u16 mapObject の行, u16 距離}`) はモデルの見える距離 (RPG2 の MapAppearWorldmap と同じと推定)。

## 5. 区画 3 / 4: エンカウントの範囲 (確定)

- `{u32 areaInfoData のハッシュ, s16 x, s16 y, u8 幅, u8 高さ}` (12 B、セル単位。全件 3 × 3)。
- `FUN_0032cb14` (区画 4) / `FUN_0032cc9c` (区画 3) が x / 3、y / 3、幅 / 3、高さ / 3 (`× 0x5556 >> 16`、`× 0xAB >> 9`) の範囲に、ハッシュで引いた areaInfoData の行を `FUN_002c9cb8` で 100 × 100 のエリアの格子に書く。層は区画 4 が 1、区画 3 が 0。
- areaInfoData (8 B): `{u32 群れ (monsterGroup の行、推定), u16 +0x04, u8 +0x06 種類, u8 0xD0}`。区画 3 のハッシュ (8 種) の行は +0x06 = 1、区画 4 (7 種) は 2 なので、**3 = 陸、4 = 海** (船)。

## 6. 区画 8: 宝箱 (確定)

`{u32 w01_EventObject の行, s16 x, s16 y}` (8 B × 10)。`FUN_0032ce24` が宝箱 (`FUN_003684a4`、ハンドラ `FUN_004bc4ec`) を 50 + x × 100 に置く (高さ −3.75)。中身はダンジョンの宝箱と同じく EventObject の +0x10 (treasureGroup)。

## 7. 編集するには

- 地形: `W01_ground.bin` のグリッドを書き換え、+0x2BF34 のプールを §3.2 で作り直す (Panana は元の値より小さくしない)。
- 入口: 区画 2 のレコード (位置・向き・モデル・種類) と、+0x0C の EventObject の行の +0x10 / +0x14 (行き先)。行き先のマップの出入口の EventObject (+0x10 = W01、+0x14 = 出る位置の ID) も揃える。
- 範囲: 区画 3 / 4 のレコード。ゲームは 3 セル単位で読むので、x・y・幅・高さは 3 の倍数にする。

## 8. 未解明

- 区画 1 の値の意味、区画 7 の用途 (地図の開けた範囲と推定)、入口 +0x1E、areaInfoData +0x04、worldmapParts +0x04 の下位 3 bit。
- W01_ground.bin ヘッダー +0x10 (`0x2DEBC`) はファイルの外を指し、使われていない。
