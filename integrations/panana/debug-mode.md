# Kahara: Panana のデバッグモード (Azahar 専用)

対象: 日本版 v1.1.0。Panana の `src/game/debugmode.ts`。2026-11-02 に ROM から読み取った内容で、ゲームでの確認はまだ (確定・推定は各項目に書く)。

## 使い方

フィールド (ダンジョン・ワールドマップ) で動ける間に、立ち止まって **L と R を一緒に押し続ける** (約 0.33 秒、ボタンの連続入力が出るまで)。地の文の窓にメニューが出る。

SELECT / START はフィールドの処理より先に中断セーブ・セーブのダイアログ (下画面) に取られるので使えない (2026-11-02、Azahar でユーザー確認)。連続入力 (+0x58) の待ちは `FUN_0033a244` の初期値 1/3 秒。L だけを押すと「調べる」(0x3FF290、A と同じ) なので、押した瞬間 (+4) ではなく連続入力で判定する。

- アイテムを手に入れる (店): 全アイテムを 0 G で売る店 18 を開く。
- ストーリーを進める: Panana のストーリーの節目 (`storyconditions.ts`) の最初から選んだ節目までのセーブ値を書く。ボスは 0x91[n] = 2、エンディングは 0x8D[種類 − 0x18] = 値。
- セーブ変数を書きかえる: 変数・位置・値を十字キーで選び、A で書く。1 行目に今の値。
- ワープする: ジャンプの行き先 (mapJumpPoint の行 1〜、訪れたか・一覧に出さない印に関係なく全部) から選び、A でその入口へ。

## 仕組み

| 部分 | 内容 | 確度 |
|---|---|---|
| ボタン | `*0x57410C` の +0 押している、+4 押した瞬間、+0x58 押した瞬間 + 連続入力 (+0x54 のリピータ、`FUN_0033a28c`)。ビットは HID と同じ (A 1, B 2, SELECT 4, START 8, →←↑↓ 0x10〜0x80, R 0x100, L 0x200, X 0x400, Y 0x800、スライドパッド 0xF0000000)。窓のボタン待ち `FUN_0031cab4` のマスクは 0xF0000EF3 | 確定 (読み取り) |
| 起動 | `FUN_003fef90` (フィールドの更新 `FUN_003fe78c` から、操作できる間だけ毎フレーム。r4 = フィールド、+0x18 = 動作のキュー)。0x3FF000 の `ldr r0, =0x51BEBC` を `bl` に替えて判定する。L と R を押していて、+0x58 に両方が出て +4 には出ていないフレームで反応し、+0x58 から L・R を消す | 推定 |
| キュー | 手札 (ハンドラ) を `FUN_0030cab8(キュー, 手札)` で登録 (+0x19C の u16 が数、+0xC から最大 100)、`FUN_0030b7ac(キュー, 行)` が行の一致する手札の [3] が返す動作を 5 枠に積む。手札の基底 `FUN_00309554(obj, 行)`、vtable 7 項目 {0, [1] 解放 0x1B0FB8 (`FUN_003094e0` が +0xC〜+0x14 の動作も解放), [2] 初期化, [3] 動作を返す, [4], 0, 0}。デバッグは疑似行 0x1DEB000 (0xFFFFFF 以上は状態を持たない) の手札をマップごとに 1 回登録する | 推定 (呼び方は読み取りで確定) |
| 窓 | `FUN_00311384(1)` が地の文の窓を作る (`*0x56CEF8`)。`FUN_0031cbec(窓, ID, a1, a2, [sp] a3, [sp+4] a4, [sp+8] 開く待ちなし)` が文を出し、`FUN_0031cba0` が文字送り中、`FUN_00307da8(1, 0)` が閉じる。窓 +0x399 の文字の速さを 0 にして呼ぶと一度に出る (店の `0x1D6B6C` と同じ) | 推定 |
| 文 | メッセージ `FUN_00310438(*0x5742D0, ID, 種別)` は種別 −1 = 本文、1 = 読み (`_IN`)。SystemCommon 0x17D9 はフォントのテスト (98 文字) で読みが空。読み込まれた本文を実行時に書き換え、自由な文を出す | 推定 |
| 窓の大きさ | 地の文の窓は 1 ページ 2 行 (ゲームの文は 1〜2 行のページがほぼ全部)。3 行目を書くと改ページになり、Azahar では崩れて見えた (2026-11-02 ユーザー確認)。▶ はフォントになく ? になる。→ と ・ は文で使われている | 確定 (3 行で崩れる) / 推定 (2 行) |
| 店 | 店はモード 7 (`FUN_00174cb8` の 7 → `FUN_0017e63c` → `FUN_00435a40`)。`FUN_00308d08(*0x574148, モード, 引数)` が次のモードを頼む。店は引数 (`*0x574148` +0xC) を店番号にし、18 以上を 0 にする (0x1D4C44)。Shop の表は 18 行で、範囲外は `FUN_0031cfb8` が行 0 を返すので、店 18 は店 0 の店員になる。ShopItem は先頭の位置と数だけを持ち、品数の上限は見当たらない。買値は `FUN_002ea5b0(_, ID)` (itemData +0x00)。店を出るとモード 4 (フィールドへ、記録した地点から) か 2 に移る | 推定 |
| アイテム | 入手 `FUN_0031140c(*0x564638 + 0x4A0, ID, 数, 0)`、所持数 `FUN_002edb9c(ID, &u8, 1)`、行 `FUN_002edc14(ID)`、行数 `[[*0x520448] + 0x138]` | 確定 (読み取り) |
| ワープ | ジャンプの決定 `FUN_00265e28` と同じ: セーブ +0x406 の bit0 を立て、`FUN_00308d44(*0x564638 + 0x404, 行 +8 bit0 ? 0x09A1DA1B (W02) : 0xA8654391 (W01), 行 +4 の入口)` で行き先を記録し、`FUN_00308d08(*0x574148, 4, 0)` でフィールドへ (`0x1B5E54` などと同じ並び)。行は `FUN_0031cfb8([0x520448] + 0x6AC, 行)`、行数は `[[[0x520448] + 0x6B0]]`、名前は行 +0 のメッセージ | 推定 |
| セーブ変数 | 読み `FUN_00304adc(セーブ, key, 位置, &out)`、書き `FUN_00305b7c(セーブ, key, 位置, &値)` (`*0x564638`) | 確定 (読み取り) |

## コードの置き場所

code cave (0x4BF020〜0x4BFF80、約 3.9 KB) はボス戦 2500 B・変身 1028 B・告知 1084 B を合わせるともう足りない。デバッグモードは .rodata の中の、使われていない mapData キーの配列の複製 5 個 (0x4D7180〜0x4D8184、0x334 B ずつ連続、4100 B) に置く (Panana のパッチの `@emu` ブロック、`KAHARA_EMU_AREA`)。読み取り専用のページなので、実機では実行できない (XN)。Azahar は実行権限を見ない見込み。

- 選んだ理由: 複製はそれぞれ静的初期化子 (0x476B60、0x478950、0x4790CC、0x47BE64、0x47C5E0 のリテラル) からしか参照されず、その初期化子はマップの行の複製 (.bss) に写すだけで、写し先はほかから参照されない (2026-11-02 に 7 個を走査)。新しいマップ ([new-map.md](new-map.md) §2) が使う 24 個 (`SPILL`) とは別。
- 0x4D6E4C は写し先の近くに別の参照 (0x374974) があり、0x4D8184 の中の 0x4D8374 を 0x4F03AC が指す値があるので、その前後は避けて 5 個にした。
- 最初は .rodata の末尾 (0x510484〜0x511000) に置いたが、そこは新しいマップの表 (`PNMP`、0x510490〜) が使うので重なった。

参照のない関数を空きとして使う案は、RVCT の `.init_array` が相対オフセットで静的初期化子を指すため、参照の走査では使用中の関数を「参照なし」と誤る (例: 0x461764〜)。
