## メッセージエディタの表現 (旧 panana#11 の記録)
panana のエディタは、種別コードを別の欄に分け、本文を `{ruby:親字|よみ}`、`{page}`、`{msg:XXXX}`、`{tag:XXXX}`、`{XXXX}` (その他) で表す。プレビューはルビを `<ruby>` で振り、声・感情・文字色を隠し、名前・数値を〈電波人間〉などのプレースホルダに、差し込みと決まった名前を参照先の本文に、Ē を灰色の ● にする。

### レアリティ
item+0x08 のフラグ bit5〜7 = ☆1〜7。

### code.ips: アイテム効果種別 4「全回復」
| アドレス | 変更 |
|---|---|
| 0x2F4248 | 効果計算 `FUN_002f41ac`: → cave `calc` (種別 3/4 は HP≤0 で復活フラグ bit31、種別5 は無し) |
| 0x310028 | 適用 `FUN_0030ffb8` (アイテム): 種別≠3 → cave `apply` (種別4: `FUN_002d8404(unit)` / 種別5: セーブレコード +0x5A の origin を 1/2 に書換え) |
| 0x318440 | 効果有無判定 `FUN_00318380`: 種別≠3 → cave `effective` (種別4: 死亡/HP<最大/AP<最大 なら有効、種別5: ユニット +0x2C == 3 なら有効) |
| 0x2F63AC | フィールド結果メッセージ `FUN_002f5324`: `bne`→`bcc` (種別≥3 で w3/w4 メッセージ表示) |
| 0x28863C | 戦闘のユニット別コマンドスロット設定 `FUN_00288634` (スロット4 = アイテム): アクション ≥0x2A0 (672) を 0 に潰す → `cmp #0x800`。これが無いと追加アイテムは戦闘で「なしは使っても効果がないので…」になる |
| 0x2F4C54 | アクション→アイテムID `FUN_002f4c54` (効果なしメッセージの名前 / 使用後の消費): 0xB2〜0xE6 のみ → cave 0x4BF080 で ≥672 (MOD 追加行) も許可 |
`FUN_002d8404(unit)`: 1 人分の全回復 (AP=最大, HP=最大=復活, 状態異常 0x5E 種すべて解除)。回復の泉/自宅ベッド/つんつん師のパーティループ `FUN_00304884` と戦闘終了処理 `FUN_0040e4fc` が使用。フィールドのメッセージは 0x1BE2「パーティのHP、APが全回復した！…」。
| 0x24E3F0 / 0x24E360 | 戦闘の全体回復演出 `FUN_0024dff4` (エフェクト 0x12) はメッセージ 0x1800/0x1802 (HP) 固定 → MOD アクション (≥672) は行の w3/w4 を使う (全体 AP 回復で「HPが回復」と出ていた) |
アクション行の +0x00 bit31 = フィールドで使用可 (mode 4)、bit29 = 戦闘で使用可 (mode 5)、bit30 = mode 7 (`FUN_0030f8e0`)。
cave は .text 末尾のゼロ領域 0x4BF01C〜0x4BFFFF (RX マップ内)。
ユニット構造体: +0x5C HP, +0x5E 直前HP, +0x60 最大HP, +0x6A AP, +0x6C 直前AP, +0x6E 最大AP。
結果レコード: +0x00 量, +0x14 フラグ (bit9-10 カテゴリ, bit11-14 効果種別, bit19 効果なし, bit30 常時, bit31 復活)。

## デバッグ: 全電波人間の固定化 (`deploy.ps1 -DebugItems`)
- `build_items.py --debug` / `build_code.py --debug` でのみ有効。通常ビルドの出力は変わらない。
- アイテム ID 176「こていかデバッグ」(空き行、カテゴリ 0x11 はどくなおしからコピー、テレポーターを売る全ショップで 1G)、アクション #677、効果種別 6 (味方全体、対象選択なし)。
- cave `fixall(write)`: 店舗モード byte (0x562F90) を一時的に 0 にして `FUN_00311748(0..0xBB)` の全レコードを走査。レベル (+0x34) 0 は空きスロット。さよならで消える条件 (origin 3、または origin∉{1,2} かつ +0x3E==0) の個体の origin を 1/2 に書き換え、パーティ (idx<8) はランタイム +0x2C も更新。
  - calc (`FUN_002f41ac`) では数えるだけ (結果の量 = 対象数)。他の呼び出し元 (0x286xxx/0x287xxx) があるため副作用は apply 側のみ。
  - effective: 対象が 1 体以上なら使用可 (0 なら「効果がない」で消費されない)。
- ハウスのユニット (idx≥8) はランタイムがキャッシュされるため、使用後はセーブしてゲームを再起動するのが確実。
- 精霊のほこら (さよなら記録は先頭 0x42 バイトのみ、呼び戻しはシードから作り直し): [shrine.md](../../kahara/shrine.md)

## セーブ直接編集: `tools/save_origin.py`
ヘッダの (offset, 0x8A80) の最初の組がユニットブロック (0xA040)。2 番目 (0x27AB8) は更新されない古い写し。チェックサムなし。

## 回復の泉: 水を汲む (code.ips)
- 泉の処理は `FUN_001f0dd8`。
  - オブジェクト +0x254 が使用済みフラグで、立っていれば 0x1BE1「回復の効果が失われている…」を出す。
  - 立っていなければ `FUN_0030873c(0x1BE0)`「回復しますか？」→ はいで全回復 (`FUN_003008dc`) し、+0x254 = 1、0x1BE2 を出す。
- はい/いいえ ダイアログ: `FUN_0030873c` → `FUN_00303f7c(種別)` → `FUN_002e42e4` (クラス vtable 0x4FBE78、種別 +0x364)。
  - ボタンはレイアウトのペインを種別ごとの表 (0x5E5ADC 左 / 0x5E5ABC 右) から選ぶ: Yes/No, Ok, oku。
  - **最大 2 ボタン**なので、3 択はレイアウトから作る必要がある。
- 0x1F0E8C (「いいえ」の分岐) → cave `spring`:
  1. 所持数を確認する (`FUN_002eda90(*(0x564638)+0x4A0, &id, 0, 0)`、1 = 空きなし)。
     `FUN_0031140c` は残り容量で個数を切り詰めるので、上限のときに足すと消える。
     - 満杯: 0x2CF1「いずみのせいすいは これ以上持てない。」を出して終わる。泉は使用済みにならない。
  2. 空きがあれば 0x2CF0「水を汲みますか？…」を聞く。
     - はい: `FUN_0031140c(inv, 36, 1, 0)` でアイテムを 1 つ足し、+0x254 = 1、0x29F2「Ćを手に入れた！」(r1 = アイテム ID) を出す。
     - 回復と水汲みは、どちらか一方しかできない。
- 0x2CF0/0x2CF1 は `build_items.py` の CODE_TEXTS (固定 ID。アイテム数によらず 0x2CF0 から)。

### テレポーター+ (アイテム 178、アクション #676 = 行 207 の複製)
- 0x2C6600 / 0x25DE4C / 0x266B14 の `cmp r0,#0x1c` → cave `tpcmp`。0x1C と 178 のどちらでも Z が立つ。
- 0x2C66FC `cmpne r0,#0` → `blne tpok`。178 のときは記録枠 (0〜12) も必要。枠がなければテレポーターが使えない場所と同じ扱いになる (0x17DC、消費しない)。
- 0x2C6764 `mov r1,#0x1300000` → `bl tprec`。178 のときは脱出イベントの前にワープ記録を書く。
  - 位置: ここでは (0, 0, 0) を仮に書く。アイテムメニューを開いている間は、キャラの `+0x10 → +0x14` が 0 を返すため (最初の実装ではこの 0 がそのまま記録され、再開時に原点の何もない空間に出た)。
  - 0x353480 (脱出イベント `FUN_00353480` の先頭) → cave `tpesc`: 現在のダンジョンの記録が「フラグあり・マップ一致・位置 (0,0,0)」なら、先頭キャラ `FUN_00303db0(0)` の `+0x10 → +0x14` (直後の `FUN_001c3dc4` がワープ演出に使うのと同じ位置) で書き直す。
  - 階: マップ表の +4
  - D02 と D03 は、バニラと同じく逆側の記録を消す。
- セーブ上の配置: 変数はビット単位で詰めて格納される (32bit 境界にそろえない)。v1.1.0 の実セーブでは、var 0x61 の枠 7 (D08) が 0x2FA1 の bit 6 から始まり、0x62 がその直後に続く (マップハッシュをビット単位で検索して確認)。
- 見た目のワープホールは作らない。記録だけを書く。記録はダンジョンごとに 1 つで、既存のワープホールの記録と共有 (上書き) する。
