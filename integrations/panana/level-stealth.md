# レベルステルス (RPG2 へ RPG3 の挙動を移す)

> 対象: 電波人間のRPG2 (`kahara`) v1.1.0、参考に電波人間のRPG3 (`oahu`) Update v4096。分類: Panana の拡張 (コードの MOD) と、その根拠になったゲーム既存仕様。
> 根拠: Ghidra の逆コンパイル (kahara は elpulse `re/all.c`、oahu は Update の code.bin を同じ設定で解析したもの) と、Panana の ROM テスト (パッチの組み立てと code.ips の適用)。エミュレーター・実機での動作確認はまだ。
> アドレスは実行時アドレス (code.bin の位置 = アドレス − `0x100000`)。

パーティーの平均 Lv がフィールドのモンスター (シンボルの敵) の Lv を大きく上回ると、そのモンスターはパーティーに気づかず、追ってこない。RPG3 にはこの挙動があり、RPG2 にはない。Panana は RPG2 の書き出しに、これを足すコードの MOD「レベルステルス」を持つ。

## 1. シンボルの敵がパーティーに気づく判定 (RPG2)

- シンボルの敵 (0x88 バイト) は `FUN_002d6628` が `FUN_001c4d88` で作る。
  - +0x00 キャラ (モデル)、+0x0C エンカウントの枠の番号 ([encounters.md](../../kahara/encounters.md) §1 の 3)、+0x18〜 AI。
  - AI は `FUN_001ef6d0` で初期化し、`FUN_001ee5e0` で MonsterDesign の行 (+0x08 / +0x0C のビット) から距離・角度などを読む。
- AI の状態 (+0x01) は `FUN_001eee7c` が進める。状態 1 (待機) と 3 (歩く) のとき、`FUN_001eeaf0` が「気づいたか」を調べる。
  1. 最初に `FUN_00435380(global + 0xB28)` (パーティー) を呼び、1 なら何もしないで返る。これは状態 0x5D (ステルス) がパーティーかメンバーにかかっているかの判定。
  2. 距離 (+0x48)・角度 (+0x4C)・壁へのレイ (`FUN_003321f4`) を調べる。
  3. 気づくと、モーション 0x66 を出し、状態を 2 (気づいた) にする。そのあと追う・突進する・逃げるなどに進む。
- モンスターの Lv: `FUN_002d6998(global + 0x54, 枠)` が、戦闘と同じ引き方で枠から MonsterParameter の行を引く。引いた行は master +0x95C に残る。Lv は w0 bit8-14 ([battle.md](../../kahara/battle.md) §2)。
- メンバーの Lv: 数は `FUN_00435380` と同じ (パーティー +0、+1 が 0 でなければ `FUN_00309960`)。i 番目は `FUN_0031d5b8(global + 0xBA8, i)` で、その +0x0C が Lv (0 は空き)。

## 2. RPG3 の挙動

- `FUN_00227030` (RPG2 の `FUN_001c4d88` に当たる) が、モンスターを出すときに「モンスターの Lv − パーティーの Lv < −9」で、かつ MonsterDesign +0x08 bit19 が 0 なら、AI +0x50 の bit3 を立てる。
- `FUN_00268188` (RPG2 の `FUN_001eeaf0` に当たる) は、ステルスの判定のすぐあとで AI +0x50 の bit3 を見て、立っていれば返る。
- したがって、差は **10 以上**。判定はモンスターが出たときに 1 回だけ行う。
- RPG3 では、フィールドのキャラに Lv の表示 (キャラ +0xA8、`FUN_002fa628` がモンスターの Lv とパーティーの Lv を渡す) もある。RPG2 のキャラにはこの表示がない。

## 3. Panana のパッチ (コードの MOD「レベルステルス」)

- `0x1EEB30` (`FUN_001eeaf0` の `bl FUN_00435380`) を、code cave の関数への `bl` に置き換える。
- その関数は、まず `FUN_00435380` を呼ぶ (ステルスはゲームのまま効く)。0 なら、モンスターの Lv と、メンバーの Lv の合計・数を求め、「合計 ≧ (モンスターの Lv + 差) × 数」なら 1 を返す。これは「平均 Lv (切り捨て) ≧ モンスターの Lv + 差」と同じ。
- 差は書き出しの画面で 1〜99 から選ぶ。既定は RPG3 と同じ 10。
- RPG3 との違い:
  - 判定は気づくたびに行う。戦闘やレベルアップで Lv が変わると、その場のモンスターにもすぐ効く。
  - RPG2 の MonsterDesign には RPG3 の +0x08 bit19 (対象外) に当たるビットがないので、すべてのシンボルの敵が対象になる。
  - すでに追ってきているモンスターは、そのまま追う。ぶつかれば戦闘になる。
- 元の語 (`0x1EEB30` が `EB091A12`) と違う code.bin (別の版、または土台の MOD が同じ場所を書き換えたもの) には入れない。

## 4. モンスターの頭上の Lv 表示 (調査中、未実装)

RPG3 はフィールドのキャラの頭上に Lv を出すが、RPG2 には同じ仕組みがない。RPG2 に足すための部品と、まだ確かめていないこと。

- RPG3 の仕組み:
  - キャラ +0xA8 のラベル (`FUN_002fa834` が 10 枠のプール (`FUN_004d0854`、場面 0xC の +0x46C、0x24 バイト × 10) から取る)。
  - 出現時に `FUN_002fa628` が、メッセージ 0x13881 にモンスターの Lv を入れて描き (`FUN_0023731c`)、パーティーの Lv も渡す。
  - 毎フレーム `FUN_00369220` が (ラベル, 頭上のワールド座標) を並べ、`FUN_001af1cc` がカメラ 0 (カメラ管理 + 4 + 0x6F0 × i) のビュー行列 (+0x80、3×4) と射影行列 (+0x40、4×4) で画面に写し、(200 + x × 200, 120 − y × 120) にペインを動かす (`FUN_00237254`)。画面の外ならラベルを隠す。
- RPG2 で使えそうな部品:
  - 上画面のレイアウト: フィールドで使う 400×240 のものは `50B5A9DF` entry 0 (darc) の `plant_info.bclyt` (枠 `Panel` と文字の位置 `Plant_Name` / `Plant_Time`) と `mask_d10` など。フィールドの地図・ボタン・名前 (`field_map`・`random_map` など) はすべて下画面 (320×240)。
  - 文字: ペインの位置に数字入りのメッセージを描く処理。階の数字 (`FUN_00237978`) と同じく、`FUN_002ecc34(レイアウト, ペイン名, …)` で文字の部品を作り、`FUN_002ecad8(部品 + 0x18, 部品 + 0x14 の書き手, メッセージ ID, 数, 0, 0, 0)` で描く。ペインの位置は +0x28 / +0x2C、表示は +0xB7 bit0、変えたらレイアウト +4 の +0x1CF に 4 を立てる。
  - カメラ: RPG3 と同じ形のカメラ管理 (`FUN_00107288`、`*0x5744E0`、0x6F0 バイト × 16)。カメラの位置は +0x20、注視点は +0x2C、上は +0x38 (`FUN_0010bedc`)。RPG3 に合わせるなら、射影行列は +0x44、ビュー行列は +0x84 (未確認)。
  - モンスターの一覧: 出現の管理 (`FUN_0021d190` の param_1) の +0x00〜 にモンスター、+0x80 に数 (u16)。モンスター +0 のキャラの +0x10 → +0x14 が位置。
- まだ確かめていないこと (エミュレーターでの確認が要る):
  - RPG2 のカメラの行列の位置。
  - 上画面にレイアウトを追加で読み込む方法 (`FUN_002fbe80` の記述子。`plant_info` を出す場面 `FUN_001d3610` が手本) と、毎フレームの更新を差し込む場所。
  - 「Lv %d」を描けるメッセージ (なければ Panana でメッセージを足す)。
