# ワールドマップの出現条件と「〇〇が出現した！」の告知

> 対象: 電波人間のRPG2 (`kahara`) v1.1.0。分類: Panana 実装記録・追加 code.ips 仕様 (最新状態の保証ではない)。
> 根拠: [kahara/worldmap.md](../../kahara/worldmap.md) §6.1〜§6.3 (2026-10 に ROM で確認した関数と実データ)。
> アドレスは実行時/Ghidra アドレス。**告知のパッチはゲーム既存仕様ではなく、Panana が書き出す code.ips に入れたときだけ動く。** 実機・エミュレーターでの確認はまだ。

## 1. 出現条件の編集 (データだけ)

ワールドマップのページ (`#/world/W01.入口`) の入口ごとに、+0x10 が指す W01_EventObject の行の条件を編集する。

- 「出る」= +0x4B と値 +0x00、「消える」= +0x4C と値 +0x04。種類は ROM の `FUN_0030b8a4` を実行器で読んだ表 (Panana `src/game/conditions.ts`) から選ぶ。ストーリーの進行 (0x8D[n] ≥ 値) を先頭に並べる。
- +0x10 = 0 (いつも出る) の入口には「出現条件をつける」で行を足す。足す行は **種類 0x11** (ふつうの入口。0 や 0x24 では入れない入口になる、[worldmap.md](../../kahara/worldmap.md) §6.1)、状態の枠は空いているもの。W01 で足せるのは行 29〜38 の 10 行。
- 行をほかの入口や区画 6 と共有しているときは警告し、「この入口だけの行にする」で条件を写した種類 0x11 の行に切り離せる。
- 行の種類が 0x11 でも 0x24 でもないときは「入れない入口になる」と警告する。0x24 の行 (動く島など) は動きが行番号で決まるので、条件だけを変える。
- Panana の実装: `src/game/worldconditions.ts`、ページは `src/pages/world.tsx` (`EntranceCondition`)、条件の選択は `src/ui/ConditionPicker.tsx`。

### 1.1 入口を足す

- 「入口を追加」: 2D の地図の真ん中のセルに、選んでいる入口の写し (種類・モデル・行き先) を新しい ID (ほかと重ならない u32) で置く。+0x10 (出現条件の行) と +0x14 (区画 3 の地点) は 0。足した入口は「この入口を消す」で消せる (ゲームの入口は消さない)。
- 入口の配列は 176 件まで ([worldmap.md](../../kahara/worldmap.md) §6.1)。W01 は 54 件なので 100 件以上足せる。
- モデル (+0x18) は mapObject の行を写真から選ぶ (`src/ui/ObjectPicker.tsx`)。ほかの入口が使っているモデルを先頭に出す。MapAppearWorldmap に載っていない行でも置かれる (距離は既定の 100)。
- 新しいダンジョンの入口なら、行き先・行き先の地点を新しいマップのものにし、行き先の地点から出るとこの入口に戻るようにする (ページの「この入口に戻るようにする」)。

## 2. 告知のパッチ (Panana の code.ips)

MOD で足した入口が出たときに、ワールドマップに入ったところで一度だけ「[地名]が出現した！」と出す。MOD を入れてから初めて W01 に入ったときに条件が既に成り立っていれば、そのときに出る。

### 2.1 データ

- 告知つきの行 = W01_EventObject の行で、**+0x40 (u32) にメッセージ ID** があるもの (Panana の取り決め。種類 0x11 の行はこの欄を使わない前提、未確認)。Panana は自分で足した行 (元の表にない行) にだけつけさせる。ゲームの行の状態はストーリーやトリガーが使うため。
- メッセージは新しく足す。種類は 0x1BF6「[黄泉の門]が開いた！」を写し、本文は `{msg:地名}が出現した！`。地名は行き先のマップのダンジョンの mapGroup +0x14。メッセージのページで書き換えられる。
- 出現の音は行 +0x3C (u32、soundData の行、0 = 鳴らさない、Panana の取り決め。種類 0x11 の行は +0x08〜+0x43 を使わない)。+0x44 は行の状態の枠 (u16) なので置けない。以前は +0x44 に書いていて、状態の枠が表の外 (0x2F = 47 など) や他の行の枠を指し、告知が一度も出なかった。Panana は読み込みと書き出しのときに、足した行で枠が表の外か重なっていて +0x3C が 0 のものを直す (音を +0x3C に移し、空いた枠を割り当てる。+0x46 は 0)。告知をつけると 0x2F (ME_GIMMICK) になり、入口のページで選べる。
- 告知済みの記録は、その行の状態 (セーブ 0x8E の枠) を 1 にする。

### 2.2 パッチ (`src/game/worldnotice.ts`)

| 場所 | 元の命令 | 変更 |
|---|---|---|
| 0x19ABA0 (`FUN_0019aa88` の W01 の分岐。pop のあと) | `b 0x17e08c` | `b wn_hook` (cave) |

- 告知は黄泉の門と同じく**ワープでマップを読み込み直して**見せる。地形はマップを読み込むときに作られ (`FUN_001e1fc4` → `FUN_002e657c` → `FUN_00204160`)、パーティやカメラを遠くへ動かしても追いつかない (Azahar で確認)。
- 途中の状態は `0x63FF00` の 32 B に置く: +0 目印 `PNWN` (0x4E574E50)、+4 段階 (1 = 入口の隣へワープした、2 = 元の場所へワープした)、+8 行、+0xC 元の位置 (0x58、float 3)、+0x18 元の角度 (0x59)。ここは .bss (0x5E5D3C〜0x63F4B4) の最後のページの余りで、code.bin から指す値は crt0 の境界 0x63F4B4 だけ。起動時の 0 埋めの外なので目印で確かめる。行の状態 0x8E は 1 枠 2 ビットで座標は入らない。
- `wn_hook`: `FUN_0017e08c` を呼び (r0 = ハンドラ、r1 = 4 のまま)、0 でなければそれを返す (ゲームの演出が先)。0 なら、段階 1 なら告知の動作を作る。段階 2 なら段階を 0 にして 0 を返す。それ以外は、乗り物に乗っていなければ (`FUN_00303c70() == 0`。セーブ変数 0x57 が 0 でないと 1。`FUN_002e592c` は船を持っていれば船を返すだけなので、乗っているかどうかには使えない) 出すべき告知があるときに作る。
- 告知の動作: 確保 0x10、`FUN_0031b170(obj, 0x1000000)`、vtable は 0x4FB8C8 と同じ形で [2] だけ差し替える (`{0, 0x1C0884, wn_run, 0x1B0FC8, 0x31713C, 0x43C2CC, 0, 0}`)。
- 出すべき = `FUN_0031bff4(0x34, 行) == 0`、かつ行の条件で置かれる (+0x4C が成り立たず、+0x4B が成り立つ。`FUN_001e2ac4` と同じ判定)。
- `wn_run` ([2]、キューのコルーチンの中):
  1. 1 回目 (段階 0): 表の最初の出すべき行を選ぶ。行、元の位置 (`FUN_003039fc(&buf)` で 0x58)、角度 (`FUN_00430e20(セーブ)` の s0 で 0x59) を覚えて段階 1 にする。黒へ 0.5 秒でフェードアウトし (`FUN_003174e8(0, 0, 0, 2)`、`FUN_00300dbc`)、`FUN_00308d44(セーブ, W01 = A8654391, 入口の ID)` → `FUN_003014f0(4, 0)` → `FUN_00308bac(0, 0)` (s0 = *0x4D07CC = 0.3) で入口の隣へワープする。この手順は黄泉の門の `FUN_00226064` と同じ。セーブは *0x564638 + 0x404。入口の ID が 0x51 と一致するので、W01 は入口の隣から読み込まれる。
  2. 2 回目 (段階 1、入口の隣): `wn_show` で見せてから `FUN_003048f8(0x34, 行, 1)`。黒へフェードアウトし、`FUN_001db864` と同じ手順で戻す (ただし `FUN_001db864` が先に呼ぶ `FUN_003008dc` はパーティの回復 (`FUN_00304884`) なので呼ばない): `FUN_003012dc(セーブ, &元の位置)` で 0x58、`FUN_003012b0(セーブ)` (s0 = 角度) で 0x59、`FUN_00300678(0)`、`FUN_00308d44(セーブ, W01, 0)` (地点 0)。そのあと段階 2 にして切り替える。地点 0 では `FUN_004326a8` がパーティを 0x58 / 0x59 に置く。
  3. 3 回目 (段階 2、元の場所): フックが段階を 0 にするだけ。ほかに出すべき告知があれば、次にマップに入ったときに出す。
- `wn_show`:
  1. すぐ黒にする (`FUN_003174c8(2, 0)`)。
  2. 入口のオブジェクト (`FUN_0031c970(行)`) があれば、カメラの制御を取り (`FUN_0031b1b4(cam, 0, 1)` → `FUN_003179b8`)、`FUN_00317210(cam, &(入口 + (0, 1187.5, 1300)), &(入口 + (0, 50, 0)), 3)` (s0 = 0) で入口へすぐ向ける。
  3. 0.5 秒待ってから、1 秒でフェードインする。
  4. `FUN_00300854` → 出現の音 `FUN_00317524(音)` (0 なら鳴らさない) → `FUN_0030cc48(メッセージ, 0, 0, 0)` (s0 = 0.2) → `FUN_003007c0`。
  5. 最後に `FUN_00301888` → `FUN_00301764` でカメラを戻す。
- 経緯:
  - 最初はカメラだけを入口へ向けたが、離れた場所の地形が読み込まれなかった。
  - 次に、パーティを入口の南へ移してからカメラを向けた。それでも離れていると地形が出なかった。
  - 最後に、ワープして読み込み直す今の方式にした。
- 出現の音: `FUN_00317524(n)` の n は soundData の行 (`FUN_00132ecc` が `FUN_00187450` で soundData の行 n の +0 に変える)。Panana の行番号と同じ。0x2F = ME_GIMMICK (黄泉の門の「開いた！」)、0xC4 = SE_BTL_LIGHT_S1 (妖精の里で門が開く)、0xB1 = SE_BTL_WATER_A3 (動く島が出る)、0x58 = SE_FLD_STAIRS、0x5C = SE_FLD_DOOR、0x70 = SE_FLD_SWITCH2。
- 表: 1 件 8 語 `{行, +0x4B, +0x00, +0x4C, +0x04, メッセージ, 音, 入口の ID}`、行 0 で終わり。書き出しのときに W01 の表と区画 2 (+0x10 がその行の入口) から作る。入口がない行は入れない。
- 書き出し: W01 の表に告知つきの行があるときだけ、書き出しの code.ips に入れる (ボス戦のパッチと同じ扱い)。

### 2.3 確かめたこと・残り

- Panana のテスト (`test/worldnotice.test.ts`): 実行器で、ゲームの演出が先に返ること、条件と状態で出す・出さないが決まること、入口の隣へワープ → カメラ → メッセージ → 状態 1 → 元の座標へワープ → 段階を戻す、の 3 回の読み込み。乗り物の上では出さない。目印のない状態は無視する。オブジェクトがないときはメッセージだけ。ROM があれば、0x19ABA0 が `b 0x17e08c` であることと、パッチを当てた code.bin でも同じに動くこと。
- 未確認: エミュレーター・実機での表示、+0x40 を種類 0x11 の動作が読まないこと、戦闘のあとに告知の判定がもう一度走るか (走っても状態で二度は出ない)。
- 未確認: 地点 0 のワープで 0x58 の座標に出ること (`FUN_001db864` と同じ手順、推定・強)。0x63FF00 がほかの用途 (OS やライブラリ) に使われないこと。
