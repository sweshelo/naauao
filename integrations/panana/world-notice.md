# ワールドマップの出現条件と「〇〇が出現した！」の告知

> 対象: 電波人間のRPG2 (`kahara`) v1.1.0。分類: Panana 実装記録・追加 code.ips 仕様 (最新状態の保証ではない)。
> 根拠: [kahara/worldmap.md](../../kahara/worldmap.md) §6.1〜§6.3 (2026-10 に ROM で確認した関数と実データ)。
> アドレスは実行時/Ghidra アドレス。**告知のパッチはゲーム既存仕様ではなく、Panana が書き出す code.ips に入れたときだけ動く。** 実機・エミュレーターでの確認はまだ。

## 1. 出現条件の編集 (データだけ)

ワールドマップのページ (`#/world/W01.入口`) の入口ごとに、+0x10 が指す W01_EventObject の行の条件を編集する。

- 「出る」= +0x4B と値 +0x00、「消える」= +0x4C と値 +0x04。種類は ROM の `FUN_0030b8a4` を実行器で読んだ表 (Panana `src/game/conditions.ts`) から選ぶ。ストーリーの進行 (0x8D[n] ≥ 値) を先頭に並べる。
- +0x10 = 0 (いつも出る) の入口には「出現条件をつける」で行を足す。足す行は **種類 0x11** (ふつうの入口。0 や 0x24 では入れない入口になる、[worldmap.md](../../kahara/worldmap.md) §6.1)、状態の枠は空いているもの。W01 で足せるのは行 29〜38 の 10 行。
- 行をほかの入口や区画 6 と共有しているときは警告し、「この入口だけの行にする」で条件を写した種類 0x11 の行に切り離せる。
- 行の種類が 0x11 でも 0x24 でもないときは「入れない入口になる」と警告する。0x24 の行 (動く島など) は動きが行番号で決まるので、条件だけを変える。
- Panana の実装: `src/game/worldconditions.ts`、ページは `src/pages/world.tsx` (`EntranceCondition`)、条件の選択は `src/ui/ConditionPicker.tsx`。

### 1.1 入口を足す

- 「入口を追加」: 2D の地図の真ん中のセルに、選んでいる入口の写し (種類・モデル・行き先) を新しい ID (ほかと重ならない u32) で置く。+0x10 (出現条件の行) と +0x14 (区画 3 の地点) は 0。足した入口は「この入口を消す」で消せる (ゲームの入口は消さない)。
- 入口の配列は 176 件まで ([worldmap.md](../../kahara/worldmap.md) §6.1)。W01 は 54 件なので 100 件以上足せる。
- モデル (+0x18) は mapObject の行を写真から選ぶ (`src/ui/ObjectPicker.tsx`)。ほかの入口が使っているモデルを先頭に出す。MapAppearWorldmap に載っていない行でも置かれる (距離は既定の 100)。
- 新しいダンジョンの入口なら、行き先・行き先の地点を新しいマップのものにし、行き先の地点から出るとこの入口に戻るようにする (ページの「この入口に戻るようにする」)。

## 2. 告知のパッチ (Panana の code.ips)

MOD で足した入口が出たときに、ワールドマップに入ったところで一度だけ「[地名]が出現した！」と出す。MOD を入れてから初めて W01 に入ったときに条件が既に成り立っていれば、そのときに出る。

### 2.1 データ

- 告知つきの行 = W01_EventObject の行で、**+0x40 (u32) にメッセージ ID** があるもの (Panana の取り決め。種類 0x11 の行はこの欄を使わない前提、未確認)。Panana は自分で足した行 (元の表にない行) にだけつけさせる。ゲームの行の状態はストーリーやトリガーが使うため。
- メッセージは新しく足す。種類は 0x1BF6「[黄泉の門]が開いた！」を写し、本文は `{msg:地名}が出現した！`。地名は行き先のマップのダンジョンの mapGroup +0x14。メッセージのページで書き換えられる。
- 出現の音は行 +0x44 (u32、soundData の行、0 = 鳴らさない、Panana の取り決め)。告知をつけると 0x2F (ME_GIMMICK) になり、入口のページで選べる。
- 告知済みの記録は、その行の状態 (セーブ 0x8E の枠) を 1 にする。

### 2.2 パッチ (`src/game/worldnotice.ts`)

| 場所 | 元の命令 | 変更 |
|---|---|---|
| 0x19ABA0 (`FUN_0019aa88` の W01 の分岐。pop のあと) | `b 0x17e08c` | `b wn_hook` (cave) |

- `wn_hook`: `FUN_0017e08c` を呼び (r0 = ハンドラ、r1 = 4 のまま)、0 でなければそれを返す (ゲームの演出が先)。0 なら告知の表を見て、出すべきものがあれば告知の動作を作って返す。なければ 0。
- 告知の動作: 確保 0x10、`FUN_0031b170(obj, 0x1000000)`、vtable は 0x4FB8C8 と同じ形で [2] だけ差し替える (`{0, 0x1C0884, wn_run, 0x1B0FC8, 0x31713C, 0x43C2CC, 0, 0}`)。
- 出すべき = `FUN_0031bff4(0x34, 行) == 0`、かつ行の条件で置かれる (+0x4C が成り立たず、+0x4B が成り立つ。`FUN_001e2ac4` と同じ判定)。
- `wn_run` ([2]、キューのコルーチンの中): 表の順に、出すべきものごとに `wn_show` → `FUN_003048f8(0x34, 行, 1)`。
- `wn_show`: 入口のオブジェクト `FUN_0031c970(行)` があれば次の順に動く。
  1. 先頭 (`FUN_00319a6c`) か乗り物 (`FUN_002e592c`) の位置と向きを覚える (変換ノード T+0x14、向きは T+0x10 の bit3 で T+0x2C のオイラー角か T+0x38 の四元数)。
  2. 黒へ 1 秒でフェードアウト (`FUN_003174e8(0, 0, 0, 2)`、`FUN_00300dbc`)。カメラの制御を取る (`FUN_0031b1b4(cam, 0, 1)` → `FUN_003179b8`)。
  3. パーティを入口の 3 マス南 (高さはそのまま) に北向きで並べる: `FUN_0030150c(&位置, 3, 1, 1)`、s0 = 100 (黄泉の門の演出と同じ。仲間ごと動く)。乗り物なら `FUN_0031b408` と `FUN_00331ca8(p, {0, π, 0})` (動く島の演出 `FUN_002c4d98` と同じ)。
  4. カメラを入口へすぐ向ける: `FUN_00317210(cam, &(入口 + (0, 1187.5, 1300)), &(入口 + (0, 50, 0)), 3)`、s0 = 0 (視点と注視点をその場で書く)。
  5. 黒いまま 1 秒待って (パーティのまわりの地形が読み込まれる) 1 秒でフェードイン (`FUN_003086e4`、`FUN_0031745c(2, 1.0)`、`FUN_0031747c`)。
  6. `FUN_00300854` → 出現の音 `FUN_00317524(音)` (0 なら鳴らさない) → `FUN_0030cc48(メッセージ, 0, 0, 0)` (s0 = 0.2) → `FUN_003007c0`。
  7. またフェードアウトし、`FUN_0030150c(&元の位置, 3, 1, 0)` (乗り物は `FUN_0031b408`) と元の向き (`FUN_00331ca8(p, …)` か `FUN_0032e6bc(T, …)`) で戻し、`FUN_00301888` でカメラを追従に戻し、1 秒待ってフェードイン、`FUN_00301764` で後始末。
  - オブジェクトがなければ音とメッセージだけ。
  - 経緯: はじめはカメラだけを `FUN_00317210` で入口へ動かしたが、描画されていない場所の地形が読み込まれなかった。次にパーティだけを移したが、Azahar ではカメラが主人公を映したままだった (推定: 追従のカメラが追いつく前にフェードインした、または先頭だけが動いた)。いまはパーティを移したうえでカメラも入口に向ける。バニラの黄泉の門は入口の隣へワープして読み込み直すが、ワールドマップの地点は入口の ID でしか指定できず元の位置へ戻せない。
- 出現の音: `FUN_00317524(n)` の n は soundData の行 (`FUN_00132ecc` が `FUN_00187450` で soundData の行 n の +0 に変える)。Panana の行番号と同じ。0x2F = ME_GIMMICK (黄泉の門の「開いた！」)、0xC4 = SE_BTL_LIGHT_S1 (妖精の里で門が開く)、0xB1 = SE_BTL_WATER_A3 (動く島が出る)、0x58 = SE_FLD_STAIRS、0x5C = SE_FLD_DOOR、0x70 = SE_FLD_SWITCH2。
- 表: 1 件 7 語 `{行, +0x4B, +0x00, +0x4C, +0x04, メッセージ, 音}`、行 0 で終わり。書き出しのときに W01 の表から作る。
- 書き出し: W01 の表に告知つきの行があるときだけ、書き出しの code.ips に入れる (ボス戦のパッチと同じ扱い)。

### 2.3 確かめたこと・残り

- Panana のテスト (`test/worldnotice.test.ts`): 実行器で、ゲームの演出が先に返ること、条件と状態で出す・出さないが決まること、フェードアウト → 移す → フェードイン → メッセージ → 戻す → 状態 1 の順、移す先と戻す先、オブジェクトがないときはメッセージだけ。ROM があれば、0x19ABA0 が `b 0x17e08c` であることと、パッチを当てた code.bin でも同じに動くこと。
- 未確認: エミュレーター・実機での表示、+0x40 を種類 0x11 の動作が読まないこと、戦闘のあとに告知の判定がもう一度走るか (走っても状態で二度は出ない)。
- 未確認: 遠くへ移したとき、1 秒で地形とカメラが追いつくか。パーティの変換ノードが四元数モードかどうか。船に乗っているとき入口の南が陸でも問題ないか (戻すので残らない)。
