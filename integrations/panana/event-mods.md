# イベント拡張 MOD: 汎用スイッチ・ボス戦・演出

> 対象: 電波人間のRPG2 (`kahara`) v1.1.0。分類: Panana / elpulse の追加 code.ips 仕様。
> 根拠: [再編前の解析記録](https://github.com/sweshelo/naauao/blob/27cc7ec6682589c764906ada88e78f5d04d57cc2/events.md) と本文に記す関数・実データ。従来の「確定」は元の解析で確認した範囲を指し、今回の再編で ROM 全体を再検証した意味ではない。
> アドレスは特記なき限り実行時/Ghidra アドレス (code.bin の位置 = アドレス − `0x100000`)。RPG3 には適用しない。

**種類 0x30 / 0x31 と演出 (§9) はゲーム既存仕様ではなく、対応するパッチがあるときだけ使用できる。** ゲーム本来の種類・状態・戦闘処理は [kahara/events.md](../../kahara/events.md)。旧文書の節番号を保つ。

## 7. 汎用スイッチ (MOD、`mod/build_code.py`)

データだけで「スイッチを踏むと柵 (扉・門) が開く」を作るための code.ips の追加。アイテム MOD と同じ code.ips に入る。

- 種類 **0x30** の EventObject の行を、区画 5 の種類 2 (または 3 / 4 / 8) のレコードから参照する。
  - モデルは +0x46 (スイッチ: mapObject 27〜39 の gimk_12_switch_*。0x27 は特別扱いがあるので避ける)。
- 欄:

| 位置 | 内容 |
|---|---|
| +0x08 | 対象の行 1 (0 = なし) |
| +0x0C | 対象の行 2 (0 = なし) |
| +0x10 | 読み込み時に既に開いていたときの対象のアニメ (0 = 0x55。扉 gate_02 なら 0x52) |
| +0x11 | 開くときの対象のアニメ (0 = 0x53) |
| +0x12 | 開くときの効果音 (0 = 0x6F。扉なら 0x5C) |
| +0x44 | スイッチの状態の枠 (ほかと重ならないこと) |

- 動き:
  - 床スイッチ 0x1E のクラスで作る (踏むと押されたまま)。
  - 踏んだら自分の状態を 1 にし、対象ごとに D01 の門のスクリプト `FUN_00258e54` と同じ演出を行う (cave の `swshow`)。
    1. `FUN_0031aa2c(対象)`、ハンドルを作る
    2. カメラ: `FUN_0031b1b4(cam, 0, 1)` → `FUN_003179b8` → `FUN_00301f80`。対象の位置 + (0, 50, 0) を注視点、+ (0, 1187.5, 1300) を視点にして `FUN_00317210(cam, 視点, 注視点, 3)` (s0 = 1.5)、`FUN_00301d9c(cam)` で待つ
    3. 開くアニメ (s0 = 1.0, s1 = 0.0) + 効果音、`FUN_003086e4` (s0 = 1.0) で待つ
    4. `FUN_00300854` (s0 = 0.3)、効果音 0x2F、`FUN_00301a44(cam, 3, 0)` (s0 = 1.5) でカメラを戻し `FUN_00301d9c` で待つ、`FUN_003007c0` (s0 = 0.3)
    5. `FUN_00301888(cam)` → `FUN_00301764(cam)`、ハンドルを解放
  - 待ちは `FUN_002d7548` (床スイッチを踏んだときのコルーチン) の中なので使える。
  - 読み込み時は、押されていれば対象を開いた姿 (+0x10 のアニメ、s0 = 1.0 / s1 = 0.0) にして `FUN_0031aa2c` する (cave の `swopen`)。
  - 版 1 の最初の cave は s0 / s1 を渡さず、ハンドルもすぐ解放していたため、当たり判定だけ消えて見た目が残っていた。
- 対象: 同じマップにある、行番号 (`+0x5E`) を持つオブジェクト。区画 3 の扉・門 (種類 11 / 16 / 17 で +0x0C にイベントの行) を想定する。
  - おすすめは D01 の行 13 と同じ「区画 3 の種類 17 (gimk_03_gate_08)、イベントの種類 0x00」。
- 制限:
  - スイッチと対象は同じマップに置く (読み込み時の復元はスイッチ側で行うため)。
  - 対象は 2 つまで。開けるだけで、閉じない。
- フック: `FUN_001d1970` の `cmp r1, #0x1e` (0x1D1974) と、`FUN_002d7548` の最後の `strb fp, [r0, #0x80]` (0x2D7888)。
- cave に目印 `PNSW` + 版 (u32) を置く。マップエディタ (panana) はこれで汎用スイッチの有無を判定する。

## 8. ボス戦 (種類 0x31、Panana のパッチ。panana#43)

データだけで「範囲に入ると、ボスの台詞のあと決まった敵と戦う」を作るための code.ips の追加。Panana (`src/game/boss.ts`) が、種類 0x31 の行があるときに書き出しの code.ips に入れる。

ゲーム既存のボス戦・範囲処理は [kahara/events.md §8.1 / §8.2](../../kahara/events.md)。

### 8.3 種類 0x31 の欄

段階 n (0〜2) は、+0x4D / +0x4E / +0x4F の種類 0x31 と、引数 +0x08 / +0x1C / +0x30 からの 0x14 バイト ([kahara/events.md §8.2](../../kahara/events.md))。

| 引数の位置 | 型 | 内容 |
|---|---|---|
| +0 | u8 | monsterFixGroup の行 (1〜255。戦闘の枠が 1 バイトで持つ)。**0 = 戦闘なし** (メッセージ・演出だけのイベント。§9) |
| +1 | u8 | 戦闘の BGM (soundData の行、0 = 0x1C) |
| +2 | u8 | bit0 = 勝っても状態を進めない (入るたびに戦闘)。bit1 = 演出 (§9) |
| +4 / +8 / +0xC | u32 | 戦闘の前に出すメッセージ (0 = なし)。`FUN_00310798(ID, 0, 0, 0)`、s0 = 0.2 (スクリプトと同じ)。bit1 のときは +4 u16 = 演出の最初の行、+6 u16 = 行の数 (+8 / +0xC は使わない) |

- 置き方: 区画 8 のレコード `{行, x, y, 9, 2, 1, 1, 0 …}` (ゲームの戦闘の範囲と同じ +8〜+11)。
- 一度きり = 段階 1 つ。勝つと状態 1 になり、次は +0x4D の動作が選ばれる (+0x4E がないため) が、状態 > 段階なので何もしない。
- 何度でも = bit0 を立てる。暗闇のどうくつのような戦闘。
- 勝つたびに強くなる (ポーンのような) = 段階を 2〜3 つ。最後の段階の bit0 を立てると、最後の戦闘がくり返される。
- 出現条件 (+0x4B / +0x4C) はほかの行と同じく使える (ストーリーの進行で出す・消す)。

### 8.4 パッチ

| 場所 | 元の命令 | 変更 |
|---|---|---|
| 0x1F41DC (`FUN_001f41c8`) | `cmp r1, #0xb` | cave へ。種類 0x31 なら 0x1C バイトの動作 (基底 `FUN_0031b170`、+0x10 = 引数、+0x14 = 段階、+0x18 = 行の先頭) を作る。段階は引数の位置 (行 +0x08 / +0x1C / +0x30) から |
| 0x1CE320 (`FUN_001ce2e8`) | `and r4, r1, #0xff` | bit15 が立っていれば 0x91 の添字にしない (r4 = 0) |
| 0x1CE358 (`FUN_001ce2e8`) | `cmp r4, #0` (勝ったとき) | bit15 が立っていれば `FUN_003048f8(ダンジョン, 行, 状態)` |

- 動作の [2] (範囲に入ったとき): 状態 (`FUN_0031b10c`) が段階より大きければ何もしない。そうでなければメッセージを出し (bit1 なら演出を動かし、§9)、敵が 0 なら §9.3 の終わり方をする。そうでなければbit0 がなければ +0xA44 = `0x8000 | (段階 + 1) << 13 | 行` (行は 0x2000 未満) にして、`FUN_002fc790(組, BGM)`。
- [4] (完了) は何もしない (0x1B0FC8)。範囲に入っただけでは状態は進まない。
- 負けたとき・逃げたときは +0xA44 が 0 に戻るだけで、状態は進まない。
- Panana のテスト (`test/boss.test.ts`) で、実行器 (`src/game/arm.ts`) を使って作る動作・メッセージ・戦闘の引数・+0xA44・勝ったときの書き込みを確かめている。実機・エミュレーターでの確認はまだ。

## 9. 演出 (ボス戦の段階の bit1、Panana のパッチ)

ボス戦 (§8) の段階に「戦闘の前の演出」を付ける、または敵を 0 にして戦闘のないイベントにするための追加。ゲームのボス戦前のスクリプト ([kahara/cutscene.md](../../kahara/cutscene.md)) と同じ部品を、データの命令の列から呼ぶ。Panana (`src/game/cutscene.ts`、`src/game/boss.ts` の `BOSS_SCRIPT_PATCH`) が、演出のある段階があるときだけ書き出しの code.ips に入れる (約 2 KB。code cave は約 3.9 KB をほかのパッチと分け合う)。

### 9.1 データ

- 段階の引数 +2 の bit1 を立て、+4 (u16) = 最初の **演出の行**、+6 (u16) = 演出の行の数。
- 演出の行 = 同じダンジョンの EventObject の行で、どのマップからも置かれないもの。行は続けて並べる。
  - +0x00〜+0x3F: 命令 8 個 (8 バイトずつ)。命令 0 (終わり) か行の終わりで止まる。
  - +0x40 = `PNCS` (目印)、+0x44 = 持ち主の行の状態の枠 (自分の枠を使わない)、+0x4D〜+0x4F = 0。
- 実行時、演出の行の位置は「動作 +0x18 の行の先頭 + (演出の行 − 自分の行) × 0x50」で求める (EventObject の行は 0x50 バイトずつ並ぶ)。

命令 `{u8 種類, u8 arg, u16 役者, u16 p, u16 q}`。役者: 0 = なし、0xFFFF = 主人公 (先頭)、0xFFFE = パーティ、それ以外 = EventObject の行 (`FUN_0031c970` でこのマップのオブジェクト。なければその命令は何もしない)。座標 p / q は区画 4 / 5 / 8 と同じ細かい単位 (ワールド = 50 + 値 × 100)。時間は 0.1 秒単位。

| 種類 | 名前 | 動き (呼ぶ関数) |
|---|---|---|
| 1 | セリフ | 話者が主人公なら `FUN_0030cca4(h, arg または 0x1F, 1)` → `FUN_00310798(p, 0, 0, 0)` (ボタンで閉じる) → `FUN_0030cca4(h, q または 1, 1)`。ほかの役者は arg / q が 0 でなければそのアニメ。役者なしならメッセージだけ |
| 2 | 歩く | 行き先 (p, q)、高さは今のまま。主人公: 歩くアニメ (3、浮くキャラは 0x26) → `FUN_003080e4` (s0 = arg × 0.1、0 = 距離から) → `FUN_00308068` で待つ → 立ち 1。パーティ: 先頭からの差だけ全員を同時に動かし、それぞれ待って立ち姿に。行の役者はアニメなしで動かす |
| 3 | 向く | `FUN_00319a7c(h, 0, 0, 0)`、[sp] = 1、s0 = arg × π/2 (0 南 1 東 2 北 3 西)、s1 = p × 0.1 (0 = 0.3)。`FUN_00308068` で待つ |
| 4 | アニメ | `FUN_0030cca4(h, p, arg)`。パーティは `FUN_0030250c(p, arg, 0, 1)` |
| 5 | 待つ | `FUN_003086e4` (s0 = p × 0.1) |
| 6 | 効果音 | `FUN_00317524(p)` |
| 7 | マーク | 効果音 0x66、`FUN_0031bc08(h, 2, arg, 1, &(0, 180, 0))` (s0 = 0.7)、0.7 秒待って消す |
| 8 | カメラ | 最初の 1 回でカメラを作って制御を取る (`FUN_0031b1b4` / `FUN_003179b8` / `FUN_00301f80`)。役者 (なければ (p, q)) の位置 + (0, 50, 0) を注視点、+ (0, 1187.5, 1300) を視点に `FUN_00317210(cam, 視点, 注視点, 3)` (s0 = arg × 0.1)、`FUN_00301d9c` で待つ (汎用スイッチ §7 と同じ) |
| 9 | カメラを戻す | `FUN_00301a44(cam, 3, 0)` (s0 = arg × 0.1、0 = 1.5)、`FUN_00301d9c` |
| 10 | フェード | arg = 0: `FUN_003174e8(0, 0, 0, 2)` + `FUN_00300dbc` (黒へ、待つ)。1: `FUN_0031745c(2)` + `FUN_0031747c`。s0 = p × 0.1 (0 = 0.5) |
| 11 | 置く | 主人公・パーティ: `FUN_0030150c(&位置, 向き, 1, 1)` (s0 = 100、arg 0〜3 を南東北西で)。行の役者: `FUN_0031b408(obj, &位置)` |

### 9.2 始まりと後始末

- 始め: `FUN_003024f8(0)` (操作を止める)、主人公のハンドル `FUN_0031ba8c`。
- 終わり: 暗いままならフェードイン、カメラを取っていれば 1 秒で戻して追従に戻し後始末 (`FUN_00301a44` / `FUN_00301d9c` / `FUN_00301888` / `FUN_00301764`)、ハンドルを壊し (`FUN_0031b67c`)、`FUN_003024f8(1)`。
- s16 を使うので d8 を保存する。待つ関数は動作の [2] (イベントのコルーチン) の中でだけ呼んでいる ([kahara/cutscene.md](../../kahara/cutscene.md) §4)。

### 9.3 敵 0 の段階 (戦闘なし)

- メッセージか演出のあと、くり返さないなら `FUN_0031b0d8(行, 段階 + 1)` で状態を進める。
- どちらでも `FUN_00317f68(行, 0)` で範囲をマップの読み直しまで止める (中に立ったまま次の段階・同じ段階がすぐ始まらないように)。
- 演出のパッチがない書き出し (`BOSS_PATCH`) では、bit1 の段階はメッセージなしで次へ進む。

### 9.4 確認

- Panana のテスト (`test/cutscene.test.ts`) で、空の code.bin にゲームの関数をスタブにして実行器で動かし、命令ごとの呼び出しと引数・後始末・状態の書き込みを確かめている (ROM があれば実 code.bin での組み立てとほかのパッチとの cave の共有も)。
- 未確認: エミュレーター・実機での動き。アクターのハンドル (`FUN_0031ba8c`) を区画 5 のモンスターのキャラに使ったときの `FUN_003080e4` / `FUN_0030cca4` / `FUN_0031bc08`、変換ノード +0x14 を位置として読むこと (ワールドマップの告知で主人公には使った)。
