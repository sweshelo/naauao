# 「ジャンプ」の行き先を足す・入口が出ていない間は外す

> 対象: 電波人間のRPG2 (`kahara`) v1.1.0。分類: Panana 実装記録・追加 code.ips 仕様 (最新状態の保証ではない)。
> 根拠: [kahara/worldmap.md](../../kahara/worldmap.md) §10 (2026-11 に ROM で確認した関数と実データ)。
> アドレスは実行時/Ghidra アドレス。**パッチはゲーム既存仕様ではなく、Panana が書き出す code.ips に入れたときだけ動く。** 実機・エミュレーターでの確認はまだ。

## 1. 編集 (Panana の「ワールドマップ」の入口の画面)

- 「ジャンプの行き先に足す」: mapJumpPoint.bin に行を足す。名前は行き先のダンジョンの名前 (mapGroup +0x14)。なければ新しいメッセージ「新しい場所」。入口 ID と W01 / W02 (+0x08 bit0) を入れる。
- 足せるのは行 38・39 の 2 行まで (セーブ 0x65 が 40 要素)。外せるのは最後に足した行から (0x65 の印は行の番号で決まる)。
- 「入口が出ていない間は一覧に出さない」: Panana の印 **+0x0D bit0** (ゲームはどこからも読まない。ゲームの行の +0x0D〜+0x0F は詰め物の 0xD0 で bit0 は 0。Panana が足す行も 0xD0 で詰め、印は 0xD1)。足した行は最初から付く。ゲームの行にも付けられる。
- どちらも、プレイヤーがその入口に一度入るか出るかすると一覧に出る (0x65[行]、`FUN_0030472c`)。セーブを書き換えて最初から出す仕組みはない。

## 2. パッチ (`src/game/jumppoints.ts`)

- 行が 38 より多いとき: 0x265F58 `mov r0, #(行 × 12)`、0x266070 `cmp r4, #行`、0x3047C8 `cmp r5, #行`。
- 印の付いた行があるとき: 0x26600C の `beq 0x26606C` を cave への `b` に替える。cave は元の `beq` を同じフラグでしてから、行の番号 (r4) を表 `{行, +0x4B, +0x00, +0x4C, +0x04}` で探し、`FUN_0030b8a4` で「消える」(+0x4C) が成り立つか「出る」(+0x4B) が成り立たなければ 0x26606C (飛ばす)、それ以外は 0x266010 (載せる) へ戻る。判定は `FUN_001e2ac4` が入口を置くときと同じ。
- 条件は書き出すときに、入口 (+0x10 の Wxx_EventObject の行) から表に写す。入口がいつも出る (+0x10 = 0) 行は表に入れない。入口が区画 2 にない行は種類 0xFF (`FUN_0030b8a4` の表は 0xB5 まで、範囲外は偽) で「いつも出さない」にする。
- `FUN_0030b8a4` の r0 (行) はどの種類でも使われない。今のダンジョン (0x4F) を読むのは種類 0x37〜0x39 だけで、ジャンプの画面を開いている間 0x4F は開いた場所のまま。W02 から開くと、W01 の行の 0x37〜0x39 の条件は W02 のものとして読まれる (Panana のストーリーの節目は 0xB0 / 0x18〜0x21 なので影響しない)。

## 3. テスト (`test/jumppoints.test.ts`)

- 空の code.bin: パッチが組み立てられ、0x26600C が cave へ、cave の先頭が元の `beq 0x26606C` であること。`jp_listed` が条件どおりに 0 / 1 を返すこと。
- ROM: 表が 38 行 × 16 B、+0x0D〜+0x0F がどの行も詰め物の 0xD0 (bit0 は 0)、行の入口がすべて W01 / W02 の区画 2 にあること。パッチを当てた code.bin の `FUN_00265f1c` のループ (0x265F38〜0x266078) を実行器で回し、元の表では元と同じ一覧、足した行 38 が載り、入口のない行 39 と条件の通らない行が載らず、訪れていない行は載らないこと。
