# Panana: kahara の戦闘・アイテム・モーション連携メモ

対象は電波人間のRPG2 (`kahara`) v1.1.0。以下は再編前の文書に書かれた実装状況・設計案の履歴であり、Panana の現行コミットに対して動作確認したものではない。ゲーム本体の仕様と MOD のパッチ仕様は [kahara](../../kahara/README.md) を参照。

## モーション再生の実装履歴

出典: [元の仕様文書](../../kahara/monster-motion.md)。以下の「実装済み」「現状」は旧文書の記録時点。

| 段階 | 内容 | ファイル |
|---|---|---|
| 1 | CGFX の骨格を捨てずに持つ (ボーン名・親・ローカルの拡大・回転・移動、逆バインド行列)。頂点のボーン番号と重み (スキニング 1 = 剛体、2 = スムース) も持ち、アニメするモデルでは静止姿勢に焼き込まない | `cgfx/cgfx.ts` |
| 2 | CANM を読む: DATA の辞書 9〜11。名前・ループ・フレーム数、ボーンごとのカーブ (定数 / ステップ・線形・エルミートのキー) と、ベイク済みの形式 (クォータニオン・行列)。参考は SPICA (GfxAnimation) と Ohana3DS | `cgfx/cgfx.ts` (新しく `cgfx/anim.ts`) |
| 3 | three.js: `SkinnedMesh` + `Skeleton`。TEV のシェーダー (`cgfx/tev.ts`) に three.js のスキニングのチャンクを足す。剛体スキニングだけのモデルなら、ボーンの `Object3D` にメッシュを付けるだけでもよい | `cgfx/three.ts`, `cgfx/tev.ts` |
| 4 | ビューア: `requestAnimationFrame` で進める。モーションの選択 (CANM の名前の一覧。アニメ表から「0x41 ミュージアム・待機」などの名前を付ける)、速さ、一時停止・フレームのスライダー | `pages/modelview.ts` |
| 5 | 表示の既定をミュージアムに合わせる: アニメ 0x41 をループ、拡大率は MonsterDesign +0x34。戦闘の待機 (0x41 / 0x42) にも切り替えられるようにする | `pages/monsters.ts`, `game/monsters.ts` |
| 6 | キャッシュ: `CACHE_VERSION` を上げる。アニメは Float32Array で持ち、ワーカーから転送する | `cgfx/loader.ts`, `cgfx/worker.ts` |

- 写真 (一覧の縮小画像) は今のまま静止姿勢でよい。0x41 の 0 フレーム目にしてもよい。
- マテリアルアニメ (テクスチャの切り替え・UV のスクロール) は、TEV の uniform を毎フレーム書き換えれば対応できる。まず骨格アニメだけで効果を確かめる。
- 注意: ゲームは名前の先頭 4 バイトで照合する。表示では完全一致で探し、なければ先頭 4 バイトで探す。

実装したもの: `src/cgfx/anim.ts` (読み込み・評価)、`src/cgfx/player.ts` (CPU スキニングと UV のアニメ)、`src/pages/modelview.ts` (モーションの選択・再生)。
スキニングは TEV シェーダーを変えずに、CPU で頂点を毎フレーム動かす。モデル 1 体なので十分速い。

## 演出の対応状況・編集方針

出典: [元の仕様文書](../../kahara/action-performance.md)。以下の「実装済み」「現状」は旧文書の記録時点。

| 要素 | データ | Panana の現状 |
|---|---|---|
| モーション | directData +0x0A → animData → モデルの CANM | 再生できる (`src/cgfx/anim.ts`、`src/cgfx/player.ts`) |
| SE | directData +0x06 → soundData | 鳴らせる (`src/sound/player.ts`) |
| エフェクトの取り付け | effectData +0x0C (ボーン名)、+0x10〜+0x26 (変換) | ボーンは読めている (スキニング用の骨格)。位置は出せる |
| エフェクトの見た目 | `8756A407` の CGFX (CMDL + PEMT + テクスチャ) | **未対応**。テクスチャは読めるが、パーティクル (エミッター・パーティクルセットの初期化・更新) の形式は未解析 |
| アビリティ | actionData の効果の欄 | 表示・一部編集できる |

- 演出の行 (directData) は複数のアクションで共有されるので、編集は今のモーションの変更と同じく「同じ内容の行を探す、なければ末尾に追加」で行う。effectData / soundData は既存の行を選ぶだけなら、書き出すのは今と同じ `2713402F` の directData だけで済む。

## 図鑑・アイテム編集の記録

- アイテム図鑑は道具の効果 (アクション) と装備の効果 (状態 × 2) を表示・編集できると旧文書に記載。アクションの欄はアクションページで編集する。
- モンスター図鑑は、属性の状態異常 (ブラインド = 光を含む 8 種) を属性と同じ順のチャートにし、毒・マヒ・ねむり・誘惑を能力ダウン・突然死と同じチャートにする。枠と名前の照合元は `test/rom.test.ts` の `ELEMENT_AILMENTS` / `PLAIN_AILMENTS`。
- 旧 `item-effects.md` はドロップ率のパーティー計算を `monsters.ts` の `dropOdds` に依拠して説明していた。再編前はゲーム側の単位・式が未確認だったが、今回 [戦闘 §2.1](../../kahara/battle.md) のROM局所実行で分母表・式・丸めを確認した。実装の表示とゲーム内部の整数変換は分けて扱う。
- モーション再生の旧計画は骨格・必要ならマテリアル／表示アニメの読み込みとスキニング。色アニメ (`*.cmcla`)、種類 6 (色)・種類 2 (表示、bool) は未対応と旧文書に記載。

## 再編時の実装照合 (2026-10-08)

`sweshelo/panana` commit `c48b0baaffab5d021625183dce4ec69e62afc37f` のソースを読み取り確認した。以下は実装の照合結果であり、ゲームの実行や ROM の再解析による確認ではない。

- `src/game/monsters.ts` の `BattleParams` は BattleParameter の `+0x10C + rate × 2` を u16 として読み、`dropOdds(rate, bonus = 100)` で次を計算する。`B = dropBase[rate & 15]`、`bonus < 0` または `B <= 1` なら `N = 1`。それ以外は `p = 1 - (1 - 1/B)^(bonus × 0.01)`、`p > 0` なら `N = max(1, trunc(1/p))`、それ以外は `Infinity`。返値は「N 回に 1 回」の分母。コメントは各枠を独立に抽選し `rand × N < 2^32` と記載し、ゲーム側の根拠候補として `FUN_00283e68` を挙げる。この関数を確認するまでは本体仕様として確定しない。
- `test/rom.test.ts` に、属性状態異常の順序を `やけど, 氷結, かぜっぴき, どろだらけ, かんでん, 水びたし, ブラインド, 呪い`、その他を `毒, マヒ, ねむり, 誘惑` とする検証コードがある (テストはこの再編では未実行)。
- 旧記述の `src/cgfx/anim.ts`、`src/cgfx/player.ts`、`src/pages/modelview.ts`、`src/sound/player.ts` は存在する。旧設計表にある各機能の全動作を確認したものではない。
- 当該コミットに `tools/` は存在せず、旧 `tools/gen_reference.py` / `tools/gen_scripts.py` の現在の所在は未確認。
