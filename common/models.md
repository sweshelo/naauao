# モンスター・アイテムのモデル (3 作品の比較と移植)

> 対象: **kahara (RPG2 v1.1.0)**、**oahu (RPG3 Base v0 + Update v4096)**、**lanai (RPG FREE! Base v0 + Update v17408)**。アドレスは各作品の code.bin の仮想アドレス (oahu と lanai は Update)。確度: **確定** = コードを読みデータで確かめた、**高** = コードを読んだがゲームでは未確認、**推定**、**未**。

作品間でモンスター・アイテムの見た目を移し替えるときに要ることを、作品ごとの資料 ([kahara/monster-motion.md](../kahara/monster-motion.md)、[lanai/monsters.md](../lanai/monsters.md)) から横断してまとめる。実装は Panana の `src/port/` (連携メモ: [integrations/panana](../integrations/panana/README.md))。

## 1. 形式の違い

| | kahara | oahu | lanai |
|---|---|---|---|
| モンスターのモデル | CGFX (rev 0x05000000)。モデル・LUT・全アニメを 1 エントリ、色違いのテクスチャを別エントリ | BCH **H3D 版 8** (converter 39824)。モデル・`*_tex.bch`・`*_battle.bch` の 3 つ | BCH **H3D 版 0x21** (converter 42482 / 42921)。oahu と同じ 3 つ |
| モデルのアーカイブ | `470D2848` (261 エントリ、type 2、LZ10、名前なし) | `28480000` (361 エントリ。297 が BCH、64 が付属エフェクト `fx_*` の CGFX) | `28480000` (Base、497) と `719F0000` (Update のみ、349)。type 4、ZIP (名前あり) |
| デザインの表 | `2713402F` の `monsterDesign.bin` 165 × 0x70 | `402F0000` の `monsterDesign.bin` 163 × 0x78 | master `2135000A` の `MonsterDesign` 570 × 0xA0 |
| デザインの行の上限 | 256 (MonsterParameter +0x4C が 1 バイト) | 256 (monsterParameter +0x48 の下位 8 ビット。bit9 は待機の切り替え) | 1024 (MonsterParameter +0x00 bit20-29) |

### 1.1 H3D の版の確認 (確定)

H3D の読み込みは版を確かめる。oahu と lanai の BCH はそのままでは入れ替えられず、版 8 ⇄ 0x21 の書き直しが要る (違いは [lanai/monsters.md](../lanai/monsters.md) のモデルの節)。

| | 場所 | 条件 |
|---|---|---|
| oahu | `0x45409C` | backward (+4) ≤ 8 かつ forward (+5) ≥ 8 |
| lanai | `0x3AAB7C` | backward ≤ 0x21 かつ forward ≥ 0x21 |

同じ関数で、マジック `BCH\0`、ヘッダーのフラグ (oahu +0x38 / lanai +0x40) の bit1、バッファの境界 (+0x18 & 3、+0x1C & 0xF) も確かめる (エラー 0x80000040 / 0x80000008 / 0x80000020)。kahara の code.bin には CGFX の revision を確かめる箇所が見つかっていない (未)。

## 2. モンスターの行からファイルまで

| | kahara (`FUN_002F2850`) | oahu (`FUN_002223E0`) | lanai (`FUN_002D5878`) |
|---|---|---|---|
| モンスター → デザイン | MonsterParameter +0x4C (u8) | monsterParameter +0x48 & 0xFF | MonsterParameter +0x00 bit20-29 (行番号。`FUN_00306E44`) |
| モデル | +0x10 (種類 3) | +0x0C | +0x08 |
| 色のテクスチャ | +0x14 (種類 9) | +0x10 (なしは `dummy_tex.bch` 8232FC00) | +0x0C (種類 0xA、`FUN_002EBBE8`) |
| 戦闘のモーション | (モデルに入っている) | +0x14。呼び出しのフラグに 0x200 があるときだけ読む (戦闘 `0x320C30`) | +0x10。フラグ 0x200 のときだけ (`FUN_002CE2C4`) |
| アーカイブ | 470D2848 | いつも 28480000 (`0x222B90`) | **+0x04 の bit20 / 21 / 22 がモデル / テクスチャ / モーションごとに 719F0000 (立っている) か 28480000 か** (`0x2D5954`、`0x2D59E4`、`0x2D5A50`、`0x1B68C0`) |

- lanai は 2 つのアーカイブを探さない。新しいエントリはどちらに置いてもよく、bit で場所を示す (確定)。719F0000 はもともと patchList にあるので、足しても patchList は変えなくてよい (LayeredFS で置き換えて動くかは未確認)。
- lanai の NpcParameter も、+0x6E & 0xF == 5 のとき +0x0C をデザインの行として使う (`0x1B6830`)。
- oahu のデザイン +0x71 は monsterEffect の行 (付属エフェクト `fx_*`、ボーン名と位置)。

## 3. モーションの選び方 (確定)

3 作品とも、コードは **animData (`B3314000`) の行** を指定し、エンジンは行の名前の **先頭 4 バイト** と同じ 4 バイトで始まるモデルのアニメを再生する。骨格アニメと目・色のマテリアルアニメ (`001_E01_eyes.cmtsa`) は同じ接頭辞で一緒に動く。接頭辞は 3 作品で同じで、行番号だけが違う。

| 接頭辞 | 動き | kahara | oahu | lanai | oahu・lanai のファイル | ループ |
|---|---|---|---|---|---|---|
| `001_` | 待機 (ミュージアム・フィールド・戦闘) | 0x41 | 0x5C | 0x75 | モデル | する |
| `002_` | 戦闘の別の待機 | 0x42 | 0x5D | 0x76 | 戦闘 | する |
| `003_` / `004_` | 歩き / 走り | 0x43 / 0x44 | 0x5E / 0x5F | 0x77 / 0x78 | モデル | する |
| `005_` `006_` `007_` `010_` | ワザ A〜D | 0x45〜0x48 | 0x60〜0x63 | 0x79〜0x7C | 戦闘 | 1 回 |
| `011_` | ワザ E | (行なし) | 0x64 | 0x7D | 戦闘 | 1 回 |
| `008_` / `009_` | ダメージ / 倒れる | 0x49 / 0x4A | 0x65 / 0x66 | 0x7E / 0x7F | 戦闘 | 1 回 |
| `012_` / `013_` | (lanai のみ) | — | — | 0x81 / 0x82 | 戦闘 | 1 回 |
| `101_`〜`105_` | 色のアニメ (`*.cmcla`) | 0x4C〜0x50 | 0x68〜0x6C | 0x83〜0x87 | モデル | (+8 = 2) |

- 再生: kahara `FUN_003189B4`、oahu `FUN_004ADC44` → `FUN_00121294`、lanai `FUN_002EC2F8` (番号を対象のオブジェクトの vtable +0x48 で置き換えてから) → `FUN_0031D12C`。lanai の `FUN_002FC300` は電波人間用の行 ID (待機 0x80000001 など) を NPC・モンスターのものに置き換える (vtable +0x48 の置き換えに当たると推定)。
- 名前の後ろ (`_E01_wait`) はゲームが見ない。移植では接頭辞を残し、ファイルの振り分けだけを作品に合わせる。戦闘のモーションのファイルは戦闘でだけ読まれるので、そこに入れた動きはミュージアムとフィールドでは出ない。
- 戦闘の待機 (確定):
  - kahara: MonsterParameter +0x4A bit3 で 0x42。
  - oahu: `FUN_0029BCBC` が monsterParameter +0x48 & 0x200 で 0x5D (走り 0x5F `FUN_0029BA98`、倒れる 0x66 `FUN_0029BC10`。`FUN_001C5A78` がユニット +0x1C / +0x1E / +0x20 に入れる)。
  - lanai: `FUN_002EF3DC` が **MonsterParameter +0x18 bit0** で animData の行 ID 0x8000005D (行 0x76 `002_`)、なければ 0x8000005C (行 0x75 `001_`)。走り 0x8000005F (`FUN_002EF44C`)、倒れる 0x80000066 (`FUN_00202034`)。`FUN_002EF3D0` がユニット +0x20 / +0x24 / +0x28 に入れる。lanai のコードは行番号でなく行 ID で指し、その数は RPG3 の行番号と同じ。NPC のユニットは NpcParameter +0x6E bit7。
  - この切り替えのビットを立てる見た目は、`002_` で始まるループのアニメを持つ必要がある (lanai で立つ 19 行はどれも持つ)。`002_` は待機のほかワザの演出 (`002_*_special`) にも使われる。

## 4. モデルの中で名前で探すもの

| | kahara | oahu | lanai |
|---|---|---|---|
| 腰のボーン (フラグ bit1) | 固定の `waist` (`0x2F2E64`) | 固定の `waist` (`0x222BCC`) | **MonsterDesign +0x34** の文字列 (0 なら `waist`、`0x2D5F94`)。データには `neck`・`jaw`・`skl_waist`・`Waist`・`root_joint` などがある |
| 影 (フラグ bit0) | 別モデル `50B5A9DF` / `05493800` | 別モデル `A9DF0000` / `22D40C00` | oahu と同じ |
| シェーダー | `DefaultShader` | master の `h3d_DefaultShader.bch` (`67E5D800`) の外部プログラム `{0..3}@DefaultShader{,-rs,-ss}{,-nl,-hs}` を名前で参照。モンスターの BCH はシェーダーを持たない | oahu と同じ |
| LUT | モデルの LUT (`enemy_NN`、サンプラー `wood_hilight` / `wood_rimlight` / `iron_*` / `cloth_*`)。Dist0 = `*_hilight`、Dist1 = `*_rimlight` | 同じ (名前で参照) | 同じ |

### 4.1 H3D のシェーダーの名前と bool のユニフォーム (確定: 全モンスターの材質・サブメッシュと一致)

- 番号 = 3 − テクスチャの数。
- テクスチャが 1 枚の材質は、剛体 / スキンなしのサブメッシュだけなら `-rs-nl`、スムースだけなら `-ss-nl`、両方に使われるなら `-nl`。
- サブメッシュの bool のユニフォームは作品で意味が違う (シェーダーのプログラムが違うため)。

| ビット | oahu | lanai |
|---|---|---|
| 常に | 0x1、0xE00 | 0x1、0x200 |
| サブメッシュがスムース / 剛体 | 0x2 / 0x4 | 0x2 / 0x4 |
| 重みが 4 個 | 0x100 | 0x100 |
| ライティング | 0x8000 | 0x8 |
| 頂点カラー | 0x80 | 0x80 |
| テクスチャ 2 枚以上 / 3 枚 | 0x2000 / 0x4000 | 0x2400 / 0x4800 |

例: oahu のスムース 0x8E03・0x8F03・0xAE03、剛体 0x8E05・0xAE05。lanai のスムース 0x20B・0x30B・0x260B、剛体 0x20D・0x260D、スキンなし 0x209。

- oahu のメッシュの skinning はいつも 0 で、サブメッシュが 1 (スムース) / 2 (剛体)。lanai はメッシュが 2 (スムース) / 1 (剛体) / 0。
- アイテムでも 99.6% がこの規則に合う (例外は `-nl` でないシェーダーで、0x1000 が加わる)。
- サブメッシュのボーンは 20 個まで (ネイティブの最大もちょうど 20)。テクスチャは 512×512 まで、ほとんどが ETC1 / ETC1A4。

|---|---|---|---|
| 名前・説明のメッセージ | +0x00 / +0x04 | +0x00 | (MonsterParameter にある) |
| ビットの欄 | +0x0C | +0x08 | +0x04 (と bit20-22 のアーカイブ) |
| モデル / 色のテクスチャ / 戦闘のモーション | +0x10 / +0x14 / — | +0x0C / +0x10 / +0x14 | +0x08 / +0x0C / +0x10 |
| 手続きテクスチャ (値・UTF-16 の名前・フォルダ) | | | +0x14 / +0x18 / +0x1C bit0 (`FUN_0043B594`) |
| 演出 0x45〜の距離 (f32) | +0x18〜 ×4 | +0x18〜 ×5 | +0x20〜 ×5 |
| 腰のボーンの名前 | (固定) | (固定) | +0x34 |
| 拡大率 フィールド / 特定のマップ・条件 / 戦闘 / ミュージアム | +0x28 / +0x2C / +0x30 / +0x34 | +0x2C / +0x30 / +0x34 / +0x38 | +0x38 / +0x3C / +0x40 / +0x44 |
| 高さ (u16 ×2) | +0x3C | +0x40 | +0x58 |
| 取り付け位置 (s16 ×4 ×4) | +0x40〜+0x5F | +0x48〜+0x67 | +0x60〜+0x7F |
| 半径 (200 を超えると使う) | +0x66 | +0x6E | +0x94 |
| 色のアニメの行 (animData、0 = なし) | +0x68 | +0x70 | +0x96 |
| 追加のモデル / エフェクト | +0x69 | +0x71 (monsterEffect) | +0x4C / +0x4E / +0x50 |
| 影の種類 | +0x6E | +0x77 | +0x9C (と +0x9D 影の拡大率) |

- 大きさ・高さ・取り付け位置の単位は 3 作品で同じ (同じ種族の行はほぼ同じ値。kahara と oahu の enemy_04 はどちらも 100.0 / 0.75 …)。
- 移植の手順 (高): 移植先の似た大きさのモンスターの行を写し、ファイルのハッシュ (lanai はアーカイブの bit も)、拡大率・高さ・取り付け位置・半径・距離を移植元から入れ、色のアニメ・エフェクトの欄を 0 にする。lanai は文字列の欄 (+0x18、+0x34) を持たない行を写す。ほかの未解析の欄は写した行のまま。

## 6. アイテムのモデル

| | kahara | oahu | lanai |
|---|---|---|---|
| 表と欄 | itemData (56562135) 713 × 0x30 の +0x20 | itemData (21350000) 1191 × 0x40 の +0x28 | **ItemDataCore** (`201DB400`) 3232 × 0x3C の **+0x18 = アーカイブ名、+0x1C = エントリ** (`FUN_0030225C` / `FUN_00302270`)。アイテム ID は ItemData の行 ID で、ItemData +0x0C が ItemDataCore の行番号 ([lanai/items.md](../lanai/items.md)) |
| アーカイブ | `1D37838B` (道具)・`302996EB` (装備)・`56562135`。呼び出し側が固定で選ぶ | `838B0000` 道具・`96EB0000` 装備・`D4270000` 家具・`982C0000` 屋根・`980C0000` 床と壁・`21350000` 服の柄。呼び出し側が固定で選ぶ | 行ごと (F0F40000・1B270000・025A0000・96EB0000・DC540000・D4270000・980C0000・90100000) |
| 形式 | CGFX (テクスチャを含む) | BCH 版 8。持たないテクスチャは共有のエントリ (equ_all、master) から | BCH 版 0x21 |

- kahara と oahu では、新しいモデルはそのアイテムの種類を読むアーカイブ (今のモデルがあるアーカイブ) に置く。
- lanai はアーカイブを行ごとに持ち、読み込みは決まった一覧と照らさない (推定・強い)。新しいモデルは patchList にあるアーカイブ (719F0000・F0F40000・1B270000 など) に type 4・ZIP で足し、+0x18 / +0x1C に書く。形式はすべて裸の BCH 版 0x21。ふく (0xDx) と床・壁 (0x67 / 0x68) はテクスチャだけの BCH。
- lanai の入手演出の表示は、位置・回転・大きさをアイテムの行ではなく RaregetParameter (A9DF0000) の行 (ItemDataCore +0x24) から取る。ふく・床・壁は入手演出で決まった代わりのモデルを使う。

## 7. エントリのハッシュ

- 名前からハッシュを作る関数は見つかっていない (CRC-32・FNV・djb2・murmur・xxHash など多数を試した)。同じファイル名は 3 作品で同じハッシュ (`monsterDesign.bin` = C402F800)、下位 8 ビットはいつも 0、ルートの名前は kahara 式の下位 16 ビット << 16 (470D2848 → 28480000)。
- ゲームは表の値とアーカイブのハッシュを比べるだけで、実行時に名前をハッシュしない。lanai の 28480000 は名前順で、二分探索ではない。新しいエントリには、その作品のどのアーカイブにもない下位 8 ビット 0 の値を使えばよい。
