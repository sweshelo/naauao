# 「なかまをよぶ」(仲間を呼ぶ・分裂) の作品比較

対象: 初代 `honolulu` (Base v1024)、RPG2 `kahara` (v1.1.0)、RPG3 `oahu` (Update v4096)、RPG FREE! `lanai` (Update v17408)。アドレスは各作品の code.bin の実行時アドレス (ファイル位置 + 0x100000。oahu・lanai は Update の code.bin)。2026-10-31 にユーザーの PC の ROM で逆アセンブルして読んだ (ツールは [roms/tools/armdis.py](../roms/tools/armdis.py))。作品ごとに行サイズ・欄・ID は違うので、ほかの作品へ流用しない。

確度: **確定** = コードで読み方を確認したもの。**推定** = 呼び出し元とデータの形からの推測。

## 0. 要点

| 作品 | 呼ぶ相手の決め方 | データだけで相手を指定できるか |
|---|---|---|
| 初代 | ワザの ID (#125 / #126) でコードが分かれ、**今のマップの群れ**か、その群れ +0x2D の monsterFixGroup から選ぶ | 一部 (マップの群れ単位)。モンスター単位はパッチが要る |
| RPG2 | アクションの ID (#409/#539 と #410/#540) でコードが分かれ、**今のマップの群れ**か、その群れ +0x2D の monsterFixGroup から選ぶ | 一部 (マップの群れ単位)。モンスター単位はパッチが要る |
| RPG3 | 系統 19 のアクション +0x1A = モンスターの行 / +0x18 = 群れの行 | **できる** (新しい行も可) |
| FREE! | 系統 27 のアクション +0x00 = MonsterParameter の行 ID | **できる** (新しい行も可) |

初代と RPG2 は同じ作りで、呼ぶ相手はアクションの欄に持たない。RPG3 から、アクションの欄で相手を決めるようになった。

どの作品も、呼べるかどうかは「敵の数 < 8」と「大きさの空き」で決まる。空きは 26 (初代・RPG2) または 27 (RPG3・FREE!) から、生きている敵ごとの (大きさ + 1) を引いた値。

## 1. RPG2 (kahara)

### 1.1 決め方 (確定)

- 計算は `FUN_00191250` のカテゴリ 3・種別 4 ([battle.md §7](../kahara/battle.md#7-カテゴリ-3-モンスターの特殊行動)、`0x191500`〜)。**アクション ID で分岐する** (`0x191514`)。
  - #409 / #539 → `FUN_0030ede0` (今のマップの群れから)
  - #410 / #540 → `FUN_001925b8` (群れ +0x2D の固定の組から。0 なら #409 と同じ)
  - **ほかの ID の種別 4 は必ず失敗する** (結果 +0x14 |= 0x80000)。行を足しても新しい「呼ぶ」は作れない。
- AI 側の判定 (`0x416B58`〜) にも同じ ID の分岐がある。敵の数 (戦闘 +0xBDAC) が 8 なら選ばない。
- 第 2 引数の空き = `FUN_0030efc8` = 26 − Σ(min(デザイン +0x6E, 8) + 1)。生きている敵ごとに数える。
- `FUN_0030ede0`:
  - 群れ = `FUN_0030f984(0)`。ハッシュ 0 なので `*(*0x564638 + 0x3D4)` の行、つまりエンカウント構造体 +0x380。マップの読み込みで `FUN_002ef15c` が区画 6 の「マップの群れ」を入れる欄なので、**出会った群れではなく今のマップの群れ**を使う。
  - monsterGroup の +0x00 の 5 枠と +0x14 の 5 枠 (計 10 枠) のうち、モンスターが 0 でないものすべてが候補。**重みは見ない** (重み 0 の枠も候補)。
  - 条件は MonsterDesign[MonsterParameter +0x4C] +0x6E (大きさ) ≤ 空き だけ。合う候補から均等に 1 体選ぶ。
- `FUN_001925b8`: 群れ +0x2D が 0 でなければ、monsterFixGroup のその行の 5 枠 (+0x04 + 4k の u16) から同じ条件で選ぶ。
- #409 と #539、#410 と #540 は、メッセージと演出 (+0x04 / +0x1E) が違うだけ (#539/#540 はキャット用の文)。
- 出現: `FUN_0030eb88` が 8 枠 (戦闘 +0xED80 + 0x2F8 × i、+4 が 0 の枠) から空きを探し、なければ 8 を返して失敗。あれば `FUN_00289524` で戦闘開始時と同じ作り方をする (名前に A/B を付ける処理もここ)。`FUN_0030e7c8` は並び (使った側の隣) を詰め直すだけ。
- 呼ばれた敵の Lv・能力・経験値・ドロップは、その MonsterParameter の行のとおり (作り方 `FUN_00199c00` が通常と同じ。確定)。報酬の集計に入るのは、同じユニットの枠に入るため (推定)。

### 1.2 monsterGroup +0x2D (確定)

- [encounters.md](../kahara/encounters.md) では未解析としていた欄。**monsterFixGroup の行**で、#410/#540 の呼ぶ相手に使う。
- 型の選択 (`0x352510`) でも「型 0 を選んだときの monsterFixGroup の行」として使う。ボス部屋などの群れは +0x28 = 1・+0x2D = 固定の組。
- なので +0x28 (型 0 の重み) が 0 でない群れの +0x2D を変えると、出会いの組も変わる。

### 1.3 ボス戦

- 群れは戦闘の組ではなく、マップの群れのまま。
- `FUN_00190b6c` は、`FUN_00281e30(…, 0x50)` が 0xA8654391 / 0x09A1DA1B のときだけ +0x380 をエンカウントの群れ (ハッシュ 0 なら行 0 = 空) で上書きする。この 2 つが何のハッシュかは未確認。

### 1.4 元データの例

群れは、その敵が入っている群れ。その群れが実際にマップの群れとして使われるかは未照合。

| 使い手 | アクション | 群れ | 呼ばれる候補 |
|---|---|---|---|
| ゴールデンハム | #410 | 26 / 27 / 29 (+0x2D = 61) | にゅうし・ゴールデンハム |
| ももいろハム | #409 × 2、#410 | 55 | #409: おばけオトシゴ / ももいろハム / どくナマコ / かいりゅう。#410: +0x2D = 62 → アンコウジュニア |
| くろぶた | #409 / #410 | 127〜130 (+0x2D = 0) | 群れから (#410 も同じ) |
| グリーンポーク | #409 | 80 | 群れから |
| くらやみ・かいとう・きぞくキャット | #539 | | 群れから |

### 1.5 呼ぶ相手を変える方法

データだけでできること:

- マップの群れの 10 枠を変える。重み 0 の枠に置くと、出会いには出ずに呼ぶ候補にだけなる見込み (出会いの処理が重み 0 を飛ばすことは推定)。
- #410/#540 を使い、マップの群れの +0x2D に monsterFixGroup の行を入れる (§1.2 の注意)。

モンスター単位で決めるパッチ案 (未実装):

- 種別 4 の 4 行は +0x14 / +0x18 / +0x1A がすべて 0。+0x18 / +0x1A (量の範囲) は種別 1 / 6 / 8 / 9 でしか使われていない。
- `0x191514` の ID の分岐 (9 命令。r7 = ID、r0 = 空き、sb = 戦闘) を code cave への `bl` にする。cave は actionData[ID] (マスター +0xE0) の +0x18 が 0 でなければそれを MonsterParameter の行とし、大きさ ≤ 空き なら返す。0 なら元の分岐へ戻る (+0x1A を「0 = 行、1 = 固定の組、2 = 群れ」のモードにしてもよい)。
- AI 側 (`0x416B74`) にも同じものを入れる。これで新しい ID の種別 4 も動く。

## 2. RPG3 (oahu)

系統 19 (`0x1B5FF0`) の読み方は [actions.md §3](../oahu/actions.md#3-系統-0x2c) のとおり (確定)。補足:

- 最初に `FUN_0048f8c8` で 戦闘 +4 ≠ 8 を確かめる (8 は呼べない戦闘の種類と推定)。
- +0x1A ≠ 0 なら、その行のモンスターを呼ぶ (`ldrh` で 0 か見て、`strb` で下位 8 ビットを使う)。
- そうでなく +0x18 ≠ 0 なら、`FUN_0022c0a8` で群れの行をハッシュにして `FUN_004EADC8` へ渡す。
- 両方 0 なら、戦闘 +0xF0 (今の戦闘の群れのハッシュ) から選ぶ。
- 群れからの選び方 `FUN_0019E8BC`: 次の候補のうち条件を満たすものから均等に 1 体 (`FUN_001B1F40`)。重みでは比べない。
  - +0x00 の 5 枠 (重み +2 が 0 でないもの)
  - +0x14 の 5 枠 (重み +0x16 が 0 でないもの)
  - +0x28 の 5 × u16 (固定の並び。重みなし)
- 呼べる条件 `FUN_001F33D0`: 側 +2 = 0xA、ユニットが 8 体未満 (`FUN_004C3B74`)、空いた枠がある、空き = 27 − Σ(大きさ + 1) が monsterDesign[MP +0x48 & 0x1FF] +0x77 より大きい。1 戦闘あたりの回数の制限は見当たらない。
- 系統 20 (分裂、`0x1B60A4`): 成功率 = w1 bit9-11 の番号で `FUN_004EAF34` の表 +0x74 を引き、乱数 (+0x73) と比べる。外れると結果 +0x12 bit3。呼ぶのは `FUN_004CCAFC` (ユニットのモンスターの行) = 自分と同じモンスター。

元データの例:

|---|---|---|
| ゴールデンハム | #491 | ゴールデンハム |
| キャットシーフ | #575 | 自分 |
| ころがし系 | #1041 / #1045 / #1049 | 自分 |
| アクアトータス (自動の枠) | #1055 | でんきフジツボ |
| よいやみのかめ | #1061 | ハードフジツボ |
| ひかりのげんぶ | #1066 | ホワイトフジツボ |
| きぞくキャット | #579 (+0x18 = 群れ 152) | きぞくキャット・おはなドール・サクラはなもぐら・トレジャーパラディン・ファイヤーブロックス |
| カビまんじゅう・ビリリきん・カミナリゴケ・カビカビまんじゅう (ボディ) | 分裂 #627 / #631 / #636 / #640 | 自分 |

Panana ではアクションの画面で呼ぶモンスター・群れを選べる。

## 3. RPG FREE! (lanai)

- **系統 27 = 仲間を呼ぶ、系統 28 = 分裂** (アクション +0x14 bit4-11。[monsters.md](../lanai/monsters.md))。計算の分岐は `0x2F9C48` (結果 +0x1E = 系統) で、27 → `FUN_0016DC1C`、28 → `FUN_00169BF0`。適用は `0x2F25C4` の `FUN_004227D4(…, 結果 +0x28 = 呼ぶ ID, +0x2C = 位置)`。
- **呼ぶ相手 = アクション +0x00** (u32、MonsterParameter の行 ID = 0x80000000 | n) をそのまま使う (確定)。系統 27 の 91 行はすべて 0 以外。
- +0x00 = 0 のときは `FUN_00473048` (+0x16 を渡す、群れから選ぶ経路) へ行く。候補のポインターの配列を 0 で埋めたまま読んでいるように見え、元データでは使われていない (未確認。使わないほうが安全)。
- 呼べる条件:
  - 1 戦闘あたりの回数 (戦闘 +0x11B) < BattleParameter +0x14F (= 4)。超えると結果 +0x20 |= 0x20 (`FUN_00473010`)。
  - `FUN_002FAB48`: ユニットが 8 体未満、空き = 27 − Σ(大きさ + 1) > MonsterDesign +0x9C (デザインは MP +0x00 bit20-29)。
- 成功すると 戦闘 +0x11B を 1 増やし、+0x11A = 1 にする。フロストキーパーのターン開始の変身条件「戦闘 +0x11A ≠ 0」(0xA7) は、**仲間を呼んだこと**を表す。
- 使った側が状態 0xB のときだけ通る別の判定 (成功すると +0x20 bit7 にして対象を変える) がある。中身は未確認。
- 分裂 (系統 28): 成功率 = +0x08 bit18-20 の段階で BattleParameter +0x89 の表 (32, 24, 16, 11, 8, 4, 2 / +0x88 = 32) を引く。外れると +0x20 bit3。呼ぶのは自分の ID (`FUN_002FAD88`)。

元データの例:

| 使い手 | 呼ぶ相手 |
|---|---|
| グリーンポーク | キャタピラー |
| おばけホール | いちごおばけ |
| フロストキーパー (各形態) | シールドナイト / トーチゴースト / かみなりちょう / アイスドラゴン |
| タイブーン | フロストキーパー・クリムゾンキーパー |
| カネコ・チテイジンモドキ | サルゾンビ / ねずみみロード |
| ゴールデンハム・しろぶた・ダイころがし | 自分 |
| ももいろハム | ももいろハム / にゅうし |
| 分裂: ビリリきん・カビカビまんじゅう・カミナリゴケ など | 自分 |

## 4. 初代 (honolulu)

- monsterAttackSkill #125 / #126「なかまをよんだ」([monsters.md §3](../honolulu/monsters.md#3-monsterattackskill-master-エントリ-47233--0x24))。2 行のデータは同じ。使い手はももいろハム (13) #125、グリーンポーク (37) #125、ゴールデンハム (64) #126・#125。
- コード (`0x177A14`) で ID が分かれる。RPG2 と同じ作り (確定)。
  - #125 → `FUN_00204C70`: `FUN_00205884(0)` = 今のマップの群れ (`*0x321C0C` +0x3C8)。+0x00 と +0x14 の 10 枠から、monsterData[BP +0x2C] +0x2A ≤ 空き のものを均等に選ぶ。
  - #126 → `FUN_00177BA4`: 群れ +0x2D ≠ 0 なら monsterFixGroup のその行 (+0x00 + 4k) から選び、0 なら #125 と同じ。
  - 空き = 26 − Σ (`FUN_00204E28`)。8 体の判定は `FUN_002B47CC`。
- [monsters.md §5.1](../honolulu/monsters.md#51-monstergroup-master-エントリ-4658--0x2e行の後ろに検索用の追加領域) の monsterData +0x2A (「それ以下の敵だけを群れから選ぶ」) は、この大きさの判定。
- 例: ゴールデンハムのいる群れ 47 / 48 は +0x2D = 22 → エアドラゴン、52 / 53 は +0x2D = 23 → ダークマンモス (#126 で呼ばれる)。これらの群れは型 0 の重みが 0 なので出会いには出ない。ももいろハムの群れ 10〜13、グリーンポークの群れ 30〜38 は +0x2D = 0。
- 相手を変えるには RPG2 と同じ制約がある。パッチ案も同じ形で、#125 / #126 の +0x0C / +0x0E (量) は 0 なので、呼ぶ行の欄に使える。
