# 電波人間のRPG (honolulu): ワールドマップ (船着場の島選び)

対象: 日本版 Base Title ID `0004000000077E00`、TitleVersion 1024 (1.0.0)。アドレスは展開済み code.bin の仮想アドレス (base `0x100000`)。[解析の入口](analysis.md) / [マップ・階の定義](map.md) / [店](shops.md)。

確度の表記は [monsters.md](monsters.md) と同じ (確定 / コード / データ / 推定)。

## 1. 全体像と RPG2 との違い

初代の「ワールドマップ」は歩けるフィールドではない。拠点 (デンパ島) の **船着場** で開く 2D の画面で、海の絵の上に島のアイコンを並べ、行き先のダンジョンを選ぶ。(確定)

```
船着場の画面 (レイアウト 3D179000 = darc、アーカイブ 49C917B7 のエントリ 0)
  下画面  pier_bg   海の絵 (pier_btm_bg) + 中央のデンパ島 (Icon_Main、レイアウトに固定)
          pier_btm  望遠鏡の枠 (Telescope)、タイトル「ワールドマップ」、もどる / ここにいく / X のボタン
          island_*  島のアイコン 7 種 (cave / plain / tower / dark / ice / volcano / last)。PierData の行ごとに 1 つ置く
  上画面  pier_top  選んだ島の名前と説明 (dungeonData +0x10 / +0x12 のメッセージ)
                     │
PierData (アーカイブ 49C917B7 のエントリ 1、10 × 0x12) ─┘  島ごとに ダンジョン・アイコン・位置・出る条件
```

- RPG2 / RPG3 / FREE! のワールドマップ (`W01` など、[kahara/worldmap.md](../kahara/worldmap.md)) は 300 × 300 セルの地形と入口の区画を持つ歩けるマップ。初代にはこの仕組み (worldmapParts・W01_ground.bin・マップ表の `W` 行) がない。マップ DB (`A2C14C00`) にもワールドマップのエントリはない。(データ)
- したがって初代のワールドマップの編集は「PierData の 10 行を直す」ことで、地形・入口・エンカウントの区画はない。(データ)
- メッセージ: 「ワールドマップ」= 504 (0x1F8)、「ここにいく」= 505、「もどる」= 506。船着場の施設名は 76 / 84、説明は 92 (「他の島へ冒険に行く…」)。(データ)

## 4. 読み手と条件

### 4.1 島のアイコン (`FUN_002C2280`)

- 船の段階 = **セーブ変数 0x26** (u8、`FUN_00201ED0`)。PierData の 10 行を順に見て、段階 0〜1 は +0x04/+0x06、2 は +0x08/+0x0A、3 は +0x0C/+0x0E の位置にアイコンを置く。`+0x10 > 段階` の行はアイコンを隠す。(コード)
- 段階で望遠鏡の枠のアニメーションも変わる (0〜1 は 0xA7、2 は 0xA6、3 は枠の部品 0x2EA を隠す)。見える範囲が船とともに広がる演出と推定。(コード、演出の意味は推定)
- 行数 10 は**コードに固定** (`cmp r6, #0xa`、0x2C25EC と 0x2C1F40)。メニューの部品もアイコンごとに menuItem 0x2EC〜 が用意されている。行を増やすにはコードとメニューの表の両方を変える必要がある。(コード)

### 4.2 クリアの星

- アイコンを出した行では、`FUN_00202728(+0x00)` (セーブ変数 0x40 のダンジョンの進み具合) が**ダンジョンごとにコードに固定された値**と等しいとき、アイコンに星のアニメーションを付ける。値はダンジョン 1〜5・7〜9 が 5、6 が 4、10 が 7、11 が 15 (0x2C2468 の分岐表)。店の段階の条件 ([shops.md](shops.md)) と同じ値で、クリア後の値と推定 ([analysis.md §7](analysis.md#7-進み具合-セーブ変数-0x40-と未解析))。(コード)
- 星のアニメーションはアイコン (+0x02 − 0x3A) で選ぶ: cave 0x86、plain 0x96、tower 0x9A、dark 0x8A、ice 0x8E、volcano 0x9E、last 0x92。+0x02 が 58〜64 以外なら星を付けない。(コード)
- したがって +0x00 を 12 以上 (再訪用の行) にすると星の判定は常に外れる。(コード)

### 4.3 選んだとき

- `FUN_002C1D9C(画面, 行)`: PierData の行の +0x00 で dungeonData を引き、+0x10 (名前) を部品 0x2E2、+0x12 (説明) を 0x2E3 に出す (上画面の pier_top)。(コード)
- 決定 (`FUN_002C1F50` の分岐。「ここにいく」と推定): 選んでいる項目 (画面 +0xF0) − 0x2EC を PierData の行として、+0x00 を `FUN_001FD330(…, ダンジョン)` に渡す。`FUN_001FD330` はダンジョンごとのセーブ変数 0x3A・0x3E を見てから移る。0x3A / 0x3E の意味は未確認。(コード)
- 中央のデンパ島 (項目 0x2E8) を選ぶと `FUN_001FD330(…, 0xD)` を呼ぶ。13 は dungeonData の行 13 (名前はデンパ島のどうくつ) で、拠点へ戻る経路と推定。(コード、意味は推定)

### 4.4 拠点の島から見える島 (`FUN_001FD17C`)

- 拠点の島の 3D 画面の物体 11〜20 を PierData の行 0〜9 に対応させ、`+0x10 ≤ 船の段階` のときだけ表示する (行 2 = 物体 13 は常に表示)。船着場の画面と同じ条件で、遠くの島の見た目を切り替えると推定。物体のモデル (FB50F315 の `mnmp_island_01〜07` と推定) との対応は未確認。(コード)

### 4.5 船の段階 (セーブ変数 0x26) の書き手

- flagData の行 0x26 は 1 要素。拠点に戻ったときの知らせを集める `FUN_0019229C` が、段階 0 で クルーザー / ふね / いかだのもと (itemData の行 0x102 / 0x101 / 0x100) を持つか、段階 1 で ふね / クルーザー、段階 2 で クルーザーを持つかを見て、知らせのビット (0x10〜0x100) を立てる。段階 0〜3 = なし / いかだ / ふね / クルーザーと推定。値を書く命令 (イベントのスクリプトと推定) は未確認。(コード、値の意味は推定)

## 5. 編集するには

- 編集の対象は PierData の 10 行: 行き先のダンジョン、アイコン (7 種)、船の段階ごとの位置 3 組、出る船の段階。書き換えたら 49C917B7 を作り直す (GS アーカイブ v5、[共通形式](../common/formats.md))。(データ)
- 行の数 (10) とアイコンの種類 (7、menuList 58〜64) はコードとメニューの表に固定。増やす編集は対象外にする。(コード)
- 星の条件の値 (ダンジョンごとの 5 / 4 / 7 / 15) はコードの分岐表にあり、PierData にはない。行き先を別のダンジョンに替えると、星はそのダンジョンの値で判定される。(コード)
- 位置は下画面 (320 × 240) の内側に収める。アイコンの大きさは 32 × 32 (last は 32 × 48)。中央 (0, 0) にはデンパ島がある。(データ)
- 上画面の名前・説明は dungeonData +0x10 / +0x12 のメッセージなので、文言はメッセージの編集で変える。(コード)
