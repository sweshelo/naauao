# 電波人間のRPG (honolulu): ワールドマップ (船着場の島選び)

対象: 日本版 Base Title ID `0004000000077E00`、TitleVersion 1024 (1.0.0)。アドレスは展開済み code.bin の仮想アドレス (base `0x100000`)。[解析の入口](analysis.md) / [マップ・階の定義](map.md) / [店](shops.md)。

確度の表記は [monsters.md](monsters.md) と同じ (確定 / コード / データ / 推定)。

## 1. 全体像と RPG2 との違い

初代の「ワールドマップ」は歩けるフィールドではない。拠点 (デンパ島) の **船着場** で開く 2D の画面で、海の絵の上に島のアイコンを並べ、行き先のダンジョンを選ぶ。(確定)

```
船着場の画面 (レイアウト 3D179000 = darc、アーカイブ 49C917B7 のエントリ 0)
  下画面  pier_bg   海の絵 (pier_btm_bg) + 中央のデンパ島 (Icon_Main、レイアウトに固定)
          pier_btm  望遠鏡の枠 (Telescope)、タイトル「ワールドマップ」、もどる / ここにいく / X のボタン
          island_*  島のアイコン 7 種 (cave / plain / tower / dark / ice / volcano / last)。PierData の行ごとに 1 つ置く
  上画面  pier_top  選んだ島の名前と説明 (dungeonData +0x10 / +0x12 のメッセージ)
                     │
PierData (アーカイブ 49C917B7 のエントリ 1、10 × 0x12) ─┘  島ごとに ダンジョン・アイコン・位置・出る条件
```

- RPG2 / RPG3 / FREE! のワールドマップ (`W01` など、[kahara/worldmap.md](../kahara/worldmap.md)) は 300 × 300 セルの地形と入口の区画を持つ歩けるマップ。初代にはこの仕組み (worldmapParts・W01_ground.bin・マップ表の `W` 行) がない。マップ DB (`A2C14C00`) にもワールドマップのエントリはない。(データ)
- したがって初代のワールドマップの編集は「PierData の 10 行を直す」ことで、地形・入口・エンカウントの区画はない。(データ)
- メッセージ: 「ワールドマップ」= 504 (0x1F8)、「ここにいく」= 505、「もどる」= 506。船着場の施設名は 76 / 84、説明は 92 (「他の島へ冒険に行く…」)。(データ)

## 4. 読み手と条件

### 4.1 島のアイコン (`FUN_002C2280`)

- 船の段階 = **セーブ変数 0x26** (u8、`FUN_00201ED0`)。PierData の 10 行を順に見て、段階 0〜1 は +0x04/+0x06、2 は +0x08/+0x0A、3 は +0x0C/+0x0E の位置にアイコンを置く。`+0x10 > 段階` の行はアイコンを隠す。(コード)
- 段階で望遠鏡の枠 (pier_btm の `Telescope`、320 × 240 の絵に丸い穴) も変わる。段階 0〜1 は 0xA7、2 は 0xA6 のアニメーションを流し、3 は枠の部品 0x2EA を隠す。(コード)
  - 0xA6 / 0xA7 は layoutAnimation の `pier_btm_Telescope_Big` / `_Small` と推定 (番号を 1 始まりで数えたとき。0 始まりだと 0xA7 が船着場と関係のない `red_mask_mask_in` になる)。Big は `telescope_01` (穴の半径 約 108) のまま、Small はフレーム 3 で `telescope_02` (穴の半径 約 81) に替わる。穴の中心はどちらもほぼ (0, 4)。(データ、番号の対応は推定)
  - 実データの島はこの穴に収まる: 段階 1 の島は中心から 38〜43、段階 2 の島は 62〜86 (アイコンの半分 16 を足しても 108 の内側)、段階 3 の島は 144〜146 で枠なしの画面に置く。つまり**段階 1 は半径 約 81、段階 2 は 約 108 の円の内側、段階 3 は画面全体**が見える範囲。円の外に置いた島は枠に隠れると推定 (描画順は未確認)。(データ)
- 行数 10 は**コードに固定** (`cmp r6, #0xa`、0x2C25EC と 0x2C1F40)。メニューの部品もアイコンごとに menuItem 0x2EC〜 が用意されている。行を増やすにはコードとメニューの表の両方を変える必要がある。(コード)

### 4.2 クリアの星

- アイコンを出した行では、`FUN_00202728(+0x00)` (セーブ変数 0x40 のダンジョンの進み具合) が**ダンジョンごとにコードに固定された値**と等しいとき、アイコンに星のアニメーションを付ける。値はダンジョン 1〜5・7〜9 が 5、6 が 4、10 が 7、11 が 15 (0x2C2468 の分岐表)。店の段階の条件 ([shops.md](shops.md)) と同じ値で、クリア後の値と推定 ([analysis.md §7](analysis.md#7-進み具合-セーブ変数-0x40-と未解析))。(コード)
- 星のアニメーションはアイコン (+0x02 − 0x3A) で選ぶ: cave 0x86、plain 0x96、tower 0x9A、dark 0x8A、ice 0x8E、volcano 0x9E、last 0x92。+0x02 が 58〜64 以外なら星を付けない。(コード)
- したがって +0x00 を 12 以上 (再訪用の行) にすると星の判定は常に外れる。(コード)

### 4.3 選んだとき

- `FUN_002C1D9C(画面, 行)`: PierData の行の +0x00 で dungeonData を引き、+0x10 (名前) を部品 0x2E2、+0x12 (説明) を 0x2E3 に出す (上画面の pier_top)。(コード)
- 決定 (`FUN_002C1F50` の分岐。「ここにいく」と推定): 選んでいる項目 (画面 +0xF0) − 0x2EC を PierData の行として、+0x00 を `FUN_001FD330(…, ダンジョン)` に渡す。(コード)
- `FUN_001FD330(画面, ダンジョン)` は**ワープホールの記録**を確かめてからダンジョンへ移る。(コード)
  - セーブ変数 **0x3A**[ダンジョン] (u8) = ワープホールの記録があるか。0 でなければ確認の窓を出す。
  - セーブ変数 **0x3E**[ダンジョン] (s8) = 記録した階の表示用の番号。負なら符号を外して MessageSystemCommon 0x14「…以前ワープホールをくぐった地下 N 階から始めますか？」、0 以上なら 0x15「…N 階から始めますか？」を出す。
  - 「はい」なら `FUN_002C492C(…, ダンジョン, 1)` がセーブ変数 **0x3C**[ダンジョン] (記録した階の内部の番号) を 0x30 (今の階) に写して再開する。「いいえ」または記録なしなら 1 階から (`FUN_002A7BFC`)。どちらでもセーブ変数 0x2E (今のダンジョン) とセーブの +0x1108 にダンジョンを書く。
  - 記録を書くのは `FUN_002C48AC` (呼び手 0x25DD2C。ワープホールをくぐったときと推定): 0x3A = 1、0x3C = 階の番号、0x3D = 位置と推定 (12 B)、0x3E = 表示用の階 (階の物体の +0x08、s16)。
- 中央のデンパ島 (項目 0x2E8) を選ぶと `FUN_001FD330(…, 0xD)` を呼ぶ。13 のときは記録の確認を飛ばして、dungeonData の行 13 (名前はデンパ島のどうくつ、+0x04 は階の定義 `A90C8038` 0021) へ直接移る。拠点の島のどうくつ (行 1) とは別の行で、船着場からデンパ島を選んだときの行き先と推定。(コード、行き先の中身は未確認)

### 4.4 拠点の島から見える島 (`FUN_001FD17C`)

- 拠点の島の 3D 画面の物体 11〜20 を PierData の行 0〜9 に対応させ、`行の +0x10 ≤ 船の段階` のときだけ表示する。船着場の画面と同じ条件。(コード)
- **物体 13 (行 2) だけは PierData を見ずに常に表示**する (0x1FD1B0 で 13 を特別扱いし、表示のあと 14 から続ける)。行 2 は魔王の塔で、船がなくても拠点から見えている塔と推定。PierData の行 2 の +0x10 を変えても 3D 画面の塔は消えない。(コード、意図は推定)
- 物体のモデルは**物体の番号でコードに固定** (島の画面の初期化 0x2C8E20 の分岐表、`FB50F315` のエントリ):

| 物体 | PierData の行 (今のダンジョン) | モデル |
|---|---|---|
| 11 | 0 (2 風の森) | `mnmp_island_03` |
| 12 | 1 (3 海底洞窟) | `mnmp_island_01` |
| 13 | 2 (4 魔王の塔) | `mnmp_island_02` |
| 14 | 3 (5 オアシスへの道) | `mnmp_island_03` |
| 15 | 4 (6 しゃくねつ火山) | `mnmp_island_05` |
| 16 | 5 (7 氷の島) | `mnmp_island_06` |
| 17 | 6 (8 闇の遺跡) | `mnmp_island_07` |
| 18 | 7 (9 火口の風穴) | `mnmp_island_05` |
| 19 | 8 (10 ストレンジフォレスト) | `mnmp_island_03` |
| 20 | 9 (11 ガーディアンタワー) | `mnmp_island_04` |

- 別の読み手 0x1BA090 (セーブ +0x1108 = 今のダンジョンで分岐) は**ダンジョン − 2 + 11** の物体と同じモデルを選ぶ。物体とダンジョンの対応 (物体 = ダンジョン + 9) がコードに固定されていて、PierData の +0x00 は見ない。島へ向かう / 戻る演出と推定。(コード、演出の意味は推定)
- 物体の 3D の位置は PierData にない (島の画面の物体として置く。場所は未確認)。PierData の位置を変えても 3D 画面の島は動かない。(コード)

### 4.5 船の段階 (セーブ変数 0x26) の書き手

- flagData の行 0x26 は 1 要素。値は 0〜3 = なし / いかだ / ふね / クルーザー。(コード)
- 書き手 (セーブ変数の書き込み `FUN_001C9FD4` を変数 0x26 の定数で呼ぶのはこの 2 か所だけ):
  - 0x1C916C: 0 を書く。同じ関数がセーブ変数 0x0E・0x24 なども初期値にするので、新しいセーブの初期化と推定。
  - `FUN_002A7B3C(セーブ, 値)`: 値が 3 以下なら書く。呼び手は拠点の演出 `FUN_00267CC0` の種類 2 (0x2686F4) だけで、演出の +0x18 の値を書く。値が 3 のときは続けて `FUN_002A75E4` も呼ぶ (セーブ変数 0x0E を見る。中身は未確認)。
- 種類 2 の演出は拠点に戻ったときの知らせ `FUN_0019229C` が作る。船のもと (itemData の行 0x100 いかだ / 0x101 ふね / 0x102 クルーザー) の所持で知らせのビットを立て、ビットごとに演出の値を決める:

| 今の段階 | 持っている品 (上が優先) | ビット | 書く段階 |
|---|---|---|---|
| 0 | クルーザーのもと / ふねのもと / いかだのもと | 0x40 / 0x20 / 0x10 | 3 / 2 / 1 |
| 1 | クルーザーのもと / ふねのもと | 0x100 / 0x80 | 3 / 2 |
| 2 | クルーザーのもと | 0x100 | 3 |

- つまり船の段階は**船のもとを持って拠点に戻ると、持っている中で最も上の段階へ一気に上がる**。(コード) 変数の番号を引数で受け取る汎用の書き込み (スクリプトの命令など) から 0x26 を書く経路があるかは未確認。

### 4.6 dungeonData の残りの欄とカメラ

- dungeonData **+0x14** (u16) = ダンジョンに入るときのタイトルの副題 (MessageField 0xB68〜0xB72。例: 行 2「電波人間と巨大な虫」、行 11「最後の試練」)。`FUN_001DD8D0` が今のダンジョンの行を引き、menuList 0x15 の部品 0x6A に +0x10 (名前)、0x6B に +0x14 を出す。(コード)
- dungeonData **+0x16** は mapData の行 (階の定義が mapData を指さないときの既定のタイルセット)。[map.md §3.3](map.md#33-タイルのモデル) を参照。
- dungeonData **+0x08** の bit 0 (行 2・5 で 1): `FUN_002C492C` がダンジョンに入るときに読み、立っていれば入場の情報の +1 に 2 を書く。意味は未確認。(コード)
- `island_camera01〜05`・`port_camera01〜04` の表 (code.bin 0x300084、10 件) は、拠点の島の画面の初期化 `FUN_002C8AB4` が読み込み、`FUN_001FD4FC(…, 番号 0〜9)` が 0x3000AC の表 (u16 × 10、下位 8 bit) で番号からカメラを選ぶ。番号は拠点の施設の選択で、ダンジョンや dungeonData は見ない。**dungeonData +0x00 とカメラは無関係**。(コード、番号が施設であることは推定)

## 5. 編集するには

- 編集の対象は PierData の 10 行: 行き先のダンジョン、アイコン (7 種)、船の段階ごとの位置 3 組、出る船の段階。書き換えたら 49C917B7 を作り直す (GS アーカイブ v5、[共通形式](../common/formats.md))。(データ)
- 行の数 (10) とアイコンの種類 (7、menuList 58〜64) はコードとメニューの表に固定。増やす編集は対象外にする。(コード)
- 星の条件の値 (ダンジョンごとの 5 / 4 / 7 / 15) はコードの分岐表にあり、PierData にはない。行き先を別のダンジョンに替えると、星はそのダンジョンの値で判定される。(コード)
- 位置は下画面 (中央が原点、上が +y、x ±160・y ±120) の内側に収める。アイコンの大きさは 32 × 32 (last は 32 × 48)。中央 (0, 0) にはデンパ島がある。(コード + データ)
- 段階ごとの見える範囲: 段階 0〜1 の位置 (+0x04/+0x06) は半径 約 81、段階 2 の位置 (+0x08/+0x0A) は半径 約 108 の円 (中心 ほぼ (0, 4)) の内側に置くと望遠鏡の穴から見える。段階 3 の位置 (+0x0C/+0x0E) は画面全体。(データ、推定を含む)
- 3D 画面 (拠点の島から見える島) は PierData の位置を使わない。島のモデルは**行の番号**で決まり (§4.4)、行き先 (+0x00) を替えても島の見た目は替わらない。行 2 の島は +0x10 によらず常に見える。(コード)
- 上画面の名前・説明は dungeonData +0x10 / +0x12 のメッセージなので、文言はメッセージの編集で変える。(コード)
