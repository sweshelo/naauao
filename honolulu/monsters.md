# 電波人間のRPG (honolulu): モンスター・ワザ・特技・群れ

対象: 日本版 Base Title ID `0004000000077E00`、TitleVersion 1024 (1.0.0)。アドレスは展開済み code.bin の仮想アドレス (base `0x100000`)。[解析の入口](analysis.md) / [マップ](map.md)。

確度の表記: **確定** = コードの読み方と実データの両方で確かめた。**コード** = コードで読み方を確かめたが、意味は値から読んだ。**データ** = 実データの形・値・メッセージから読んだ (コードは未確認)。**推定** = 形からの推測。

表の保持体 (master + オフセット) は [analysis.md §3 master](analysis.md#3-master-56562135) の表を参照。この文書で使うのは monsterBattleParameter `+0x508`、monsterAttackSkill `+0x4EC`、monsterGroup `+0x540`、monsterFixGroup `+0x524`、skillData `+0xE0`、conditionData `+0x214`、monsterData (`2713402F`) `+0x498`、directData (`2713402F`) `+0x620`。行は `FUN_0020CBB4(保持体)` で引く。

一覧は `python3 roms/tools/honolulu.py monsters <master> <2713402F>` で出せる ([ツール](../roms/tools/honolulu.py))。

## 1. RPG2 との違い

- 初代の monsterBattleParameter は **ビット詰め** で、この点は RPG2 の MonsterParameter と同じ。ただし行は 0x34 バイト (RPG2 は 0x54) で、欄の位置もビット幅も違う。RPG2 の表の定義を当てない。
- HP・こうげき・ぼうぎょ・すばやさは RPG2 と同じく「2 つの値の間の乱数」。ドロップは 2 枠 (RPG2 は 3 枠)。耐性は 4 bit × 6 と 2 bit × 11 (RPG2 は 5 bit × 25)。
- 名前とモデルは monsterData (`2713402F`) の行で、その行番号を monsterBattleParameter +0x2C が持つ (RPG2 の MonsterDesign +0x4C と同じ役割)。

## 2. monsterBattleParameter (master エントリ 48、111 × 0x34)

読み手は戦闘のモンスターの初期化 `FUN_00205BE8(…, 行, 戦闘の物体, 引き継ぎ)` (確定)。戦闘の物体の +0x88 に行番号、+0x8A に monsterData の行を書く。乱数は `FUN_0020CB5C(乱数, 幅)` で、「2 つの値の小さい方 + 0〜差」になる。

w0〜w12 は +0x00 からの u32 (リトルエンディアン)、ビットは最下位を 0 とする。

### 2.1 monsterData (`2713402F`、92 × 0x2C) の追記

- 既存の記録: +0x00 名前のメッセージ ID、+0x04 / +0x08 `470D2848` のエントリ (モデル / テクスチャ)、+0x0C / +0x10 f32 ([analysis.md](analysis.md#31-表の一覧-データ))。

## 3. monsterAttackSkill (master エントリ 47、233 × 0x24)

モンスターのワザ。`FUN_00204A40` が行を戦闘の「行動」(電波人間の特技と同じ形の作業領域、§4) に写す。

| 位置 | 型 | 内容 | 確度 |
|---|---|---|---|
| +0x00 | u32 | 戦闘メッセージ (2471〜、例 0xA91「〜の　たいあたり！」) | データ |
| +0x04 | u32 | ビット詰め (下の表) | コード |
| +0x08 | f32 | 威力の倍率と推定 (100.0 / 130.0 / 140.0 / 150.0 など) | データ |
| +0x0C / +0x0E | u16 | 量の最小 / 最大 → 行動 +0x0C / +0x0E (§4) | コード |
| +0x12 / +0x14 | u16 | 演出 (directData の行)。使う側の演出。+0x1D bit2-3 が 0 で使い手に条件 (`+0x411` の下位 4 bit) があるとき +0x14 を使う | コード (`FUN_0018B870`) |
| +0x16 / +0x18 | u16 | 演出。相手ごとに出す (`FUN_001F8F14` の種類 1) | コード |
| +0x1A | u16 | 演出。相手ごと (種類 4) | コード |
| +0x1C | u8 | 未解析 (3 / 7 / 8 / 9 / 0xA) | — |
| +0x1D | u8 | bit0-1 → 行動の bit4-5、bit2 → 行動の bit1 (攻撃の形の切り替え)、bit3 → 行動の bit3、bit4 → 行動の bit2 | コード |
| +0x1E | u8 | ×10 して行動 +0x02 か +0x03 (命中率と推定。実データは 0x0A = 100) | コード |
| +0x1F・+0x20 | u8 | 未解析 (+0x20 は `FUN_001E376C`、+0x1F は `FUN_001779D8` が読む) | — |

+0x04 のビット (+0x1D bit2 = 1 のとき、`FUN_00204A40`): bit0-3 → 行動 w4 bit23-26、bit4-8 → 行動 w4 bit18-22 (状態、conditionData の行)、bit9-10 → 行動 w4 bit3-4、bit11-13 → 行動 w4 bit0-2、bit14-17 → 行動 w4 bit5-8、bit18-21 → 行動 w4 bit9-12、bit23 → 行動 +0x01 bit6。+0x1D bit2 = 0 のときは別の写し方 (bit0-3 → 行動 w4 bit28-31 など) をする。(コード)

## 4. skillData (master エントリ 42、152 × 0x28)

電波人間の「アンテナ」の特技。`FUN_00205260` が monsterAttackSkill と同じ形の行動に写す。

| 位置 | 型 | 内容 | 確度 |
|---|---|---|---|
| +0x00 | u32 | 名前のメッセージ ID (0x414〜) | データ |
| +0x04 | u32 | 説明のメッセージ ID | データ |
| +0x08 | u32 | 名前 (+0x00 と同じ値) | データ |
| +0x0C | u32 | ビット詰め: bit0 → 行動 bit2、bit1 → 行動 bit3、bit2-3 → 行動 bit4-5、bit6-9 → 行動 w4 bit23-26、bit10-14 → 行動 w4 bit18-22 (状態)、bit15-16 → 行動 w4 bit3-4、bit17-19 → 行動 w4 bit0-2、bit20-23 → 行動 w4 bit5-8、bit24-27 → 行動 w4 bit9-12 | コード |
| +0x10 | u16 | 小さい値 (3 / 4 / 0x0D / 0x0E / 0x0F / 0x10)。範囲か消費と推定 | データ |
| +0x12 | u16 | 値 (例: かいふく系 3〜25) | データ |
| +0x14 / +0x16 | u16 | 量の最小 / 最大 → 行動 +0x0C / +0x0E (例: ちょっとかいふく 30〜45、ぜんぶかいふく 999) | コード |
| +0x18 / +0x1A | u16 | 演出と推定 (0x1E3〜、0x198〜) | データ |
| +0x20〜+0x27 | | 未解析 (+0x24 u8 は 0〜0x10 の小さい値) | — |

- 行動は 1 バイト目が種類、+0x01 にビット、+0x02 / +0x03 に 100 を基準にした値、+0x04 にビット詰め、+0x0C / +0x0E に量を持つ。量は回復のとき「最小〜最大の乱数」を HP (+0x52) に足し、最大 HP (+0x50) で止める (`FUN_00205104` 付近)。w4 bit18-22 が 0 以外なら conditionData (`+0x214`) の行を引く。(コード)

## 5. 群れ

### 5.1 monsterGroup (master エントリ 46、58 × 0x2E、行の後ろに検索用の追加領域)

表は +0x20 に追加領域を持ち、`{u32 キー, u32 行}` がキーの昇順に並ぶ。群れは行番号ではなくキーで引く (`FUN_00205884`: 追加領域があれば `FUN_0020B44C` でキーから行を探す。引数 0 のときは今のマップの群れ `*0x321C0C` +0x3C8)。キーはダンジョンの階の定義ファイル ([map.md §4](map.md#4-ダンジョンの階の定義-261-ファイル)) にある。(確定)

| 位置 | 型 | 内容 | 確度 |
|---|---|---|---|
| +0x00 + 4k (k = 0〜4) | u16, u8, u8 | 枠 A: monsterBattleParameter の行 / 重み / 未解析 (0・5・10・12 など) | 確定 (行)、コード (重み) |
| +0x14 + 4k (k = 0〜4) | u16, u8, u8 | 枠 B: monsterBattleParameter の行 / u8 / u8 | 確定 (行) |
| +0x28〜+0x2C | u8 × 5 | 型 0〜4 の重み | コード |
| +0x2D | u8 | 型 0 を選んだときの値 | コード |

- `FUN_0025D174`: +0x28〜+0x2C の重みで型を 1 つ選び (重みの合計が 0 なら型なし)、型 0 なら +0x2D を、型 1〜4 なら `FUN_0016A80C` で枠 A から重み (+2) で 1 体を選ぶ。型の意味 (出てくる数と推定) は未確認。(コード)
- `FUN_00204C70`: 枠 A と枠 B の行のうち、monsterData +0x2A が引数以下のものから乱数で 1 体を選ぶ (フィールドに出す見た目の敵と推定)。(コード)
- 実データの例: 行 1 = きばコウモリ・ぶたばなウサギ (重み 1 ずつ)、型 1 だけ。行 3 = きばコウモリ・ぶたばなウサギ・もろこしおばけ、型の重み [1, 1, 2, 0, 0]。

### 5.2 monsterFixGroup (master エントリ 45、24 × 0x16)

- +0x00 + 4k (k = 0〜4): u16 monsterBattleParameter の行 + 詰め物 (`00 D0`)。+0x14 u8 は行 0 だけ 1。(データ)
- ボス戦の固定の組と推定。例: 行 1 = 4 ウルフベア、行 9 = 71 フレイムボウ・70 パワーせんし・71 フレイムボウ。どこから引くかは未確認。
