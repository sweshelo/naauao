# 電波人間のRPG (honolulu): ショップ

対象: 日本版 Base Title ID `0004000000077E00`、TitleVersion 1024 (1.0.0)。アドレスは展開済み code.bin の仮想アドレス (base `0x100000`)。[解析の入口](analysis.md)。

## 1. 仕組み

- 店はデンパ島のショップ 1 軒だけ。RPG2 の「店 ID ごとの品揃え」(ShopItem の店 ID 0〜17、[kahara/shops.md](../kahara/shops.md)) はない。
- 品揃えは **段階** (shopItemGroup の行、12 段階) ごとに丸ごと持ち、ダンジョンの進み具合で段階が切り替わる。前の段階の品物も新しい段階の一覧にもう一度並ぶ (段階の一覧がその時点の品揃えのすべて)。(確定)
- 店員のメッセージ (いらっしゃい・どうする・数の入力・売るときの確認など) は固定のメッセージ番号 (116〜149) で、店ごとの設定の行はない。(データ)

## 2. 表

### 2.1 shopItemGroup (master エントリ 69、12 × 0xC、保持体 master +0x5E8)

| 位置 | 型 | 内容 |
|---|---|---|
| +0x00 | u16 | この段階の品揃えの最初の行 (shopItemData) |
| +0x02 | u16 | 最後の行 (この行を含む) |
| +0x04 | u16 | ダンジョン (dungeonData の行、1〜11)。0 = 最初の段階 |
| +0x06 | u16 | そのダンジョンの進み具合の値 |
| +0x08 | u16 | 前の段階の最初の行 (= 前の行の +0x00) |
| +0x0A | u16 | 前の段階の最後の行 (= 前の行の +0x02) |

### 2.2 shopItemData (master エントリ 68、753 × 4、保持体 master +0x5CC)

| 位置 | 型 | 内容 |
|---|---|---|
| +0x00 | u16 | アイテム (itemData の行) |
| +0x02 | u8 | bit0: 目玉の品 (§3) |
| +0x03 | u8 | 0xD0 (詰め物) |

## 3. 段階の選び方とあいさつ

- **今の段階** (`FUN_00230074`、店の一覧を作る): 段階 0〜11 を順に見て、`進み具合(+0x04) == +0x06` を満たす最後の段階を使う。どれも満たさなければ段階 0。進み具合は `FUN_00202728(ダンジョン)` で、セーブ変数 0x40 のダンジョン − 1 番目の値 (ダンジョン 1〜13、それ以外は 0)。(確定)
  - 一覧は +0x08〜+0x0A (前の段階) の行を読んでから +0x00〜+0x02 の行を読む。前の段階の品はスタックの一覧 (12 バイト × 最大 298、`sp+0`〜`sp+0xDF8`) に入り、今の段階の品ごとに「前の段階にないアイテムか」を比べて一覧のエントリの +0x06 に持つ (新しく並んだ品の印。画面での出方は未確認)。(確定)
  - 行の範囲のループは `cmp first, last; bgt` (符号付き)。last < first の段階は品物なしになる。first = 0 で last = 0xFFFF にすると 65536 行を読むので、空の段階を行 0 に置くときは [1, 0] と書く。(コード)
  - 一覧は店の物体 (r0 = `sl`) に 12 バイトずつ書く: すべての品 `+0x64` (+0x00 itemData の行へのポインタ、+0x04 目玉の bit、+0x06 前の段階にないと 1、+0x08 itemData の行番号)、目玉の品 `+0xE5C`、装備 (分類 3) `+0x10B4`、ふく (分類 4) `+0x17B0`。次の欄 (`+0x1FB0` 今の段階) までの大きさから、1 段階に並べられるのは **品数 298・目玉の品 50・装備 149・ふく 170** まで (推定。超えると後ろの一覧と段階の番号を壊す)。ROM の最大は段階 11 の 137 品・目玉 21。(コード)
- **入荷の知らせ** (`FUN_001BD0xx`、`FUN_002580xx`): 段階が変わったとき、新しい段階の行に +0x02 bit0 の品があればフラグ 0x27 を立てる。(確定)
- **あいさつ** (店の画面の初期化 `FUN_002C7B18`): フラグ 0x0F が立っていなければ立てて 131「よく来た、いらっしゃい、ショップ、始めた。…」。立っていてフラグ 0x27 が立っていれば 135「タイミングいいな。良い物、入ってる。」にしてフラグ 0x27 を下ろす。それ以外は 133「いらっしゃい。」。(確定)
- bit0 の品と、メッセージ 143「今だけ、売ってる、後で、売らない。買うなら、今！」の関係は未確認。bit0 の品は後の段階に並ばないことがある (例: 段階 1 の ひのうでわ は段階 2〜4 になく、段階 5 でまた bit0 で並ぶ)。

## 5. MOD・エディタの制約 (推定)

- 段階の数 12 はコードに固定 (`cmp r4, #0xc`)。段階を増やすにはコードの変更が要る。
- 段階の品揃えは shopItemData の連続した行なので、品数を変えると後ろの段階の +0x00〜+0x0A をずらす必要がある (RPG FREE! の Shop と同じ事情。[lanai/shops.md](../lanai/shops.md))。
- 1 段階の品揃えの上限は §3 の一覧の大きさ (品数 298・目玉 50・装備 149・ふく 170、推定)。shopItemData の行数そのものの上限は未確認。
- Panana (sweshelo/panana#153) は品数を変えると全段階を並べ直し、+0x00/+0x02/+0x08/+0x0A を付け直す (段階 0 の +0x08/+0x0A は ROM と同じく自分自身)。
