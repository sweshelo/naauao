# lanai (電波人間のRPG FREE!) のアイテム: 表・説明文・モデル

対象: Base v0 + Update v17408。アドレスは Update の code.bin (0x100000 起点)。表の置き場 `*0x004EAE44` (マスターのオブジェクト) の中のホルダーは 0x28 間隔で、`FUN_0031C038(ホルダー + 4, 行)` で行を引く ([analysis.md §2](analysis.md#2-gs-テーブル-lanai-形式確定))。

確度: **確定** = 読むコードを特定し、データとも合う。**推定** = コードかデータの片方だけ、または意味づけが推測。**未確認** = 観測値だけ。

## 2. アイテム ID と引き方 (確定)

- **アイテム ID = ItemData の行 ID** (`0x80000000 | n`)。モンスターのドロップ (能力の表 +0x0C〜+0x18)、コード入力、メッセージのタグ 0x37 (`ItemData`, ID, `name`) は、どれもこの ID を使う。
- **`FUN_003141EC(ID)` = ItemDataCore の行**:
  1. ItemData (+0x1A40) の行を ID で引く。その行の +0x0C (u16) が 0 なら、ID を 0 とみなす。
  2. ItemData の行 (ID) の **+0x0C (u16) を ItemDataCore (+0x1A68) の行番号**として引く。
  - 109 か所から呼ばれる。ItemDataCore の欄はすべてここを通して読まれる。
- `FUN_00311E4C(ID)` は、ItemData +0x0C が 0 なら 1 (無効・空) を返す。
- **所持数** (`FUN_00312B4C` / `FUN_00312C00`):
  - 番号 (ID & 0x7FFFFFFF) が **3000 (0xBB8) 未満**ならセーブの値 0x1D / 0x1E の番号の欄。
  - 3000 以上なら、値 0x5C の (番号 − 3000) の欄。
  - 書くときは 99 で頭打ち (`cmp #0x63; movhi`)。
  - 番号 3000 以上の ID は 0xBB8〜0xF16 の範囲に実在する。ID を新しく足すときの上限は未確認。
- **所持の上限** = ItemDataCore +0x34 (u8)。ほぼすべて 99 (`FUN_001BDC40` で比べて切り詰める)。

### 説明文の引き方 (`FUN_001BED90`、確定)

1. Core +0x28 が 0 なら説明なし。
2. +0x38 が 1 なら 2 つ目 (+0x1AB8)、2 なら 3 つ目 (+0x1AE0)、それ以外は 1 つ目 (+0x1A90) の MessageItemFlavor から +0x28 の行 ID を引く。
3. 見つからなければ 3 つの表を順に探す。

1 つ目と 2 つ目の表は ID の範囲が重なる (0x11E〜0x22A) ので、+0x38 で区別する。

### 入手演出 `FUN_002B9A94(ID, &arc, &entry, &scale, &rot, &pos, 変種)` (確定)

1. 大分類 (`FUN_002F4D8C`) が **0xD0 (ふく)** なら `90100000:71417400` (`item_03.bch`、体の形のモデルにテクスチャ `hum_base`)。

### どのアーカイブでもよいか (推定・強い)

- **コードはアーカイブの値をそのまま読み込みに渡す**:
  - 決まった一覧との照合はない。`0x96EB0000`・`0xD4270000`・`0x025A0000` などの即値はコードにほとんどなく、ある箇所は代わりのモデルや別の物の直書き。
  - `FUN_002EDA68` はアーカイブの値を `FUN_00322B80` (`xxxx000A` の言語の解決) に通すだけ。
- **データでも、Base だけのアーカイブと Update だけのアーカイブが混ざって使われている**:
  - Update の patchList にないもの (`96EB0000`・`D4270000`・`980C0000`)。
  - Update で足されたもの (`F0F40000`・`025A0000`)。
  - Update で差し替えられたもの (`1B270000`・`DC540000`・`90100000`)。
  - したがって `rom:` / `patch:` の切り替えは、アーカイブの名前ごとに読み込みの層が行う (RPG3 と同じ patchList 方式と推定。lanai の path 組み立て `rom:/FFFFFFFF` / `patch:/FFFFFFFF` (`0x4EB8E4` / `0x4EB8F3`) の参照元は未確認)。
- **モデルを差し替える手順**:
  - 既存のアーカイブ (`F0F40000`・`1B270000`・`719F0000` など。どれも Update の patchList にある) に **type 4・ZIP (comp 1)** のエントリとして BCH を足す。
  - 足したら、Core +0x18 にそのアーカイブ、+0x1C にエントリのハッシュを書く。
  - **719F0000 (モンスター用) に入れても読める**と推定する。読み込みはアーカイブの種類を区別しないため。
  - エントリのハッシュは下位 8 ビットが 0 で、そのアーカイブの中で重ならない値にする ([共通: モデル §7](../common/models.md#7-エントリのハッシュ))。
  - 新しいルートのアーカイブを作るときは、patchList に載せるか Base の RomFS に置く必要がある (推定)。
- 例外の扱い (確定): 種類 0x67 / 0x68 / 0xDx は入手演出で決まった代わりのモデルを使う (上)。モデルを差し替えても入手演出の見た目は変わらない。

## 7. 一覧のページを作るための要点

- 1 行 = ItemData の 1 行 (ID 順)。+0x0C = 0 の行は飛ばす。
- 名前は ItemData `name`。色違いは +0x08 の ColorData の名前を足して表示するのがよい。
- 説明は Core +0x28 / +0x38 → MessageItemFlavor (`3A08000A`)。
- 種類は +0x32、レア度は +0x33 & 0xF。値段は +0x04 / +0x08 (推定)。
- モデルは +0x18 / +0x1C。表示の参考の大きさ・回転は RaregetParameter (+0x24)。
- 種類 0xDx と 0x67 / 0x68 はテクスチャだけの BCH なので、プレビューは代わりのモデル (`90100000:71417400` / `1B270000:F0E3C800`) にテクスチャを貼る形になる。

- ItemDataCore の +0x14・+0x2E・+0x30・+0x31・+0x35・+0x36 / +0x37 の意味。+0x04 / +0x08 が店の買値・売値であることは、店の画面のコードで未確認。

- PreviewParameter の欄の意味 (+0x00 と 2 組の座標) と、使う画面 (フラグ `0x004EB294`)。
