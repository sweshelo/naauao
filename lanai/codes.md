# コード入力

対象: lanai Update v17408 の code.bin。タイトル画面の「せってい」→「コード入力」。参照実装は同梱の [lanaicode.py](../roms/tools/lanaicode.py)。

## 1. 入力 (確定)
- ソフトウェアキーボードで **16 文字**。使える文字は `0-9 a-z A-Z` で、ほかの文字があると「入力されたコードの中に使用できない文字が含まれています。」(`FUN_003D61F8`)。
- 小文字は大文字に直す (`FUN_001B5908`)。
- 入力画面には 3 つの使い方があり、それぞれ別の「コードの種類ごとの作り手」を使う (`FUN_003D34EC`)。

| 使い方 | 作り手 (vtable) | クラス |
|---|---|---|
| 通常のコード入力 | `0x4D2A3C` | `CampaignCode` |
| 「サポートより発行されたコードの入力を開始しますか？」 | `0x4D296C` | `SupportCode` |
| 前回の処理が途中で終わったときの再入力 (「前回と同じコードを入力してください」) | `0x4D49C0` | `CodeUniqueRestore` |

## 2. 16 文字 → 10 バイト (確定)

デコードは `FUN_001B53D4`。

1. 各文字を **CampaignCharacter** (`7BF7000A`、32 行) の行番号 = 5 ビットの値にする。並び順は `C341PV0BTXLJYKM8FDHRQ7GNAEW6U592` (1 文字目が 0)。表にない文字は失敗。
2. 16 × 5 = 80 ビットを、1 文字目の最上位ビットから順に 10 バイトに詰める (ビッグエンディアン)。
3. 撹拌を戻す。次の順に、リトルエンディアンで読んで書き戻す (+4 と +6 は重なる)。
   - `+6` の u32
   - `+0` の u32
   - `+4` の u32
   - `+8` の u16

   | 幅 | 変換 |
   |---|---|
   | u32 | `x = x × 0x43BD527F`、ビット順を反転、`x = x × 0x950C6D7F` (mod 2³²) |
   | u16 | `x = x × 0x9FA5`、16 ビットの反転、`x = x × 0x302D` (mod 2¹⁶) |

   乗数がすべて奇数なので逆にできる (コードを作るときは逆順に逆元を掛ける)。

## 3. 10 バイトの中身 (確定)

| バイト | 内容 |
|---|---|
| 0〜3 (u32 LE) | ビット 0〜9 = 版の 2 番目、ビット 10〜23 = 版の 3 番目、**ビット 24〜31 (= バイト 3) = チェックの値** |
| 4 | ビット 0〜1 = **コードの種類**、ビット 2〜7 = 版の 1 番目 |
| 5〜8 (u32 LE) | 中身 (種類ごと) |
| 9 | 中身の追加の 1 バイト |

- **チェック**: `SHA-256(バイト 5〜9)` の先頭 1 バイトが、バイト 3 と同じでないと「入力されたコードが間違っています。」。
- **版**: `(1 番目 × 1000 + 2 番目) << 16 | 3 番目` が、ソフトの版 (`*0x4EB01C` の +0x48 / +0x4C を同じ式にしたもの) より大きいと「ソフトのバージョンが古い為…チェックインをして、更新してください。」(`0x80000403`)。

### 3.1 種類 (確定)

| 種類 | 通常のコード入力 | サポートのコード入力 |
|---|---|---|
| 0 | `CodeCommon` を作る (§4) | 「サポート発行の物ではありません」 |
| 1 | 「有効期限が切れています」 | 「サポート発行の物ではありません」 |
| 2 | 「サポート専用です」 | `CodeSystemAction` を作る (§5) |
| 3 | 「コードが間違っています」 | 「コードが間違っています」 |

## 4. 種類 0: ROM の中の表のコード (CodeCommon)

- 中身 (バイト 5〜8) = **CampaignCodeLocal (`7BF7000A`、50 行 × 0x58) の行番号**。バイト 9 は 0 でないといけない。
- 行番号が表の行数以上なら「コードが間違っています」。
- 行の条件と報酬の形は、チェックインの表と共通 ([checkin.md §5.1](checkin.md#51-行の形-配信の報酬の構造))。この表だけ +0x34 に「条件に合わないときのメッセージ」がある。
- **使用済みの記録**:
  - FlagData のキー 0x67 のビット [行番号]
  - 行の +0x54 (u16、0xFFFF = なし) が指すキー 0x27 のビット (まとまりごと)

  どちらかが立っていると「このコードは既に使用されています。」。
- 例 (確定): **`A4J8Y13ML7TAWWE1`** (公式に案内されたとされるサービス終了後のコード) は、種類 0・版 1.17.0・行 49。行 49 は報酬の種類 0x08、値 0x2A4 で、**スイッチ 0x51[0x2A4] (サービス終了モード) を立てる** ([checkin.md §6](checkin.md#6-サービス終了後のオフラインチェックイン))。`lanaicode.py enc 0 49 0 1.17.0` で同じ 16 文字が作れることを確認した。
- コードは行番号と版だけで決まるので、**表の行を足せば新しいコードが作れる**。ただし表を変えると Update の内容が変わる。

### 4.1 CampaignCodeLocal の中身 (要約)
- 見出しの行 (メッセージつき) と報酬の行が交互に並ぶ。
- 報酬は主に次の 2 つ。
  - Miiverse のフォロワー記念のジュエル (種類 0x01)
  - 記念アイテム (種類 0x02、例 `0x80000234`)
- 種類 0x17 の行もある (電波人間と推定)。
- 行 49 が終了告知 + サービス終了モード。

## 5. 種類 2: サポートのコード (CodeSystemAction)

セーブデータの異常を直すための、オペレーター専用のコード。入力画面の文言は「サポートより発行されたコードの入力を開始しますか？　その他のコードは受け付けませんので…」。

- 中身の 5 バイト `p[0..4]` (`FUN_00217B4C`) は次のとおり。
  - 操作の番号: `p[1]`
  - 引数: `p[2]` と `p[3]`
  - 16 ビットの値: `p[0] | p[4] << 8`
- 操作の番号は 1〜12。0 と 13 以上は「コードが間違っています」(`FUN_00217A0C`)。操作ごとに `FUN_001CFFF0` / `FUN_001CF878` / `FUN_001CF958` / `FUN_001CF70C` / `FUN_001CFB28` / `FUN_001CFF08` / `FUN_001CFF90` / `FUN_001D0130` (8〜12) へ進む。
- 実行の条件 (`FUN_002178FC`): ゲームが「異常を検知した」状態 (`*0x4EB01C` の +5 が 1) か、操作が 1 または 6 のとき。それ以外は、異常の種類 (TYPE-<num>) ごとのメッセージを出して終わる。
- `FUN_001CF70C` などは引数を本体の値と比べて、合わなければ「入力されたコードは取扱いできません。サポート番号をご確認ください。」。サポート番号 (サポート ID) と結び付けて、ほかの人のセーブでは使えないようにしていると推定。
- 各操作の中身 (何を直すか) は未解析。

## 6. ネットワークのコード (CodeUnique、未解析)

- `CodeUnique` (vtable `0x4D1CB0`、作成 `FUN_0017C648`)、`network::CampaignCodeUnique`、表 CampaignCodeNetwork (137 行 × 0x58、`message` +0x38) がある。
- campaigncodeserver に `req=res` / `req=sre` を送る ([checkin.md §4](checkin.md#4-その他のサーバー))。1 回だけ使えるコードをサーバーで照会・記録したと推定。
- `CodeUniqueRestore` は、通信が途中で終わったコードの再処理と推定。
- どの種類・中身のコードが CodeUnique になるかは未確認。
