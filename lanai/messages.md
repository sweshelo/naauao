# lanai (電波人間のRPG FREE!) のメッセージと「電波人間の性格」による出し分け

対象: lanai Base v0 + Update v17408。表の形式は [analysis.md §2](analysis.md#2-gs-テーブル-lanai-形式確定)、ステージは [contents.md](contents.md)。
調査日 2026-10-11。方法は、実データ (CIA を `src/lanai/` の読み取りで開いた) の統計と、code.bin の逆アセンブル (capstone)。

確度の凡例: **確定** = 実データの全件で成り立つ。**推定** = 一部の根拠 (意味の一致、コードの読み取り) のみ。**未確認** = 分かっていない。

## 0. 先に結論

- 性格ごとの出し分けは、**タグではなく「行」で行う**。タグ (0x22 改ページ、0x37 差し込みなど) に性格を示すものはない (確定)。
- メッセージ表の行 (12 バイト) は `message` (+0x00)、`voice` (+0x04)、**話者の種別 u8 (+0x08)** を持つ。+0x08 が 1〜8 の行は、**「同じ台詞を 8 通りの口調で言い直した 8 行」の組**の一部になる (確定)。
- 8 通りの口調は、**1 = ストーリー専用の主人公 (「ボク」口調)** と、**2〜8 = 性格 0〜6 (ノーマル / クール / あらくれ / こども / オネエ / いばり / やさぐれ) の 7 種** (性格 → 口調の対応は推定。§3)。
- 電波人間の性格は 7 種 (0〜6) で、個体の +0x77 に入る。見た目の部品から決まる (DenpaPersonality の加点の合計)。DenpaCustom の +0x42 が 0〜6 ならその値、0xFF なら見た目から決める (推定)。
- oahu (RPG3) / kahara (RPG2) には、性格ごとの台詞の出し分けは**ない**。あるのは「メッセージごとの声タグ (č ď Ď)」と「店ごとの口調の組」だけ。lanai は仕組みが違うので、「oahu と同じ」という仮定は**外れ**た (§6)。

## 1. メッセージ表の行 (確定)

12 バイトの行を持つ「メッセージ表」(`MessageContents`、`d01_msg` / `s01_msg` / `m01_msg` などの `*_msg`、`MessageNagomiFriend`、`MessageNagomiTower`、`MessageTalk*`、`MessageQuiz`) 共通。

| off | 型 | 内容 |
|---|---|---|
| +0x00 | 文字列 | `message` (本文。UTF-16LE、タグは analysis.md §2.2) |
| +0x04 | 文字列 | `voice` (音声合成用の読み。1 バイトの文字列で、本文とは別のバイナリ。後述) |
| **+0x08** | **u8** | **話者の種別 (声の ID)**。+0x09〜+0x0B は 0xD0 の詰め物 |

- 行 ID は `0x80000000 | 番号`。ゲームは行 ID から行を引く。
- **`voice` があるのは +0x08 が 1〜0x0F の行だけ** (1〜8: 約 5,800 行のほぼ全部、0x0A / 0x0B / 0x0C / 0x0E: 全部、0x0F: 一部)。0x10〜0x16 と 0 の行は `voice` が空。つまり音声 (合成) が付くのは性格口調の行と固有名のキャラクターで、一般の NPC は付かない (確定)。
- 先頭行 (行 ID `0x80000000`) は「なし」や「ダミー」で、+0x08 は 0。

### 1.1 +0x08 の値 (全メッセージ表を数えた)

| 値 | 意味 | 確度 |
|---|---|---|
| 0 | 話者なし (地の文、システム、ダミー) | 確定 |
| 1〜8 | **主人公 / 先頭の電波人間の口調 (性格による出し分け)**。§2〜§3 | 確定 (意味は §3) |
| 0x0A / 0x0B / 0x0C / 0x0E | 固有名のキャラクターの声 (あかり、子供 1、子供 2、引退した女性冒険者など)。例: コンテンツ 17 の「はじめまして、私は『あかり』です」が 0x0A、コンテンツ 70 の「ぐすん、ぐすん…」が 0x0C | 推定 |
| 0x0F | 店員の一部 (敬語) | 推定 |
| 0x10〜0x16 | 一般の NPC の口調の分類 (0x10 / 0x11 は店員・窓口、0x12 は一般の丁寧語で最多、0x13 は女性、0x14 は男性のぶっきらぼう、0x15 は地底人の片言 (「…した　ほうが　いい」のように文節を空ける)、0x16 は敵・ボス) | 推定 |

(DenpaCustom の +0x42 が 101〜105 のキャラクターは あかり=101、テル=102、ルナ=103、みちる=104、ひのわ=105。0x0A〜0x0E との対応は 101→0x0A… の順と推定するが、確かめていない。)

## 2. 8 通りの言い直しの組 (確定)

- 全メッセージ表 (Nagomi 系を除く) で、**+0x08 が 1,2,3,…,8 と並ぶ連続した 8 行**の組が **727 組**ある。性格の値を持つ全 5,934 行のうち 5,816 行 (98%) がこの組。ほかは、1 行だけの 4 (あらくれ口調の固定キャラクター、62 行)・1 (主人公、26 行)、2〜8 の 1 行ずつ (コロシアムの対戦相手、§5) など。
- **8 行は表の中で物理的に連続**している。行 ID は次の 2 通り (どちらも組の中の順序は 1→8):
  - 588 組: 8 行の行 ID が連続 (`x, x+1, … x+7`)。
  - 139 組: **1 番目 (主人公) の行 ID だけ小さく**、2〜8 番目は別の範囲で連続 (例 `0x02 | 0x1E…0x24`、`0x57 | 0x9A…0xA0`)。後から性格違いを足した名残と見られる。行 ID の連続性は当てにできない。
- コンテンツのスクリプト (CRO) が埋め込んでいる行 ID は、組のうち **1 番目の行 ID が圧倒的** (組のうち CRO に ID が 1 つだけ出る 270 組中 212 組が 1 番目)。スクリプトは「組の代表の行 ID」を渡し、**ゲームが先頭の電波人間の性格で、同じ組の中の行を選ぶ**と推定する。物理的な行の並びを使うのか (代表の行 + 口調 − 1)、ほかの方法かは未確認 (§8)。
- 組の中で、`{ins:…}` の差し込み (地名、モンスター名) や改ページ `{page}` は 8 行とも同じ位置に入る。性格だけが違う。

## 3. 8 通りの口調と電波人間の性格 (性格の名称・ID)

### 3.1 性格は 7 種、口調は 8 種

| 口調 (+0x08) | 性格名 | 性格の値 | 口調の特徴 (実データ) |
|---|---|---|---|
| 1 | (ストーリー専用の主人公) | 100? (推定) | 「ボク」「〜だよ」「〜かな」。少年。 |
| 2 | ノーマル | 0 | 「〜ですね」「〜ましょう」。明るい丁寧語。 |
| 3 | クール | 1 | 「〜ですね」「〜ですよ」。落ち着いた・几帳面な丁寧語 (「お待ちください」「参りたい」)。 |
| 4 | あらくれ | 2 | 「俺」「〜だぜ」「〜だな」「ちょい待ち」。荒っぽい男。 |
| 5 | こども | 3 | 「僕」「〜だよ」「〜の？」「〜だね」。子供。 |
| 6 | オネエ | 4 | 「アタシ」「〜わ」「〜のね」「〜かしら」。 |
| 7 | いばり | 5 | 「〜たまえ」「〜のだよ」「〜かね」。尊大。 |
| 8 | やさぐれ | 6 | 「〜ですよ」「〜ですねえ」「やれやれ」。やる気のない敬語。 |

- **性格の名称と値 (確定)**: master の `DenpaCustom` (209 行 × 0x50) の **行 106〜112 の名前**が「ノーマル」「クール」「あらくれ」「こども」「オネエ」「いばり」「やさぐれ」で、**+0x42 の u8 が 0〜6 の順**。ほかの個体 (ここ / さな / ゆら / ちせ / ふう / さら / もか、しょう / あおい / まこと … など 0〜6 を 7 人 1 組にした行) も +0x42 が 0〜6 の順。性格の名称はゲーム内の文字列として見つかったのは DenpaCustom の名前のみ (「性格」という語の表は無い)。名称は DenpaCustom の行名 (推定: プリセットの名前をそのまま性格名としている)。
- **口調 = 性格 + 2 (推定、根拠が強い)**:
  - 4〜8 の口調は、性格あらくれ〜やさぐれの名前とセリフの口調が一致する (あらくれ=「俺」、こども=「僕」、オネエ=「アタシ」、いばり=「たまえ」、やさぐれ=「やれやれ」)。
  - コンテンツ 73 (電波人間コロシアム) は、対戦相手のチームを 7 つの性格で作り、`ScriptPlayer::GetPersonality` を使う CRO で台詞を出し分ける。その台詞は +0x08 が **2〜8 の 7 行だけ**で、1 は無い。
  - 1 は、ストーリーの主人公「ボク」(最初に仲間になる少年) が先頭のとき専用。コンテンツ 0 では 1 の行にだけ「ボクは、電波のまわりに漂っている電波人間という種族なんだ」のような固有の台詞が続き、2〜8 は「先頭の電波人間」の汎用の言い直しになっている。
  - 「性格 + 1」だと、あらくれが 3 (丁寧語)、いばりが 6 (オネエ) になり、口調が合わない。
- **主人公 (口調 1) の性格の値**: DenpaCustom の +0x42 は 0〜6 のほか、**100〜105** (あかり 101、テル 102、ルナ 103、みちる 104、ひのわ 105) と、0xFF (137 行。見た目から決める) がある。code.bin に 0x64〜0x69 (100〜105) を特別扱いする比較がある (個体の同一判定)。主人公が 100 かどうかは未確認。
- 口調 8 が `voice` を持つこと、DenpaCustom の「ジニアスくん」など +0x42 が 0xFF の行のことは §1・§8。

### 3.2 性格が個体のどこに入るか (推定)

- 個体 (電波人間のユニット) の **+0x77** (u8) が性格。DenpaCustom から個体を作る関数 (Update `0x2DE480` 付近) が、DenpaCustom 行の +0x42 を読み、0xFF でなければ +0x77 に書き、0xFF なら見た目から決める関数 (`0x2A1810`) を呼ぶ。
- 見た目から決める計算 (`0x2A1A74`): 頭・顔・髪・体など 6 つの部品の番号で `DenpaPersonality` (417 行 × 0x10) を引き、**各行の +2〜+8 の符号付き 1 バイト 7 個 (性格 0〜6 の加点)** を足し、最大の性格を選ぶ。同点は先の性格を優先 (推定)。部品の分類は 0x00 / 0x40 / 0x80 / 0xC0 / 0xE0 / 0x118 の行番号の範囲 (推定)。個体の +0x76 下位 4 ビットの値によっては、候補から外れる性格がある (詳細は未確認)。
- ゲーム内の文言「性格ってなんとなく顔に出ますよね。」(MessageNagomiFriend) と一致する。
- `DenpaPersonality` の +0x00 (u16: 0x416f 等) と +0x09〜+0x0F の 7 バイトの意味は未確認。
- スクリプトからは `ScriptFlag::GetPersonality` / `ScriptPlayer::GetPersonality` で取る (これを使う CRO は、コンテンツ 0、16、70、73 の 4 つだけ)。ほかの場面は、メッセージを開く関数 (`ScriptMenu::StartMessageHero` / `PlayMessageHero` / `PlayMessageAndCloseHero` / `PlayMessageAsyncHero`。`...Auto` / 無印のものもある) の中で、先頭の電波人間の性格を使うと推定する。Hero 付きと無印・Auto の違いは未確認。

## 4. 「なごみ」の雑談 (MessageNagomiFriend / MessageNagomiTower)

同じ +0x08 (1〜8) を使うが、**ストーリーのような 8 行の組ではなく、口調ごとのまとまり**になっている。

| 表 | 行 | 内容 |
|---|---|---|
| MessageNagomiFriend (FE74000A:3503C000) | 2117 | 口調 1〜8 の雑談 (各 163 / 327 / 290 / 288 / 264 / 268 / 245 / 271 行)、行 0 のみ 0x0F |
| MessageNagomiFriend (FE74000A:524B3C00) | 360 | 家で話す雑談 (各 39 / 51 / 47 / 44 / 43 / 42 / 44 / 50 行) |
| MessageNagomiTower (FE74000A:E452FC00) | 751 | 塔で出会う電波人間の台詞 (各 80 / 103 / 82 / 95 / 96 / 101 / 97 / 96 行) |

- 口調ごとに物理的に固まっている場合 (2 の雑談は行 1〜、前半) と、8 行の組になっている場合 (後半、行 ID が不連続な組を含む) が混ざる。雑談は、なごみに住む友達の性格の口調の行から選ぶと推定 (選び方は未確認)。
- 口調 1 の行は雑談にもある (「強くなったら、どんなとこにでも行けるよね。君はどこか行きたいところある？」)。雑談の「相手」にも口調 1 (ボク) があるので、**口調 1 = 主人公専用ではなく、「ボク」の少年の声が 1 つの声として存在する**ともいえる。主人公専用という説明は、ストーリーの用途に限った推定。
- 口調 2 の例: 「いいおてんきですね。」/ 3: 「冒険に行く前に行先にあわせてしっかり準備してくださいね。」/ 4: 「たくさん仲間を増やしてさわごうぜ。」/ 5: 「どこかつれてってくれる？」/ 6: 「出会いは外にあるのよー。」/ 7: 「どうしてもというなら私が手を貸してあげようじゃないか。」/ 8: 「あまり人が増えてもうるさいですよね。」

## 7. ステージ → MessageContents の参照関係

- ステージ (MapStageIntegration の行) → +0x34 の**コンテンツ番号** → master `Contents` の行 → コンテンツのアーカイブ (`59B00000` など)。
- コンテンツのアーカイブには**メッセージ表が 1〜数個**ある。
  - **`MessageContents`**: エントリのハッシュは全コンテンツ共通で `35676C00`。TableResource (26 行の読み込み表) の 21 番目 (索引 20) に載っている。127 コンテンツすべてにある。行数はコンテンツで 2〜485。
  - **`d01_msg` (`f7638800`) / `s01_msg` (`99c3ac00`) / `d02_msg` / `d04_msg` / `d07_msg` / `f01_msg` / `w01_msg` / `s01outf01_msg`**: マップごとの会話 (名前が「マップ名 + _msg」)。コンテンツ 0 だけ `m01_msg` (896 行)。これらは TableResource に載っていない (マップのイベントの読み込みで読む。未確認)。
  - **`MessageQuiz`** (コンテンツ 75、810 行): クイズ。+0x08 は全部 0x12。
- 行が少ない (MessageContents が 2 行) ステージは、会話が `d01_msg` などにあるだけで、MessageContents は「なし」とテスト用文言 (+0x08 = 0 と 0x12)。会話が MessageContents にあるコンテンツ (12、16〜20、76〜79、81、85〜109 など) もある。
- **どの CRO がどの行 ID を使うか**: CRO 内に行 ID (`0x8000xxxx`) の定数が埋め込まれている (性格の組では、代表の 1 行の ID。§2)。`GSmessage::DbMessageParam` と `ScriptMenu::StartMessage*` / `PlayMessage*` に ID を渡す。引数の渡し方 (どの表を引くか) は未解析。
- 性格を使う箇所の数 (727 組) のうち、組の多いコンテンツ: 0 (島・町、83 組)、124 (ダークネスじーさん、46 組)、4 (ウッキー、36 組)、13 (ドラゴンの里、32 組)、58 (幻帝のどうくつ、27 組)、109 (30.決着の地の獄、27 組)、94 (幻帝のどうくつ 真、25 組)、16 (23 組)、18 / 19 / 20 (15 / 12 / 14 組)。試練・ゲットもの (コンテンツ 34〜57) は組が 0〜1 で、ほぼ性格違いが無い。

### 7.1 代表例 (組の 1〜8)

## 8. 編集 UI が扱うデータ構造 (提案)

- **一覧の単位は「行」でなく「話者グループ」**にする:
  - 行 (message / voice / +0x08) を、+0x08 が 1,2,…,8 と並ぶ**連続する 8 行を 1 つの「性格違いの組」**に束ねて表示する。組の代表は 1 番目の行 (行 ID はこれを使う)。
  - 組を作る条件は「物理的に連続していて +0x08 が 1..8」。行 ID の連続性は条件にしない (139 組で不連続)。
  - 組にならない +0x08 = 1〜8 の行 (コロシアムの 2〜8 など) は、1 行ずつの「性格付き 1 行」として表示する。
- **編集する単位は 8 行の本文 (message) ×8**。8 欄を縦または横に並べ、口調のラベルを付ける (1 主人公 / 2 ノーマル / 3 クール / 4 あらくれ / 5 こども / 6 オネエ / 7 いばり / 8 やさぐれ)。差し込み `{ins:…}` と `{page}` の位置は 8 行で揃える (差分の警告があると良い)。
- `voice` 欄は 1 バイトの文字列で、本文を直すと読みが合わなくなる。編集 UI は触らず**そのまま保持**し、本文を変えた行では警告を出すか、(RPG2 の panana と同じく) 空にする選択肢を持つ (音声合成の読みの形式は未解析)。
- +0x08 は選択式 (0 話者なし / 1〜8 口調 / 0x0A 〜 固有名 / 0x0F〜0x16 NPC) にし、「1〜8 を選ぶと、組の整合 (連続する 8 行) が崩れる」旨を警告する。行を足すときは**組ごと (8 行) 足す**操作を用意する。
- 行の追加・削除で行の位置が変わる (物理的な連続を使うので)。行 ID は変えず、表の中で行を動かさないか、組の位置を保って書き戻す。
- 一覧のフィルタ: 「性格付きの組のみ」「NPC (0x10〜0x16) のみ」「話者なし」。コンテンツの階層は、コンテンツ → メッセージ表 (`MessageContents`、`*_msg`) → 組 / 行。
- 検索は 8 行すべての本文を対象にして、ヒットした口調を示す。
