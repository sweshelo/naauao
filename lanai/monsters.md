# lanai (電波人間のRPG FREE!) のモンスター: パラメータ・耐性・変身

対象: Base v0 + Update v17408。表は master `2135000A` (GS テーブルの lanai 形式は [analysis.md §2](analysis.md#2-gs-テーブル-lanai-形式確定))。アドレスは Update の code.bin (Ghidra と同じ 0x100000 起点)。RPG2 ([kahara/battle.md](../kahara/battle.md)) / RPG3 ([oahu/actions.md](../oahu/actions.md)) と比べながら読んだが、**行サイズ・ビット位置・ID は流用していない**。

確度: **確定** = 読むコードを特定し、データとも合う。**推定** = コードかデータの片方だけ、または動きの意味づけが推測。**未解析** = 観測値だけ。

調査に使ったスクリプト (表の読み込み、耐性、変身の一覧、分岐表を解く簡易エミュレータ) は一時的なもので、コミットしていない。

## 0. 要点

- モンスター 1 体 = **MonsterParameter (1231 × 0x24)** の 1 行。名前・図鑑・見た目と、**能力の行への参照** (+0x14 / +0x16) だけを持つ。
- 能力の本体は 4 つの表 (**Main 370 / Extra 184 / RegularEvent 200 / SpecialEvent 437、どれも 0x9C、行 ID なし**) のどれかの 1 行。どの表か = MonsterParameter +0x16 の下位 3 ビット (1〜4)、行番号 = +0x14。**確定** (`FUN_002F82B8` ほか)。
- 能力の行は RPG2 と同じく**ビット詰め**。空きビットには詰め物 `0xD0` が「使っている最後のビットの次」から入る (`0x34000000` = 0xD0 << 22 なら bit0-21 を使う)。書き込み時は詰め物を残すこと。
- **耐性は 5 ビット符号付き × 27 欄** (属性 9 + 状態 18)。属性は 1 火 2 氷 3 風 4 土 5 電気 6 水 7 光 8 闇 (0 は未使用)。状態の並びは RPG2 と同じ順 (毒・やけど・水びたし・かぜっぴき・どろだらけ・呪い・かんでん・しもやけ・マヒ・ねむり・ブラインド・攻撃力〜回避率ダウン・突然死) に、ゆうわく (みりょう)・きょうふが付く。**確定**。
- **変身はアクションの系統 29 / 30** (行 +0x00 = 変身先の MonsterParameter の行 ID)。RPG2 の「ボス特殊番号」はなくなり、RPG3 の「ボディ + 発動条件」に近い形で、**発動条件はモンスター側の 1 バイト (+0x96〜+0x99)** に置かれる。
  - 置き場は 5 種類: 被弾時の枠 2 つ (+0x44 / +0x48)、ターン開始・終了の枠 (+0x40 / +0x4C)、戦闘開始の枠 (+0x38)、AI が選ぶワザ枠 6 つ (+0x54〜+0x68)。
  - 条件コード 0x65 = **倒される一撃** (死亡を取り消し、新しい形態の最大 HP で作り直す)、0x66〜0x9C = 打撃・呪文・属性を受けた (各 100/20/30/50/80%)、0xC1〜0xC3 = HP 75/50/25% 以下、0〜100 = 確率 % など (§7)。
  - 系統 30 は大ボスの変身 (セリフ付き)。変身先を **+0x50** にも入れておく (戦闘開始時に先読み)。

## 1. 表の関係

```
MonsterParameter[行] (2135000A, LZ, 4C2BD400)
  +0x00 bit20-29 ─→ MonsterDesign の行 (見た目)                    §11
  +0x10          ─→ MessageFlavor (4177000A) の行 ID (図鑑の説明文)
  +0x16 bit0-2 = k, +0x14 = n
        ─→ k=1 MonsterParameterMain / 2 Extra / 3 RegularEvent / 4 SpecialEvent の行 n (0x9C)
               +0x0C..+0x18 ─→ ItemData の行 ID (ドロップ)
               +0x38..+0x68 ─→ ActionData の行 ID (行動・ワザ・変身)
                                   ActionData +0x00 (系統 29/30) ─→ MonsterParameter の行 ID (変身先)
               +0x50        ─→ MonsterParameter の行 ID (系統 30 の変身先の先読み)
```

- 表の置き場 `*0x004EAE44` (マスターのオブジェクト) の中で、表は 0x28 間隔のホルダー。MonsterParameter +0x758、Main +0x780、Extra +0x7A8、RegularEvent +0x7D0、SpecialEvent +0x7F8 (ホルダー +4 を `FUN_0031C038` に渡す)。ActionData +0x1310、ConditionData +0x1360、BattleParameter +0x1888、MonsterDesign +0x18D8、Boss +0xC8。読み込み `FUN_0017C6D4` の二分探索を簡易エミュレータで解いて得た。**確定**。
- 能力の表の引き方 (`FUN_002F82B8`、`FUN_0045CF64`、`@0x2B7F14`、`@0x3D87D0`): `表 = +0x758 + 4 + 0x28 × max(0, (+0x16 & 7) − 1) + 0x28`、行 = +0x14 (0x80000000 未満なので行番号)。**確定**。
- 1231 行のうち能力の行を参照するのは 1188 通り。34 の能力の行は複数の MonsterParameter の行から共有される (2 体目・3 体目の同じモンスターなど)。**能力の行を書き換えると共有している全員が変わる**。参照されない能力の行が 3 つある。

### 3.1 能力値の決まり方 (`FUN_002B4928`、確定)

- 通常: HP・こうげき・ぼうぎょ・すばやさ・AP は**2 つの値の間の一様乱数** (`FUN_002B1AB4(a, b)` は大小どちらの順でもよい)。
- 呼び出しの第 4 引数が 1 のとき (見積もり・表示用と推定) は**上側 (+0x76 など先の値)** をそのまま使う。
- 戦闘の状態 +0x52 (段数 n) が 2 以上のとき: 値 = 下側 + (上側 − 下側) / n × 段 (+0x53)。連戦・段階のある戦闘で強くしていく仕組みと推定。
- 生成した値はユニット +0x78 (HP) などに入る。最大 HP は都度 `FUN_0030665C` で計算し直す。

## 4. 耐性

### 4.1 並び (5 ビット符号付き、`lsl n; asr #27` で取り出す。確定)

| 語 | bit0-4 | bit5-9 | bit10-14 | bit15-19 | bit20-24 | bit25-29 |
|---|---|---|---|---|---|---|
| +0x24 (w9) | 属性 0 (未使用、全行 0) | 火 | 氷 | 風 | 土 | 電気 |
| +0x28 (w10) | 水 | 光 | 闇 | (詰め物) | | |
| +0x2C (w11) | 毒 [1] | やけど [2] | みずびたし [7] | かぜっぴき [4] | どろだらけ [5] | 呪い [8] |
| +0x30 (w12) | かんでん [6] | しもやけ [3] | マヒ [9] | ねむり [10] | ブラインド [21] | 攻撃力ダウン [16] |
| +0x34 (w13) | 防御力ダウン [17] | 素早さダウン [18] | 回避率ダウン [19] | 突然死 [23] | ゆうわく (みりょう) [11] | きょうふ [12] |

- [ ] は戦闘の状態番号。状態番号 → ConditionData の行は `FUN_0016720C` の分岐表 (1→行 1 毒、2→3 やけど、3→9 しもやけ、4→5 かぜっぴき、5→6 どろだらけ、6→8 かんでん、7→4 みずびたし、8→7 呪い、9→10 マヒ、10→11 ねむり、11→12 ゆうわく、12→14 きょうふ、16/17/18/19→18/20/22/24 各ダウン、21→27 視界 (ブラインド)、23→29 カウント (突然死)) で確かめた。
- 属性の番号は「属性 n たいせい」= 能力 0x24+n (ConditionData 129〜136 の 火・氷・風・土・電気・水・光・闇) と対応 (`FUN_003062E0` の分岐表)。データでもアイスバード・アイスドラゴンが氷 +9、まおうが闇 +10。
- 状態の 18 欄のうち 1〜11・21・23 の 13 個は「状態異常」で、全状態異常たいせい (能力 0x3B) も足す (`FUN_002F8ED8` の 2 つ目の分岐表、`0x4A38F6` の一覧 `1..11, 21, 23`)。12 (きょうふ)・16〜19 (ダウン) は足さない。

### 4.2 値の意味

- 範囲は −9〜+9。正が強い。属性だけ **+10 = 無効** (`FUN_003062E0` が 10 を見たらそのまま 10 を返す)。
- 状態: モンスターで値が 9 ならほかの補正を見ずに 9 (効かない)。それ以外は「装備・状態の補正 (たいせい系の能力) のうち絶対値の大きいほう + 元の値」を −9〜+9 に丸める (`FUN_002F8ED8`)。属性も同じ (`FUN_003062E0`)。
- 倍率 (BattleParameter、推定): +0x4C〜+0x70 の u16 × 19 = 属性ダメージの % (−9: 400, −8: 300, −7: 250, −6: 200, −5: 180, −4: 160, −3: 140, −2: 130, −1: 120, 0: 100, +1: 80, +2: 60, +3: 50, +4: 40, +5: 30, +6: 20, +7: 15, +8: 10, +9: 5)。+0x91〜+0xA3 の u8 × 19 = 状態の成功率の係数 % (−9: 200 … 0: 100 … +9: 0)。表の形は RPG2 の BP[0x08] / BP[0x67] と同じだが、lanai で読むコードは未確認。
- 元のデータでは多くの雑魚が状態 +4 前後、メタル系 (にゅうし・えいきゅうし) が属性 +10・状態 +9。

## 6. ドロップ (確定)

- 4 枠。枠 i のアイテム = +0x0C + 4i (ItemData の行 ID)、ランク r = +0x8A / +0x8B のニブル (枠 1 = +0x8A 下位、枠 2 = 上位、枠 3 = +0x8B 下位、枠 4 = 上位)。

## 8. AI (ワザの選び方、`@0x172380`、確定)

1. ワザ枠 1〜6 それぞれについて、枠の「狙い方」(6 ビット) で対象を探し (`FUN_00160C0C`)、見つかった枠だけ残す。
2. 0 個なら **+0x9A bit3-5 の枠**を対象なしで使う。1 個ならそれ。
3. 複数なら +0x9A bit0-2 の方式:

| 方式 | 選び方 (RPG2 と同じ 5 方式) |
|---|---|
| 0 | 残った枠から均等 (同じワザを複数枠に入れると出やすい) |
| 1 | 前の枠ほど重い (三角形の重み) |
| 2 | 19/20 の確率で枠 1、外れたら残りから均等 |
| 3 | 枠を順番に (前回の枠 +1) |
| 4 | 2 枠ずつの組 (1-2, 3-4, 5-6) を順番に回し、組の中は均等 |

- 1 ターンの行動回数は +0x90 bit0-2 (§3)。
- ワザ枠に系統 29/30 のアクションを入れると、AI が選んだときに変身する (箱に隠れる・息を吸い込む・モード切り替えなど)。

## 9. 変身

### 9.1 仕組み

- **系統 29** (352 行) と **系統 30** (6 行) のアクションが変身。系統はアクション +0x14 の bit4-11 (`@0x2026A0`、`@0x16D4A8`)。
- **アクション +0x00 = 変身先の MonsterParameter の行 ID**。たからばこぞう #1112「箱に隠れてしまった」→ 0x800000A1 (行 42、隠れた姿)、#1113「箱からとびだした」→ 行 41 など、名前・文がすべて合う。**確定 (データ)**。結果 +0x28 の行で `FUN_002029AC(ユニット, 行, HP を戻すか)` が作り直す (`@0x2F2690`)。
- `FUN_002029AC`: MonsterParameter の行を差し替え、Lv (+0x96)・経験値 (+0x98) を新しい能力の行から入れ直す。第 3 引数が 1 なら HP を新しい最大 HP にする (`FUN_002F8374`)。1 になるのは、アクションの +0x14 下位 4 ビットが 5 で、かつそのアクションが +0x44 / +0x48 にあって条件が 0x65 のとき (`@0x2F2628`〜)。それ以外は今の HP のまま。
- **系統 30** はセリフ付きの大ボスの変身 (じごくのじょおう → アビス、アグニホース → ホースドラゴン、マスターぶたばな → ぶたばなダークロード、カオスナイト、さいごのポーン → とうしんポーン)。変身先を +0x50 にも入れ、戦闘開始時に読み込む (`@0x201F00`)。モデルを入れ替える演出と推定 (RPG3 の系統 22 + monsterParameter +0x62 と同じ役割)。
- 置き場ごとの発動: 被弾時 +0x44/+0x48 (条件 §7)、ターン開始 +0x40 / 終了 +0x4C (条件 §7)、戦闘開始 +0x38、AI のワザ枠 +0x54〜+0x68。
- 変身先の形態は自分の行を持ち、そこに「元に戻る」アクションを入れて往復させる (たからばこぞう、ひょうけつぶくれ、アグニホース、マスターぶたばなの闘神モード)。

## 10. エディタで編集する欄 (書き込み先)

能力の行の位置: 表 = `MonsterParameterMain/Extra/RegularEvent/SpecialEvent` (2135000A、それぞれ GS テーブル。データ領域の先頭は表のヘッダー +0x10)、行 = MonsterParameter +0x14、表の番号 = +0x16 bit0-2。**能力の行は共有されることがある** (§1) ので、1 体だけ変えたいときは空き行を足して +0x14/+0x16 を付け替える。ビット詰めの欄は他のビットと詰め物 (0xD0 系) を残して書く。

## 11. 見た目の選び方 (確定)

ゲームは MonsterParameter の行を引いたあと、+0x00 の bit20-29 を取り出し (`lsl #2; lsr #22`)、MonsterDesign をその値で引く。値は 0x80000000 未満なので、表の行の検索 `FUN_0031C038` ([analysis.md §4](analysis.md#4-codebin-update-v17408)) は**行番号**として扱う。

- 場所 (Update の code.bin): `0x306E60`〜`0x306EA4`、同じ並びが `0x2B7EB4`〜`0x2B7EE4`。表の置き場 `*0x004EAE44` の +0x758 が MonsterParameter、+0x18D8 が MonsterDesign (読み込み `0x17C6D4` で、エントリのハッシュ `0x4C2BD400` / `0xC402F800` から決まる)。
- この行の +0x04 / +0x08 / +0x0C などを読むコードがある (`0x189090`、`0x1B68BC`、`0x1A557C`)。
- 照合: この規則で並べると、種族の名前ごとに 1 つのモデルに収まり、色のテクスチャが順に並ぶ (コウモリ enemy_01、鳥 02、キノコ 04、チョウ 05、ドラゴン 10、木 11、イノシシ 12 …)。描画しても名前と姿が合う (アイスドラゴンは竜、いちごおばけはイチゴ)。
- 以前の資料の「+0x10 = MonsterDesign の行 ID」で引くと、enemy_05 あたりから先の多くで別の種族の姿になる (ドラゴンが木、ドライウッドがイノシシ)。

## 13. モデル
- 敵のモデルは `28480000` (Base、497 エントリ) と `719F0000` (Update、349 エントリ) の `enemy_NN[_MM].bch`・`enemy_NN_MM_tex.bch`・`enemy_NN_battle.bch`。基本の番号は enemy_01〜enemy_99 などで 104 種類ある。
- 形式は **BCH (H3D)**。RPG3 (oahu) の type 2 も BCH で、`enemy_03` のような同じ名付けがある。RPG2 (kahara) は CGFX。
- H3D の版 (backward compatibility) は **0x21** (RPG3 は 8)。Panana で読むときに分かった違い (SPICA の版ごとの分岐と同じ向き):
  - 材質は 0x2C バイト。テクスチャの mapper は +0x18 のポインターの先、テクスチャ名 3 つと材質名が +0x1C〜+0x28。
  - アニメのカーブは 0x20 以降、segment がカーブの中にある (index の後ろに u8 補間・u8 量子化・u16 キー数・f32 値の倍率・f32 値のずれ・f32 フレームの倍率・f32 1/長さ)。
  - H3DAnimation の +0x04 が flags (bit0 = ループ)、+0x05 が種類。wait / walk / run はループし、ワザ・ダメージ・倒れるはループしない。
  - モデルの +0x01 (bone scaling) が 1 (Maya) で、骨の flags の bit22 (segment scale compensate) が腰より下の骨に立つ。この骨は親の大きさを回転・大きさに受け継がない (local = T × 親の大きさ⁻¹ × R × S)。舌の骨 (tongue_1〜3) などで効く。
  - 骨の番号が固定の属性 (頂点ごとでない) で、重みが頂点ごとに 4 個のメッシュがある (いちごおばけ・おばけとうがらしの舌)。固定の骨の番号も 4 個使わないと、4 個目の骨の重みが落ちて舌が伸びる。
- **移植の見込み (未検証)**:
  - RPG3 のモンスターは、BCH のまま `enemy_*` として足せる可能性がある。足したあと MonsterDesign → MonsterParameter → 能力の表と行を足す。
  - RPG2 のモンスターは、CGFX から BCH への変換が要る。
- エフェクトは `.ptcl` (SPBD) で、RPG3 の CGFX のエフェクトはそのままでは使えない。

## 14. 未解決
