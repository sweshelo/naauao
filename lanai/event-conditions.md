# FREE! のイベント出現条件と編集 UI

対象: ローカルの Base CIA と Update v17408 (展開後 code.bin = 4,182,016 bytes)。2026-11-10 にコードを再確認。既存の [マップ §7.1](map.md#71-eventobject-の行-100-b) と [重要オブジェクト](key-objects.md) の補足。

## 判定の流れ

- 出る: `FUN_002C7130(event)` が `FUN_002FCD38(+0x5F, +0x00, +0x04, 1)` を呼ぶ。
- 消える: `FUN_002C708C(event)` が `FUN_002FCD38(+0x60, +0x08, +0x0C, 0)` を呼ぶ。
- 種類 0 は第4引数をそのまま返す (`@0x2FCF28`)。したがって出る条件の 0 は「いつも出る」、消える条件の 0 は「消えない」。値を 0 にする操作ではない。
- 先に `FUN_002E7E4C` でコールバック 0x1F / 0x20 を取得する。関数が存在し、呼び出し結果が非ゼロなら、その出力を採用する。以下はデータによる共通判定であり、CRO の上書きを解除するものではない。
- 分岐表は `0x2FCD60`、種類は 0〜0x71。RPG2 / RPG3 の番号を流用しない。

## 汎用として編集できる条件

`v1` と `v2` は、それぞれ出る側の +0x00/+0x04 または消える側の +0x08/+0x0C。

| 種類 | 成り立つ条件 | 分岐先 | 読む処理 |
|---|---|---|---|
| 0x01 | コンテンツ v1 をクリア済み | 0x2FCF34 | `FUN_002F4B58((u16)v1)` → セーブ 0x53[v1] が非ゼロ |
| 0x02 | 上の否定 | 0x2FCF44 | 同上 |
| 0x03 | フラグ v1 が非ゼロ | 0x2FCF58 | `FUN_002E7DF4((u16)v1)` → セーブ 0x51[v1] |
| 0x04 | 上の否定 | 0x2FCF68 | 同上 |
| 0x05 | 数値 v1 = v2 | 0x2FCF7C | `FUN_002FF158((u16)v1)` → セーブ 0x52[v1] (u8) |
| 0x06 | 数値 v1 ≥ v2 | 0x2FCF94 | 同上、符号なし比較 |
| 0x07 | 数値 v1 ≤ v2 | 0x2FCFAC | 同上、符号なし比較 |
| 0x08 / 0x0A | 常に偽 | 0x2FE044 | 値は使わない |
| 0x09 / 0x0B | 常に真 | 0x2FE038 | 値は使わない |
| 0x0C | 現在の MapGroup のイベント v1 の状態 ≥ v2 | 0x2FCFC4 | `FUN_002C7028(v1)` |
| 0x0D | 同じ状態 ≤ v2 | 0x2FCFF0 | 同上 |
| 0x16 | タイマー v1 の残り時間がある | 0x2FD124 | `FUN_002BE834(*0x4EAD08, (u16)v1)` |
| 0x17 | 上の否定 (残り時間がない) | 0x2FD13C | 同上 |
| 0x1D | 常に偽 | 0x2FE044 | 値は使わない |

0x03/04 は 0x51 の要素数を確認し、範囲外なら値 0。0x05〜07 も 0x52 の要素数を確認し、範囲外なら値 0。0x01〜07 の番号は下位16ビットだけを使うが、比較する v2 は u32 のまま。0x0C/0D は `*0x4EAE3C +0x2C` が 0 なら偽。読み出しは `FUN_002C7028` → 現在の MapGroup (`FUN_0031EB38`) → `FUN_00191290`。イベントの +0x58 の状態枠を `FUN_002DF8AC` で解決し、MapGroup +0x2A 未満ならセーブのキー 3[MapGroup +0x28 + 枠] を読む。

重要: ボス戦で「フラグ」と呼んでいた消える条件 6 は、実際には **0x52 の数値 ≥ v2**。既存データの v2 = 3 を消して単純な真偽値に置き換えてはいけない。クリア済みの判定は 0x53 であり、0x51/0x52 とは別。

### タイマー (0x16 / 0x17)

`FUN_002BE834` は `FUN_002D1638` の返す64ビット残り時間と `0x4EACE8` の基準値を符号付きで比較する (基準値 < 残り時間なら真)。`FUN_002D1638` は `FUN_002D1600` でセーブの **0x17[v1] (開始時刻) / 0x18[v1] (継続時間)** を読み、`FUN_003258C8` の現在時刻との差を 1,000,000 倍して継続時間から引く。開始情報が無効、時計が開始前、期限到達・経過の場合は基準値を返す。ゲーム固有のマップ番号・イベント番号による分岐はないため、タイマー番号を指定する汎用条件として UI を提供する。既存タイマーの開始・更新は別の処理であり、この UI はタイマーを開始しない。

### 実データの照合

ローカルROMの全127コンテンツを MapGroup 単位で走査し、種類0を除く出る・消える条件を合計すると、0x01:20、0x02:25、0x03:927、0x04:4、0x05:859、0x06:407、0x07:22、0x0C:149、0x0D:1、0x16:14、0x1D:1。これらはすべて上表で意味を確認し、編集 UI に含めた。0x16 の v1 の例は 102、106、111、116〜120 (v2は0)。CRO が動的に設定する条件や未使用種類の全解析を意味しない。

## 専用・未確定の条件

| 種類 | コードで確認した内容 | UI の扱い |
|---|---|---|
| 0x0E〜0x10 | `FUN_00314550(*0x4EB01C, v1)` と v2 を = / ≥ / ≤ で比較。内部で +0x54 のテーブルを読み、ビット幅に応じて値を取り出す | 要素の利用上の意味が未確定なので新規選択肢にしない |
| 0x11〜0x13 | `FUN_002FE090(*0x4EB01C, v1)` と v2 を = / ≥ / ≤ で比較。別テーブルの定義で `FUN_00310AA4` / `FUN_00310B2C` に分岐 | 同上 |
| 0x14 / 0x15 | `FUN_00312D78(*0x4EB028, v1, 1)` が v2 以上 / 未満 | 対象が未確定なので新規選択肢にしない |
| 0x18〜0x71 (0x1Dを除く) | 今回は意味を確定していない | 番号の推測による編集 UI は作らない |

未解析の種類が設定されているイベントでは、現在の種類を表示して保持する。通常 UI で未解析の値を編集させず、汎用条件への変更は可能。元の値は条件を切り替えても保持する。生データ欄は従来どおり詳細表示に残る。

## 再現と検証

Panana のルートから、PC 内 `roms/lanai-update.cia` を使う。

```sh
bun scripts/research/lanai-conditions.ts 0 23
bun scripts/research/lanai-conditions.ts --usage
bun test test/lanai-eventeditor.test.tsx
```

解析スクリプトは ROM の分岐表からアドレスを取り出して逆アセンブルし、`--usage` では実データを集計する。テストは ARM 実行器で ROM の実際の分岐を実行し、セーブ読出しと時計だけをスタブ化してキー・添字、真偽反転、比較、タイマーの期限前・到達・経過、種類 0 の呼出側既定値を検証する。これはゲーム内で CRO が上書きするイベントの動作確認を意味しない。

## 編集 UI

- イベントは番号の手入力から、アイテムと共通の検索付きグリッドへ変更。動作名、配置マップ、種類、座標、モデル、位置の縮図を表示する。他の物が使う番号は直接再割当てできない。状態の比較では配置済みイベントも参照できる。
- 出入口・階段・ワープ (動作 0x80000011 / 0x80000013 / 0x80000039) は、同じコンテンツのマップ表 (追加マップを含む) からマップを選び、そのマップの区画3から地点 ID を選ぶ。壁の扉 (種類100) は地点を持たないため候補から除外する。マップ変更時は有効な既存地点を保持するか、新しいマップの最初の地点を使う。地点のないマップは 0 と警告を表示する。
- 3つの動作すべてに同じ選択 UI を適用。テーブル変更・参照先変更は既存の Undo / 保存 / MOD 書出しに載せる。
- W01 は従来どおり専用レイアウトの表示・編集に未対応。この変更は新しいワールドマップエディタの実装を含まない。
