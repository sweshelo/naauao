# 電波人間のRPG FREE! (lanai) の重要オブジェクト: ボス戦・ゴールの宝箱・クリアのワープ

対象: lanai Base v0 + Update v17408。ステージの進行を決めるマップ上の 3 種類のオブジェクトについて、どの区画のどのレコードが何を指すかをまとめる。区画・EventObject (EO)・動作の段の基本は [map.md](map.md) (§5 区画ごとの記録、§7 MapGroup と EventObject) を前提にする。

調べ方: Panana の CI の ROM ジョブ (復号済みのダンプ) で一時テストを動かし、全 127 コンテンツ・W01 を除く全マップのレコードと EO を数えた (2026-10-18、panana `claude/project-thread-jwylgw` の一時テスト。PR には含めない)。件数は「レコード (区画の記録) の数」。コードの確認は、Update v17408 の code.bin を Ghidra 12.1.3 で読んだ (2026-10-18)。関数の番地はこの code.bin のもの。

確度の表記は [map.md](map.md) と同じ (確定 = 全件のデータで矛盾なし、推定 = 統計・名前・他作との類似から)。

## 1. 会話のあとのボス戦

ボス戦は**範囲 (区画 8) が戦闘を起こし、キャラクター (区画 5) がボスの姿を見せる**組で置かれる。

### 1.1 戦闘: 区画 8 種類 0 + 動作の型 0x8000000C (確定: データ)

- 66 件 / 28 コンテンツ。すべて区画 8 (oahu の区画 8 = イベントの範囲) の種類 0 で、EO の動作 1 の型が 0x8000000C。
- **引数 1 (+0x14) = コンテンツの MonsterGroup の行番号** (行 ID ではない)。66 件すべてで表の範囲内で、群れのモンスターがステージのボスと合う。例: コンテンツ 1 `D01001B02` → 行 6 おばけホール、コンテンツ 15 `D01001F04` → 行 9 まおう、`D01001F99` → 行 10 あくのいきもの。
- **引数 2 (+0x18) = 勝ったときに立てるフラグの番号**。0 でない 48 件はすべて、同じ EO の「消える条件」が種類 6・値 1 = 引数 2 (勝つと範囲が消える)。0 の 18 件はコンテンツ 8 の何度も出る雑魚戦で、消える条件は種類 0x0C (別の条件) を使う。
- 引数 3 (+0x1C) = 0x0D〜0x5B の番号。群れの台詞の表 (MapGroup +0x24) の行として読むと場面に合わず、表の行数を超える例もある (コンテンツ 8 は 67 行の表に 0x5B)。**意味は未解析** (会話は区画 5 の姿のスクリプト 0x8000002D か CRO が出していると推定)。
- 引数 4 / 5 は 0。

### 1.2 姿: 区画 5 種類 1 (確定: データ)

- 範囲とほぼ同じ場所 (例 範囲 (37, 37) に対して (36, 36)) に区画 5 種類 1 のレコードがあり、EO の消える条件は範囲と同じフラグ (種類 6・値 = 引数 2、段 3)。動作は「なし」か 0x8000002D (スクリプト) が多い。
- EO +0x5A = コンテンツの `MapChara` の行。その行 +0x00 の下位 3 ビットが 1 (モンスター)。
- **MapChara 種類 1 の +0x2C (u16) は MapObject の行ではなく MonsterDesign の行番号** (RPG3 の mapChara 種類 1 が monsterDesign の行なのと同じ)。範囲と組になる 70 組のうち 59 組で、範囲の MonsterGroup のモンスターの見た目 (MonsterParameter +0x00 bit20-29、[monsters.md](monsters.md)) と一致した。
  - 例: コンテンツ 15 の MapChara 7 → 193 = まおう、コンテンツ 7 の MapChara 4 → 39 = みどりマタンゴ、コンテンツ 8 の MapChara 10 → 103 = ダークゴースト。
  - 一致しない 11 組: 姿が別のキャラ (コンテンツ 15 `D01001F99` の MapChara 8 = 273 じゃあくのまじょ。戦うのはあくのいきもの)、EO +0x5A = 0 (コンテンツ 5 `D01001B04`) など。
  - MapObject の行として読むと `obj_towerB_stand00` (まおう) や `twn_bill41` のような無関係のモデルになる。
- MapChara の行のほかの欄: 種類 1 は +0x04 = 0x8000005C、+0x08 = 0x8000005E、+0x0C = 0x00034000 (群れの雑魚は 0x00034001)。NPC (種類 0) は +0x04 = 0x80000075、+0x08 = 0x80000077。**+0x04 / +0x08 / +0x0C の意味は未解析** (待機・歩きのモーションと推定)。

## 2. 開けるとクリアの宝箱 (ゴールの宝箱)

### 2.1 区画 4 見た目 3 + 動作の型 0x8000002E (確定: データ)

- 区画 4 (宝箱) の見た目 (+0x00) 3 は 75 件。うち 61 件 (61 コンテンツに 1 個ずつ) が EO に型 0x8000002E を持つ。残り 14 件は 0x8000002D (スクリプト) だけ。61 件のうちコンテンツ 14 の 1 件は、段 1 が 2D で段 2 から 2E。
- 型 2E は**状態の段** ([map.md §7.3](map.md#73-動作の段)) で 2〜3 個並ぶ: 段 1 = 初めて開けたとき、段 2 / 3 = 2 回目以降 (再挑戦)。
- 引数 (段ごと):
  - **引数 1 (+0x14) = TreasureGroup の行番号**。段ごとに 1 ずつ増える (例 コンテンツ 8: 0x1C / 0x1D / 0x1E)。中身は段 1 が伝説の装備などの 1 品、2 回目以降は複数の品の抽選 (例 コンテンツ 1 の行 11: 6 品、重み 30 / 20 / 10 / 2 / 1 / 1)。
  - **引数 2 (+0x18) = クリアにするコンテンツ番号**。段 1 にだけ入り (段 2 / 3 は 0)、値が 0 でない 60 件すべてでそのコンテンツ自身の番号 (コンテンツ 1 → 1、34 → 0x22、59 → 0x3B、98 → 0x62)。**開けるとこのコンテンツをクリア済みにする** (確定: コード、§4)。
  - **引数 3 (+0x1C) = 開けたあとの台詞** = 群れの台詞の表 (MapGroup +0x24、なければ MessageContents) の行。例 コンテンツ 1 の 0x8A「やったー！宝を手に入れたよ！…」、コンテンツ 11 の 0x85「あった！ これがカネコさんの落し物だよ！！…」。試練 (コンテンツ 34〜57) と別世界 (80〜89) は 0 (台詞なし)。
  - 引数 4 (+0x20) = 0x1F (全件)。引数 5 (+0x24) = 1 か 0x0E。コードでは引数 3 が `FUN_001924EC` (台詞)、引数 4 が `FUN_002E2AE8` (モーションと推定)、引数 5 が `FUN_002D61A0` に渡る。**引数 4 / 5 の意味は推定のまま**。
- EO の欄: +0x5E = 0xFE (通常の宝箱は 0xFF)、+0x5A = 0 (モデルの指定なし)。別世界のステージ (コンテンツ 81〜89) は出る条件 (種類 6、ボスのフラグ) 付きで、ボスを倒すと現れる。

### 2.2 モデル (確定: コード)

- 宝箱を置く関数 `FUN_0044F9EC` (区画 4。読むのは `FUN_00210A80`、動作は ItemEvent `FUN_0047572C`) は、EO +0x5A が 0 でなければその MapObject を使い、0 なら見た目と屋内かどうか (実行時の +0x5472) で行を選ぶ。
  - 外: 見た目 0 / 1 / 2 → MapObject の行 0x40 / 0x41 / 0x42 (`gimk_05_trebox_1`〜`3`)。屋内: 行 0x43 / 0x44 / 0x45 (`gimk_05_trebox_4`〜`6`)。
  - **見た目 3 → 行 0x46 (= 70、行 ID 0x80000274、`gimk_05_trebox_goal`)。外・屋内とも同じ**。
  - それ以外の値 → 行 0x40 (外) / 0x43 (屋内)。
- ItemGoalCommon の `FUN_001F2750` も、アーカイブの項目 0x3D3A0000 (`trebox_goal`) だけを別に扱う。
- 以前に手がかりと書いた code.bin 0x49B2D0 の u16 の並びは宝箱の表ではなかった。0x49B2AC から始まる 24 個 (34〜57 = 試練のコンテンツ番号) の末尾で、`FUN_00181A00` (0x181B4C) が試練のクリア数を数えて 10 以上かを見る表。

## 3. 使うとクリアのワープ

### 3.1 区画 3 種類 3 + 動作の型 0x80000031 (確定: データ)

- 区画 3 (出入口) の種類 (+0x15) 3 は 46 件 / 16 コンテンツで、**46 件すべて**の EO が型 0x80000031。逆に型 31 はほかの区画・種類にない。
- **引数 1 (+0x14) = クリアにするコンテンツ番号**。46 件すべてでそのコンテンツ自身の番号 (コンテンツ 7 → 7、58 → 0x3A、59〜66 → 0x3B〜0x42、81 → 0x51、112 → 0x70)。宝箱 (§2) の引数 2 と同じ役割と読む。
- 引数 2 (+0x18) = 0 / 0x19 / 0x1C / 0xA3、引数 3 (+0x1C) = 0x15 (全件)、引数 4 (+0x20) = 1 (全件)。コードでは引数 2 が `FUN_001924EC` (台詞)、引数 3 が `FUN_002E2AE8` (モーションと推定)、引数 4 が `FUN_002D61A0` に渡る (宝箱の引数 3〜5 と同じ並び。**意味は推定のまま**。引数 2 は幻帝のどうくつ (58 / 94) で階ごとに違う)。
- **引数 5 (+0x24) = 1 なら、確認の台詞 0x80000396 で「はい」を選んだときだけクリアにする** (0 なら使うとすぐ)。確定: コード (`FUN_00203508` が +0x3C2 を立て、`FUN_00203AE0` がそれを見る)。行き先のマップ・地点の引数はない (型 11 / 13 と違う)。
- 置かれる所: 属性チャレンジ (59〜66) は 3〜4 つのダンジョンの最後の階に 1 つずつ、幻帝のどうくつ (58 / 94) は 7 か所 (出る条件が種類 6 のフラグ)、別世界・試練 (81、84、85、87、112) はボスの部屋の手前のワープ (型 0x80000039、§3.3) で着くマップ。
- EO +0x5A = 0 (モデルの指定なし)。

### 3.2 見た目: モデルではなくエフェクト (確定: コード)

- 区画 3 を置く関数 `FUN_0021D744` (読むのは `FUN_002BECE8`、動作は MoveEvent `FUN_00475B50`) は、**種類 3 のとき MapObject を置かず、EO +0x5A も見ない**。代わりに EffectData (master +0x1E4、`effectData.bin`) の行 0x22 = `fx_bg_f_warpzone_goal.ptcl` (アーカイブ 90ED0000 の項目 3) のエフェクトを置く。
  - 高さはレコードの +0x20 だけ足す。+0x26 の bit0 で置き方の印が 1 つ変わる。
- 種類 3 以外は `FUN_00433884` (RPG3 の `FUN_00365294` に当たる) でモデルを決める: EO +0x5A が 0 でなければそれ、0 ならマスの +0x16 (仕掛け) で選ぶ (2 → 0x69、9 → 0x68、0x0C〜0x12 → 0x2D〜0x33、0x14〜0x45 → 0xCE〜0xFE)。
- 以前の推定 (`gimk_11_warp_04` = 行 ID 0x8000005E が既定のモデル) は誤り。0x8000005E を読む code.bin の場所は、MapChara +0x08 と同じモーションの ID を読んでいると見られる。

### 3.3 近くにある別の型

- **0x80000039** (区画 3 種類 14、8 件): 引数 1 / 2 = 行き先のマップのハッシュ / 地点 ID、引数 3 = 0x2D、引数 4 = 1、引数 5 = 0x7A。別世界・試練でクリアのワープのあるマップへ移る。
- **0x8000003B** (区画 3 種類 15 / 12、8 件): 段 2 が 0x80000015 (壁の扉)。引数 1 = 0xB1〜0xB8 (コンテンツごとに違う)、引数 2 = 1、引数 3 = 0x7A。未解析。
- **0x8000003A** (区画 5 種類 0、5 件): ワープのマップの NPC (MapChara の `npc_22b`)。引数はすべて 0。未解析。
- **0x80000030** (区画 5 種類 13、71 件 / 43 コンテンツ) = **回復ポイント** (SafeAreaCommon、確定: コード)。引数はすべて 0。本編のほぼ全ステージに 1〜数個あり、ゴールの宝箱やボスの部屋の近く (コンテンツ 9 は 3 / 5 / 7 / 9 階、15 は 99 階) に置かれる。
  - 使うと HP / MP を全回復する (`FUN_00201780` → `FUN_001913D0`)。台詞は 0x8000030E、0x800001F6、0x800000F4。**クリアにはしない** (以前の「島へ戻る出口」の推定は誤り)。
  - 区画 5 を置く関数 `FUN_0021C844` (読むのは `FUN_00210C84`、動作は NpcEvent `FUN_00474538` / SafeAreaEvent `FUN_0045AECC`) は、種類 13 では EO +0x5A を見ず、EffectData 行 0x27 `fx_bg_repair_point.ptcl` を置く。種類 12 は行 0x26 `fx_bg_repair_field.ptcl` で、種類 12 だけは EO +0x5A も使う。種類 3 の既定は MapObject 0x3F `gimk_04_heal_1`。

## 4. クリア済みの記録 (確定: コード)

- `FUN_00191130(n)` が `FUN_0031C44C(*0x4EB01C, 0x53, n, 1)` で、セーブのフラグ群 0x53 の n 番 (n = コンテンツ番号) を立てる。読むのは `FUN_002F4B58`。
- `FUN_00191130` を呼ぶのは 2 か所だけ:
  - 0x2C1DA8 (`FUN_002C1D90`、ItemGoalCommon = 型 2E): 引数 2 の下位 16 ビットを渡し、そのあと引数 2 を 0 にする (2 度は書かない)。
  - 0x203B14 (`FUN_00203AE0`、WarpGoalCommon = 型 31): 引数 1 を渡す。引数 5 = 1 なら確認の「はい」のあと (§3.1)。
- つまりステージのクリアは「ゴールの宝箱を開ける」か「クリアのワープを使う」のどちらかだけで書かれる。ボス戦 (型 0C) は自分ではクリアにしない。
- master の表の場所 (参考): +0x1404 MapObject、+0x142C EventObject、+0x16D4 MapChara、+0x1E4 EffectData。表の行は `FUN_0031C038` で引く (0x80000000 未満は行番号、以上は行 ID)。
